# Editorial Carousel

โพสต์ carousel ที่ดูเป็นชุดเดียวกับคลิป `talking-head-editorial`: ทุกสไลด์มี **คำสำคัญคำเดียวตัวใหญ่**, สี accent สีเดียว,
สลับพื้นสไลด์ ขาว / ดำ / กรมท่า / โปสเตอร์ครีม, และภาพที่ "เล่า" ข้อความ (รูปของผู้ใช้ หรือ motion graphics สไตล์ Jitter × Swishy).
คนอ่าน carousel ปัดเร็ว — แต่ละสไลด์ต้องอ่านจบใน 2–3 วินาที และอยากปัดต่อ.

งานนี้ทำด้วยโค้ดแบบเดียวกับ editorial: HTML/CSS/WAAPI ใน Chromium (Playwright). คุณ (Claude) เขียน `deck.js` ของแต่ละโพสต์
(สไลด์ละหนึ่งบล็อก `slide(...)`) ส่วนเอนจิน, ชุดการ์ด, MG kit, เสียง และ pipeline มีให้แล้ว. สไลด์ทุกใบมีแอนิเมชันเข้า
→ **PNG = ภาพสุดท้ายหลังทุกอย่างเข้าที่**, **MP4 = สไลด์เดียวกันเล่นแอนิเมชันจริง** (ได้ทั้งสองแบบจากไฟล์เดียว).

## สิ่งที่ต้องรู้ก่อนเริ่ม

- **ห้ามแต่งข้อเท็จจริง** — ข้อความบนสไลด์มาจากที่ผู้ใช้ให้ (ข้อความที่เขียนแล้ว / บท / SRT). ย่อ ตัด เรียงใหม่ได้ แต่ไม่เติมตัวเลข ราคา ชื่อ
  ผลลัพธ์ หรือคำแนะนำที่เขาไม่ได้พูด. ถ้าเนื้อหาไม่พอทำสไลด์ปิด/CTA ให้ใช้คำกลาง ๆ ("เซฟไว้", "ส่งให้เพื่อน") หรือถามผู้ใช้.
  แก้ได้แค่คำผิดชัด ๆ และคำพูดติดปาก — บอกผู้ใช้ว่าแก้อะไร.
- **คุณดูงานได้เป็นภาพนิ่ง** → ตรวจด้วย `preview.jpg` และเปิด PNG ทีละใบเสมอ; ความลื่นของ MP4 ต้องให้ผู้ใช้ยืนยัน.
- **ผู้ใช้ส่วนใหญ่สั่งงานจากมือถือ** ผ่าน Claude Code บนเว็บ/แอป — เครื่องคลาวด์มี ffmpeg, Node + playwright, python3 แล้ว.
  ห้ามขอให้ผู้ใช้ติดตั้งหรือรันคำสั่งเอง. รัน `scripts/check_env.sh` ก่อนเสมอ.
- **ไม่เกรดสีรูปของผู้ใช้** ไม่ใส่ filter / vignette / grain · **ฟอนต์ Mitr + Sriracha เท่านั้น** · **ไม่ใส่บาร์โค้ด** — ผู้ใช้กำหนดไว้ (เหมือน editorial).
- ไม่ดึงรูปจากเน็ต และไม่ใช้โลโก้แบรนด์จริง — ไม่มีรูปจากผู้ใช้ก็ใช้ motion graphics.

## Workflow

ตั้ง `SK=<path ของ skill นี้>` และ `P=<โฟลเดอร์งาน>` (เช่นใน scratchpad, ชื่อสั้นไม่มีช่องว่าง).

1. **ตรวจเครื่อง** — `bash $SK/scripts/check_env.sh`
2. **รับวัตถุดิบ** — อย่างน้อยหนึ่งอย่างจากนี้:
   - **ข้อความที่เขียนเสร็จแล้ว** → ใช้ตามนั้น แค่แบ่งเป็นสไลด์และเลือกคำสำคัญ.
   - **บท / SRT ของคลิปพูดหน้ากล้อง** → อ่านทั้งหมด แล้วย่อเป็นประเด็น (ดู "จากคลิปเป็น carousel" ด้านล่าง).
     ถ้าผู้ใช้ส่งคลิปมาด้วย: `bash $SK/scripts/fetch_video.sh $P <ไฟล์ | ลิงก์ Drive>` → `$P/input.*` แล้ว
     `bash $SK/scripts/pipeline.sh $P grab $P/input.mp4` → เปิด `$P/scan.jpg` (เฟรมทุก 2 วินาที มีเลขวินาที) เลือกเฟรมหน้าชัด
     ปากไม่เบี้ยว ตาไม่ปิด แล้ว `bash $SK/scripts/pipeline.sh $P grab $P/input.mp4 12.4,31` → `$P/img/v_12.4.jpg` …
   - **รูปของผู้ใช้** → คัดลอกไป `$P/img/` (ชื่อสั้น เช่น `i01.jpg`). เปิดดูทุกรูปก่อนวางแผน (เนื้อหา, สีพื้น, ตำแหน่งคน).
   แบรนด์: คัดลอก `$SK/assets/brand.default.json` เป็น `$P/brand.json` แล้วแก้ — อย่างน้อยถาม/ใส่ `handle` (เช่น `@ชื่อร้าน`)
   ถ้าผู้ใช้มี; ไม่มีก็เว้นว่าง. ขนาดค่าเริ่ม 1080×1080 — ถ้าผู้ใช้ขอ 4:5 ตั้ง `SIZE=1080x1350` ตอน build (ตำแหน่งในสไลด์ต้องคิดใหม่ตามความสูง).
3. **วางแผนแล้วให้ผู้ใช้เห็นก่อนเขียนโค้ด** — ตาราง `สไลด์ · ข้อความ (คำสำคัญเป็นตัวหนา) · พื้น · ภาพ/MG`.
   หลักวางแผนดูหัวข้อ "โครงเรื่องและจังหวะ" ด้านล่าง. ถ้าผู้ใช้สั่งให้ทำเลยก็ไปต่อ.
4. **เขียน `$P/deck.js`** — อ่าน `references/deck-api.md` และ `references/slide-library.md` ก่อน;
   เปิด `examples/deck_mg.js` (ไม่มีรูป ใช้ MG) หรือ `examples/deck_photo.js` (ใช้รูป/เฟรมจากคลิป) เป็นต้นแบบ —
   คัดลอกสไลด์ที่จูนแล้วมาเปลี่ยนเนื้อหา ดีกว่าเขียนใหม่.
5. **Build + PNG + ตรวจเอง** — `bash $SK/scripts/pipeline.sh $P all` (= build + stills) → `$P/slides/01.png …`, `$P/preview.jpg`, `$P/carousel_png.zip`.
   สคริปต์พิมพ์ `QC slide NN: …` ถ้าข้อความล้นขอบ/ทับแถบล่าง, บรรทัดถูกบีบเกิน หรือเนื้อหาไม่สมดุล
   (`unbalanced` = ที่ว่างบน/ล่างต่างกันมาก — ขยับตามที่บอก) — แก้ให้ `QC clean`.
   แล้ว **เปิด PNG ทุกใบ** ตรวจตาม QC ใน `references/standards.md` (สระ/วรรณยุกต์ชนกัน, สมดุล, อ่านใน 2 วิ, หน้าปกดึงดูด).
   render.js ออกด้วย exit code 2 ถ้ามี JavaScript error หรือหาไฟล์รูปไม่เจอ — แก้ก่อนไปต่อ.
   แก้เฉพาะสไลด์: `bash $SK/scripts/pipeline.sh $P build && bash $SK/scripts/pipeline.sh $P stills 3,5`.
6. **MP4 (ถ้าผู้ใช้ขอแบบขยับได้)** — `[SFX=1] bash $SK/scripts/pipeline.sh $P motion` → `$P/slides/NN.mp4` (ยาวตาม `dur` ของสไลด์)
   + `$P/carousel_mp4.zip`. ~8 สไลด์ใช้ ~1–2 นาที. `SFX=1` ใส่เสียงประกอบเบา ๆ (ค่าเริ่มเงียบ — คนมักใส่เพลงในแอปเอง).
   ดูเฟรมกลาง ๆ ของ 1–2 สไลด์ก่อนส่ง (`ffmpeg -i slides/03.mp4 -vf "select='eq(n\,10)+eq(n\,30)',tile=2x1" …`).
7. **ส่งงาน** — ส่ง PNG ทุกใบในแชท (เรียงลำดับ) + `carousel_png.zip` (และ `carousel_mp4.zip` ถ้าทำ) พร้อมตารางสรุปสไลด์
   และขอฟีดแบ็กแบบระบุเลขสไลด์. ถ้า session มี GitHub repo และไฟล์ zip ใหญ่เกินส่งในแชท:
   รันจากในโฟลเดอร์ repo `bash $SK/scripts/deliver_github.sh $P/carousel_mp4.zip <ชื่อโพสต์>_mp4.zip` → ส่งลิงก์ `DOWNLOAD:`
   พร้อมบอกว่า "เปิดลิงก์ในเบราว์เซอร์ที่ล็อกอิน GitHub แล้ว ไฟล์จะดาวน์โหลดลงเครื่อง" (branch `exports` เก็บเฉพาะไฟล์ล่าสุด).
   เสนอแคปชันโพสต์สั้น ๆ จากเนื้อหาเดียวกันได้ (ไม่บังคับ, ไม่ใส่ข้อมูลใหม่). แก้ตามฟีดแบ็กเฉพาะสไลด์ → stills เฉพาะใบนั้น.

## โครงเรื่องและจังหวะ (หัวใจของสไตล์)

- **5–10 สไลด์** (ค่าเริ่ม 7–8). หนึ่งสไลด์ = หนึ่งความคิด. ข้อความต่อสไลด์ ≤ ~20 คำ (ยกเว้นสไลด์สรุป/รายการ).
- **สไลด์ 1 = ปก (hook)** — ประโยคเดียวที่ทำให้อยากปัด: ปัญหา / ความเชื่อผิด / คำถาม. คำสำคัญใหญ่สุดของทั้งชุด (170–200 px),
  มีภาพ/MG หนึ่งชิ้น, ชิป "เลื่อนดู" มุมขวาล่าง (อัตโนมัติ). เนื้อหาสำคัญอยู่ในแนวกลาง x 135–945 (กริดโปรไฟล์ IG ครอปข้าง).
- **สไลด์กลาง** — เดินเรื่องเป็น ปัญหา → สาเหตุ/ความเข้าใจผิด → สิ่งที่ควรทำ (หรือเป็นข้อ 1, 2, 3 ด้วย `num()` / `rows()`).
  ประโยคหักมุม ("ไม่ใช่ X") ใช้สไลด์ขาวประกอบคำ + `strike`.
- **สไลด์ก่อนสุดท้าย = สรุป** (รายการ `rows()` หรือประโยคปิดที่แรงที่สุด — เป้า `target()` ใช้ตรงนี้).
- **สไลด์สุดท้าย = CTA** — เซฟ / ส่งให้เพื่อน / ติดตาม / ดูคลิปเต็ม. พื้น accent หรือขาว. ไม่สัญญาสิ่งที่ผู้ใช้ไม่ได้ให้.
- **คำสำคัญคำเดียวต่อสไลด์** ตัวใหญ่ — สลับ **Mitr ตัวหนา** (`k`/`kw`) กับ **ลายมือ Sriracha** (`i`/`iw`) ระหว่างสไลด์;
  `hl` (กล่อง accent) ใช้กับคำที่เป็น "การกระทำ/ตัวปัญหา". ที่เหลือเป็นคำนำตัวเล็ก (`l`).
- **สี accent สีเดียวทั้งชุด** (ค่าเริ่มเขียวมะนาว); ที่เหลือขาว / กรมท่า / ครีม / ดำ. แดง `#FF3B30` เฉพาะความหมายลบ (กราฟร่วง, กากบาท).
  บนพื้นสว่าง ตัวอักษรทุกสไตล์เป็นกรมท่าอัตโนมัติ — accent บนพื้นสว่างมาทาง `hl` / tile / ปุ่มเท่านั้น.
- **สลับพื้นสไลด์** ไม่ให้ซ้ำติดกันเกิน 2 ใบ: ดำ+MG (`mood`) · ขาว (ประกอบคำ) · กรมท่า (คำ + รายการ) · โปสเตอร์ครีม (`curl` + panel/รูป) · accent (CTA).
- **ภาพต้องเล่าความหมาย** — "ถ้าไม่มีข้อความ ภาพนี้ยังสื่อไหม". สไลด์ตัวอักษรล้วนไม่เกินครึ่งชุด.
- **แอนิเมชันจบใน ~1.5 วินาที** แล้วค้าง (`dur` 3–4 วิ) — PNG ถ่ายตอนท้ายสไลด์ จึงต้องไม่มีอะไรสำคัญหายไปตอนจบ.

## จากคลิปเป็น carousel (บท / SRT)

- อ่านบททั้งหมดก่อน แล้วหา **ประเด็นหลัก 4–7 ข้อ** + ประโยคเปิด (hook) + ประโยคปิด — ไม่ต้องใช้ทุกประโยค.
- ใช้ **คำของผู้พูดเอง** เป็นหลัก (ตัดคำซ้ำ, "เนี่ย/อ่ะ/นะครับ", คำเชื่อมยาว) — ให้คนที่ดูคลิปแล้วจำได้ว่าเป็นเรื่องเดียวกัน.
- ถ้าคลิปเดียวกันตัดด้วย talking-head-editorial แล้ว ให้ใช้ **คำสำคัญ + สไตล์ (k/i/hl) และ brand.json ชุดเดียวกับคลิป**
  และยกการ์ดที่เคยทำ (ฉากใน timeline.js) มาใช้ได้ — ย้ายตำแหน่ง y จาก 1920 มาเป็น 1080 (`references/deck-api.md` หัวข้อ "ยกการ์ดจาก timeline.js").
- หน้าผู้พูด: ใช้เฟรมจากคลิปบน **ปก** และ/หรือ **CTA** ("ดูคลิปเต็ม") — `photo()` มุมมนบนพื้นครีม/ดำ. ใช้ไม่เกิน 2 สไลด์.

## ไฟล์ใน skill

|---|---|
| `references/deck-api.md` | ก่อนเขียน deck.js — `slide()`, ข้อความ, รูป, MG kit, พิกัด และกับดัก |
| `references/slide-library.md` | เลือกชนิดสไลด์: ปก, ประกอบคำ, รายการ, โปสเตอร์, รูป, สูตร MG, CTA |

| `scripts/deliver_github.sh` | ส่งไฟล์ใหญ่ผ่าน GitHub → ลิงก์ดาวน์โหลด |
| `assets/engine_*.html` | เอนจิน + ชุดสไลด์ + MG kit (ไม่ต้องแก้) |
| `assets/brand.default.json` | ค่าแบรนด์เริ่มต้น (accent เขียวมะนาว, Mitr + Sriracha, handle ว่าง) |
