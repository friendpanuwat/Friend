# Talking-Head Overlay

สไตล์นี้แตกจาก `talking-head-motion` (v9) — ใช้เอนจิน, ซับ, เสียง และ pipeline ชุดเดียวกัน แต่ **ไม่มีฉากเต็มจอ**:
หน้าคนพูดชัดตลอดทั้งคลิป และภาพประกอบเป็น **วิดเจ็ตเล็ก** ที่เด้งขึ้นในที่ว่างของเฟรมเฉพาะตอนที่ประโยคนั้นมีภาพให้เล่า
(แชตที่ลูกค้าอ่านแล้วเงียบ, ป้ายราคาโดนขีดฆ่า, กราฟดิ่งลง, เครื่องหมาย ? ส่ายไปมา, เป้าล็อกตรงกลาง ฯลฯ).

งานนี้ทำด้วยโค้ด: HTML/CSS/WAAPI เรนเดอร์ทีละเฟรมใน Chromium (Playwright) แล้วรวมด้วย ffmpeg — ทุกเฟรมคำนวณจากเวลา
จึงเรนเดอร์ซ้ำได้ตรงเป๊ะ. คุณ (Claude) เป็นคนเขียน `timeline.js` ของแต่ละคลิป; เอนจิน, ชุดวิดเจ็ต (`assets/overlay_kit.js`), เสียง และ pipeline มีให้แล้ว.

## สิ่งที่ต้องรู้ก่อนเริ่ม

- **คุณฟังเสียงไม่ได้** และมักติดตั้งตัวถอดเสียงไม่ได้ → ต้องได้บทพูดพร้อมเวลาจากผู้ใช้ (.srt จาก CapCut ดีที่สุด หรือบรรทัด `MM:SS ข้อความ`).
  ถ้าบทไม่ครบความยาวคลิป ให้ถามส่วนที่ขาด อย่าเดาเนื้อหา.
- **คุณดูวิดีโอได้แค่เป็นภาพนิ่ง** → ตรวจงานด้วย contact sheet / preview เสมอ และบอกผู้ใช้ตรง ๆ ว่าความลื่นของ motion และความดังเสียงต้องให้เขาดู/ฟังยืนยัน.
- **ผู้ใช้ส่วนใหญ่สั่งงานจากมือถือผ่าน Claude Code บนเว็บ/แอป** — งานรันบนเครื่องคลาวด์ที่มี ffmpeg, Node + playwright (Chromium), python3 อยู่แล้ว.
  ห้ามขอให้ผู้ใช้ติดตั้งโปรแกรมหรือรันคำสั่งเอง. รัน `scripts/check_env.sh` ก่อนเสมอ; ถ้าขาดอะไร ลองติดตั้งเองด้วยคำสั่งที่สคริปต์พิมพ์.
- ไฟล์ที่ส่งให้ผู้ใช้ต้องดาวน์โหลดบนมือถือได้: ≤ ~30 MB (pipeline เข้ารหัส 2-pass ให้แล้ว).

## Workflow

ตั้ง `SK=<path ของ skill นี้>` และ `P=<โฟลเดอร์งาน>` (ชื่อสั้น ไม่มีช่องว่าง).

1. **ตรวจเครื่อง** — `bash $SK/scripts/check_env.sh`
2. **รับไฟล์** — `bash $SK/scripts/fetch_video.sh $P <ไฟล์แนบ | ลิงก์ Google Drive | หลายท่อนเรียงลำดับ>` → `$P/input.*`
   (ลิงก์ Drive ต้องแชร์แบบ "ทุกคนที่มีลิงก์"; ถ้าดาวน์โหลดไม่ได้ ให้บอกผู้ใช้ตามข้อความที่สคริปต์พิมพ์).
   ต้องมีบทพูดพร้อมเวลา และแบรนด์ (ถ้ามี: คัดลอก `$SK/assets/brand.default.json` เป็น `$P/brand.json` แล้วแก้).
3. **จับเวลาบทพูด** — `bash $SK/scripts/word_timing.sh $P <video> <transcript>` → `chunks.json` / `chunks.md`
   (Whisper จับเวลาจริงทีละคำแล้วจับคู่กับบทของผู้ใช้ — แม่นกว่าเวลาวินาทีเต็มมาก; ถ้าติดตั้ง/โหลดโมเดลไม่ได้ สคริปต์ถอยไปใช้
   `make_timeline.py` ให้เอง). แถวที่มี `*` คือเดาเวลาจากแถวข้าง ๆ — เปิด `words.json` ดูคำแถวนั้นแล้วแก้ใน chunks.json เองถ้าจำเป็น.
   บทที่มีเวลาแค่ระดับวินาทีจะได้บางแถวที่ `end < start` หรือสั้นผิดปกติ — ปรับเวลาเองให้ต่อกันอย่างสมเหตุสมผล และบอกผู้ใช้ว่าจุดไหนเดา.
4. **หาพื้นที่ว่าง** — `bash $SK/scripts/pipeline.sh $P <video> frames` แล้วทำ contact sheet ทุก 2 วินาทีจาก `$P/src_frames`
   (`ffmpeg -pattern_type glob -i '$P/src_frames/*.jpg' -vf "select='not(mod(n\,60))',scale=270:480,tile=7x3" -frames:v 1 $P/contact.jpg`).
   หา **โซนวิดเจ็ต**: ส่วนใหญ่คือเหนือหัว (เพดาน/ผนัง) — จดขอบล่างของโซน = ยอดหัวที่สูงที่สุดในคลิป − ~40 px (ซูมกล้องดันหัวขึ้นได้ ~20 px).
   ถ้าเหนือหัวแคบกว่า ~250 px ให้ใช้ข้างลำตัว (ซ้าย x 40–330) แทน และย่อวิดเจ็ต. ดู `references/standards.md` หัวข้อโซน.
5. **วางแผนแล้วให้ผู้ใช้เห็นก่อนเขียนโค้ด** — ตาราง `ช่วงเวลา · คำพูด · ซับ (คำเน้น) · วิดเจ็ต`. วิดเจ็ต ~1 ชิ้นต่อ 3–4 วินาที
   (≈ 10–12 ชิ้นต่อ 40 วินาที) เฉพาะประโยคที่ภาพช่วยเล่า, เว้นช่วงไม่มีวิดเจ็ตบ้างให้คนดูพักสายตา. ช่องวิดเจ็ตบอกเป็นภาพที่เห็น
   ซึ่งคิดจากประโยคนั้นของคลิปนี้. ผู้ใช้สั่ง "ทำเลย" ก็ไปต่อได้.
6. **เขียน `$P/timeline.js`** — อ่าน `references/timeline-api.md` (ซับ + kit) และ `references/widget-library.md` (สูตรวิดเจ็ต 11 แบบ) ก่อน;
   เปิด `examples/timeline_example.js` (ของจริง 42 วินาที) เพื่อดูระดับงานและวิธีใช้ฟังก์ชัน — **ออกแบบวิดเจ็ตใหม่ให้คลิปนี้ทุกครั้ง**
   ห้ามคัดลอกวิดเจ็ตจากตัวอย่างหรือคลิปก่อนมาเปลี่ยนคำ (ดู "Motion graphics ต้องทำใหม่ให้คลิปนั้น" ด้านล่าง).
   **ห้ามเรียก `scene()`** ในสไตล์นี้ และห้ามใส่ `backdrop-filter` / `filter: blur` บนวิดเจ็ตที่ค้างจอ (คลิปต้องคมตลอด).
7. **Build + preview + ตรวจเอง** — `bash $SK/scripts/pipeline.sh $P <video> build` แล้ว
   `PREVIEW="t1,t2,..." bash $SK/scripts/pipeline.sh $P <video> preview` อย่างน้อย 1 เฟรมต่อวิดเจ็ตและต่อก้อนซับ (หลังขึ้น ~0.5 วินาที).
   ดูโซนวิดเจ็ตแบบซูม: `ffmpeg -pattern_type glob -i '$P/prev/p_*.jpg' -vf "crop=1080:640:0:100,scale=360:-1,tile=4x3" $P/top.jpg`.
   แก้ตาม QC ใน `references/standards.md` จนผ่าน. render.js ออกด้วย exit code 2 ถ้ามี JavaScript error — แก้ก่อนไปต่อ.
8. **เรนเดอร์ + เสียง + ไฟล์** — `pipeline.sh $P <video> render`, `... audio`, `... encode` (หรือ `all`). รันแบบ background ได้ (~5–8 นาที / 45 วิ).
9. **QC รอบสุดท้ายแล้วส่ง** — ดู `$P/qc_sheet.jpg` (ซับเบลอในบางช่องเป็นจังหวะเฟดระหว่างก้อน ไม่ใช่บั๊ก — ยืนยันด้วยเฟรมจาก `$P/out_frames`),
   ส่ง `$P/edit.mp4` พร้อมตาราง "วินาที · วิดเจ็ต" และขอฟีดแบ็กแบบระบุวินาที.
   **ไฟล์คุณภาพสูง** — เมื่อ session มี GitHub repo: `pipeline.sh $P <video> hq` (ได้ `edit_hq.mp4`) แล้วส่งผ่าน repo
   (`scripts/deliver_github.sh` ดันไป branch `exports`; ถ้า session จำกัดให้ push ได้เฉพาะ branch ที่กำหนด ให้ commit ไฟล์ไว้ใน `exports/` ของ branch นั้นแทน)
   แล้วให้ลิงก์ `https://github.com/<owner>/<repo>/raw/<branch>/exports/<ไฟล์>`. ตั้งชื่อเวอร์ชันถัดไป v2, v3 … แก้เฉพาะจุดแล้ว preview ก่อนเรนเดอร์ทั้งคลิป.

## หลักที่ทำให้สไตล์นี้ออกมาดี (และเหตุผล)

- **หน้าคนพูดคือพระเอก** — คนดูติดตามสีหน้า; วิดเจ็ตเป็นแค่ "คำอธิบายภาพ" ข้างหัว จึงต้องเล็ก (กว้าง ≤ ~600 px สูง ≤ ~400 px) และไม่บังหน้าแม้ตอนซูม.
- **คลิปไม่เบลอ ไม่มืดลง** — ผู้ใช้ที่ขอสไตล์นี้ปฏิเสธการเบลอพื้นหลัง; การ์ดใช้พื้นมืดโปร่งแสง `.mini` (ไม่มี backdrop-filter).
- **Motion graphics ต้องทำใหม่ให้คลิปนั้น** (ผู้ใช้สั่ง) — วิดเจ็ตทุกชิ้นคิดจากเนื้อหาของคลิปนี้ทีละประโยค: พูดถึงอะไร,
  เห็นอะไรแล้วเข้าใจทันที, อะไรเกิดตรงคำสำคัญ — แล้วประกอบจากชิ้นใน kit. **ห้ามเอาวิดเจ็ตจากตัวอย่างหรือคลิปก่อนมาเปลี่ยนคำพูด**.
  **สไตล์ไม่เปลี่ยน** — ตัวอักษรพลิก 3D, สี, การ์ดมืด, ฟอนต์ และการเคลื่อนไหวคงเดิม; ที่ต่างกันแต่ละคลิปคือ "วาดอะไร จัดวางยังไง และอะไรเกิดตรงคำ".
- **ไม่ปรับสีวิดีโอ** (ผู้ใช้สั่ง) — คลิปตามที่ถ่าย ไม่มี filter สี, ไล่สี, vignette หรือเกรนฟิล์ม.
- **วิดเจ็ตต้องเล่าความหมาย** — ถามตัวเองว่า "ถ้าปิดเสียง วิดเจ็ตนี้ยังสื่อไหม"; ส่วนประกอบในวิดเจ็ตขึ้นตามคำพูด (แถวที่ 2 ขึ้นตอนพูดคำที่ 2).
- **ทีละชิ้น** — วิดเจ็ตก่อนหน้าต้องหายก่อนชิ้นถัดไปขึ้น (t1 ≤ t0 ถัดไป) ไม่งั้นจะซ้อนกันเหนือหัว.
- **ซับครบทุกคำพูด** — ไม่มีฉากเต็มจอมาช่วยเล่า ซับจึงต้องต่อเนื่องทั้งคลิป (ตัดคำลงท้าย "เนี่ย/อ่ะ/เว้ย" ได้ บอกผู้ใช้ว่าทำ).
- **จังหวะช้า นุ่ม ไม่รีบ** (ผู้ใช้สั่ง — เวอร์ชันที่ขยับเร็ว/เด้งแรงถูกติว่า "รีบ แข็ง แปลก") — กราฟิกเข้า 0.7–0.9 วินาที (`SOFT`), ออก 0.4 วินาที;
  การเคลื่อนไหวหลักชิ้นละ **1 อย่าง** ตรงคำสำคัญ ยาว 0.6–1.0 วินาที (`CALM`) แล้ว**ค้างนิ่งให้อ่านทัน** ≥ 0.5 วินาที. ห้ามวนซ้ำเร็ว ๆ
  (สลับ/ส่าย/กระพริบเกิน 2 ครั้ง หรือรอบละ < 0.8 วินาที) — ช่วงรอใช้ลอยขึ้นลงช้า ๆ แทน; ห้าม duration < 0.4 วินาที ยกเว้นเส้นขีดฆ่า (0.4–0.5).
  ฟังก์ชันในเอนจิน (`rise`, `fadeOut`, `draw`, `widget`, `popIn`, `iconChip`, `strikeChip`) ตั้งค่าเริ่มต้นตามนี้แล้ว — **อย่าใส่ duration สั้นกว่าค่าเริ่ม**, และอย่าลอกตัวเลขเวลาจากไฟล์ตัวอย่างที่สั้นกว่านี้.
- **ซูมน้อย ช้า** (ผู้ใช้สั่ง — ซูมทุกก้อนซับถูกติว่าถี่เกิน) — ซูมเข้า 4–5 ครั้งต่อคลิป (ห่างกัน ≥ 4 วินาที) เฉพาะประโยคแรง:
  ค่อย ๆ ดันเข้า 1.04–1.06 ใน 1–1.5 วินาที แล้วกลับ 1.0 ใน ~1 วินาทีตอนขึ้นเรื่องใหม่; ไม่ซูมกระแทกตามคำเน้น (`keyHit` อย่างเดียวพอ).
  build เตือน `WARNING pace` เมื่อเกินกฎ — แก้ timeline จนไม่มีคำเตือน.
  ไม่มีจังหวะตัดฉากไปซ่อนการรีเซ็ตซูม → ห้าม dur สั้นกว่า 0.8 (ห้าม `.01`).
- **ห้ามแต่งข้อเท็จจริง** — ไม่ใส่ตัวเลข ราคา % หรือชื่อที่ผู้พูดไม่ได้พูด (แถบ/กราฟใช้สัดส่วนแทนตัวเลข); ใช้ชื่อแบรนด์เป็นตัวอักษร ไม่ใช้โลโก้จริง.
- **นิ่งดีกว่าจุกจิก** — ไม่ใช้กลิตช์, อีโมจิ, เสียงการ์ตูน.

## ไฟล์ใน skill

| ไฟล์ | ใช้เมื่อ |
|---|---|
| `references/timeline-api.md` | ก่อนเขียน timeline.js — ซับ ซูม เสียง และฟังก์ชันใน overlay kit |
| `references/widget-library.md` | เลือก/ดัดแปลงวิดเจ็ต 11 แบบ + วิธีออกแบบใหม่ |
| `references/standards.md` | สี ฟอนต์ โซนบนจอ motion เสียง QC checklist และการตั้งค่าแบรนด์ |
| `examples/timeline_example.js` | ตัวอย่างระดับงานเต็มคลิป (ไทย 42 วินาที, 11 วิดเจ็ต) — ดูเป็นไอเดีย ห้ามคัดลอกวิดเจ็ต |
| `assets/overlay_kit.js` | ชุดวิดเจ็ต (build แทรกให้อัตโนมัติ — ไม่ต้อง copy ลง timeline) |
| `assets/engine_*.html` | เอนจิน (ไม่ต้องแก้) |
| `scripts/pipeline.sh` | frames · build · preview · render · audio · encode · hq |
| `scripts/word_timing.sh` | บท + เสียง → chunks.json เวลาระดับคำ (Whisper, มี fallback ไป `make_timeline.py`) |
| `scripts/fetch_video.sh` / `make_timeline.py` / `deliver_github.sh` | รับคลิป · แปลงบท (fallback) · ส่งไฟล์ใหญ่ |
