# Talking-Head Glass UI

ภาษาภาพ: คนพูดคมชัดเป็นพระเอก, ใต้คางมี **ก้อนข้อมูลก้อนเดียว** บนแกนกลางจอ — ซับสามชั้น
(คำนำตัวเอียงเล็ก → **คำสำคัญหนาเอียงไล่ขาว→ฟ้า→น้ำเงิน** ปาดเข้าตอนพูด → คำท้าย) แล้วตามด้วย **UI กระจกที่ดูเหมือนหน้าจอแอปจริง**
ซึ่งออกแบบจากความหมายของประโยคนั้น ๆ. กล้องมีจังหวะ (เบลอ→ชัด, whip, push) และมีฉากพิเศษไม่เกิน 1–2 ครั้งต่อคลิป.

งานนี้ทำด้วยโค้ด: HTML/CSS/WAAPI เรนเดอร์ทีละเฟรมใน Chromium (Playwright) แล้วรวมด้วย ffmpeg — ทุกเฟรมคำนวณจากเวลา จึงเรนเดอร์ซ้ำได้ตรงเป๊ะ.
คุณ (Claude) เป็นคนเขียน `timeline.js` ของแต่ละคลิป; เอนจิน คอมโพเนนต์ กล้อง เสียง และ pipeline มีให้แล้ว.

## ทำตาม reference ไม่ใช่ลอก

ref เป็น **ตัวอย่างวิธีคิด** ไม่ใช่คลังของให้หยิบ. ห้ามยกพร็อพของ ref (บ้าน, ประกัน, "PAID OFF", ค้อนศาล, Yes or No, กระดาษฉีก) มาใส่คลิปที่ไม่ได้พูดเรื่องนั้น.
สิ่งที่เอามาจาก ref คือหลัก 6 ข้อนี้:

1. **ทุกกราฟิกคือคำอธิบายภาพของประโยค** — เริ่มจาก "ประโยคนี้หมายถึงอะไร" แล้วหาภาพที่ทำให้เข้าใจเร็วขึ้น (ลิสต์ที่ไม่ผ่าน, ของที่วนซ้ำ, ก่อน→หลัง, ความคืบหน้า).
   ถ้าคิดภาพที่ดีไม่ออก **ให้มีแค่ซับ** — ช่วงว่างคือส่วนหนึ่งของจังหวะ.
2. **ก้อนเดียว แกนเดียว** — ซับ + UI อยู่กึ่งกลางจอ (x = 540) เป็นหน่วยเดียวใต้คาง, จุดสนใจทีละจุด, UI กว้าง 45–80% ของจอ ไม่ใช่ชิ้นเล็กกระจายมุมจอ.
3. **UI ต้องดูเป็นแอปจริง** — การ์ดกระจกที่มีหัว/แถว/ไอคอนแอป มีโครงสร้าง (ใช้ `gcard`, `versions`, `compare`) ดีกว่าป้ายลอย ๆ หลายชิ้น;
   การ์ดขยายตามข้อที่พูด, แถวขึ้นตรงคำ, มือกดตรงจังหวะ.
4. **ระบบภาพเดียวทั้งคลิป** — ฟ้าตระกูลเดียว + ขาว + กระจก, ฟอนต์ Kanit ตัวเอียงชุดเดียว, **ไอคอนเส้น Lucide เท่านั้น — ห้ามใช้อีโมจิ**, มุมมนและเงาแบบเดียวกันทุกชิ้น.
5. **จังหวะตามเสียง** — คำใหญ่ปาดเข้าพร้อมคำพูด, ทรานสิชันอยู่ต้นประโยค/เปลี่ยนเรื่อง, ทุกการเคลื่อนไหวมีเหตุผล (เข้า → ค้างให้อ่าน ≥ 0.8 วิ → ออก).
6. **ความเรียบร้อยระดับพิกเซล** — ไม่ทับหน้า, ไม่ล้นโซน UI ของแอป, ระยะห่างสม่ำเสมอ, ไม่มีกล่องว่างรอของ, ไม่มีของค้างนอกเวลา, สระไทยไม่โดนตัด.

## สิ่งที่ต้องรู้ก่อนเริ่ม

- **คุณฟังเสียงไม่ได้** → ต้องได้บทพูดพร้อมเวลาจากผู้ใช้ (.srt จาก CapCut ดีที่สุด หรือบรรทัด `MM:SS ข้อความ`).
  ถ้าบทไม่ครบความยาวคลิป ให้ถามส่วนที่ขาด อย่าเดาเนื้อหา. ข้อความบนจอใช้ตามบทของผู้ใช้ (แก้ได้แค่คำผิดชัด ๆ และบอกผู้ใช้).
- **คุณดูวิดีโอได้แค่เป็นภาพนิ่ง** → ตรวจด้วย preview / crop / contact sheet เสมอ และบอกผู้ใช้ตรง ๆ ว่าความลื่นและเสียงต้องให้เขายืนยัน.
- **ผู้ใช้ส่วนใหญ่สั่งงานจากมือถือ** — เครื่องคลาวด์มี ffmpeg, Node + playwright, python3 แล้ว. ห้ามขอให้ผู้ใช้ติดตั้งหรือรันคำสั่งเอง. รัน `scripts/check_env.sh` ก่อนเสมอ.
- ไฟล์ที่ส่งในแชทต้อง ≤ ~30 MB; ไฟล์คุณภาพสูงส่งผ่าน GitHub (ขั้น 9).
- **ห้ามเกรดสีเป็นลุค** — ถ้าคลิปมืด/ทึบ ใช้ `LOOK=clean` ตอนขั้น frames (แก้ exposure/contrast เบา ๆ) และบอกผู้ใช้.

## Workflow

ตั้ง `SK=<path ของ skill นี้>` และ `P=<โฟลเดอร์งาน>` (ชื่อสั้นไม่มีช่องว่าง, ใน scratchpad).

1. **ตรวจเครื่อง** — `bash $SK/scripts/check_env.sh`
2. **รับไฟล์** — `bash $SK/scripts/fetch_video.sh $P <ไฟล์แนบ | ลิงก์ Google Drive | หลายท่อน>` → `$P/input.*`
   (แนบได้ ~30 MB, ใหญ่กว่านั้นใช้ลิงก์ Drive แบบ "ทุกคนที่มีลิงก์" หรือแบ่งท่อน). แบรนด์: คัดลอก `$SK/assets/brand.default.json` เป็น `$P/brand.json` แล้วแก้ถ้าผู้ใช้มีสี.
   รูป/คลิปประกอบจากผู้ใช้ → `$P/img/` (วิดีโอ: `scripts/prep_broll.sh`). ไม่มีรูปก็ไม่ต้องใช้วิดเจ็ตที่ต้องมีรูป — ห้ามดึงรูปจากเว็บ (ลิขสิทธิ์).
3. **จับเวลาบทพูด** — `bash $SK/scripts/word_timing.sh $P <video> <transcript>` → `chunks.json` / `chunks.md`
   (Whisper จับเวลาจริงทีละคำแล้วจับคู่กับบทผู้ใช้; ถ้าใช้ไม่ได้จะถอยไป `make_timeline.py` เอง). แถว `*` = เดาเวลา ให้ตรวจใน `words.json`.
4. **หาโซน** — `[LOOK=clean] [HOLD=0.6] bash $SK/scripts/pipeline.sh $P <video> frames` แล้วเปิด `$P/grid.jpg` (เส้นกริดทุก 100 px)
   + contact sheet ทุก 2 วินาที: `ffmpeg -pattern_type glob -i "$P/src_frames/*.jpg" -vf "select='not(mod(n\,60))',scale=270:480,tile=7x3" -frames:v 1 $P/contact.jpg`.
   จดยอดหัว / คาง / กลางหน้า → ซับ `top` = คาง + 30–40; UI อยู่ใต้ซับถึง y 1620. หน้าใหญ่จนที่ว่างน้อย → ช่วงที่มี UI ให้ซับเหลือแค่คำนำ.
5. **Visual brief แล้วให้ผู้ใช้เห็นก่อนเขียนโค้ด** — ตาราง `ช่วงเวลา · คำพูด · ความหมาย (1 บรรทัด) · ซับ (คำนำ / คำใหญ่ / ท้าย) · ภาพ/UI · กล้อง`.
   ทุกแถวที่มี UI ต้องตอบได้ว่า "ภาพนี้ช่วยให้เข้าใจอะไร". สัดส่วนที่ดี: UI 1 ชิ้นต่อ 3–5 วิ, ช่วงมีแค่ซับ ≥ 30% ของคลิป, screen ≤ 1 ครั้ง.
   ผู้ใช้สั่ง "ทำเลย" ก็ไปต่อได้.
6. **เขียน `$P/timeline.js`** — อ่าน `references/timeline-api.md` และ `references/widget-library.md` ก่อน;
   เปิด `examples/timeline_example.js` (ไทย 24 วินาที วางแผนจากความหมาย) แล้วดัดแปลง.
7. **Build + preview + ตรวจเอง** — `bash $SK/scripts/pipeline.sh $P <video> build` แล้ว
   `PREVIEW="t1,t2,..." bash $SK/scripts/pipeline.sh $P <video> preview` อย่างน้อย 1 เฟรมต่อซับ/UI (หลังขึ้น ~0.4 วิ) + กลางทุกทรานสิชัน.
   ซูมดูโซนอก: `ffmpeg -pattern_type glob -i "$P/prev/p_*.jpg" -vf "crop=1080:900:0:900,scale=540:-2,tile=3x4" -frames:v 1 $P/chest.jpg`.
   ไล่ QC ใน `references/standards.md` แล้วแก้ก่อนเรนเดอร์. เอนจินโยน error (render.js exit 2) ถ้าวิดเจ็ตซ้อนเวลากัน หรือใส่สิ่งที่ไม่ใช่ไอคอน Lucide.
8. **เรนเดอร์ + เสียง + ไฟล์** — `pipeline.sh $P <video> render`, `... audio`, `... encode` (background ได้; 25 วิ ใช้ ~4 นาที).
   ระหว่างเรนเดอร์อย่าแก้ไฟล์ใน `scripts/` (bash อ่านสคริปต์ทีละส่วน — แก้กลางทางทำให้ขั้นถัดไปพัง).
9. **QC รอบสุดท้ายแล้วส่ง** — ดู `$P/qc_sheet.jpg`, ส่ง `$P/edit.mp4` + ตาราง "วินาที · สิ่งที่ใส่ · เพราะอะไร" และขอฟีดแบ็กแบบระบุวินาที.
   **ไฟล์คุณภาพสูง** — เมื่อ session มี GitHub repo: `pipeline.sh $P <video> hq` แล้วรันในโฟลเดอร์ repo
   `bash $SK/scripts/deliver_github.sh $P/edit_hq.mp4 <ชื่อคลิป>_hq.mp4` → ส่งลิงก์ `DOWNLOAD:` พร้อมบอกว่า
   "เปิดลิงก์ในเบราว์เซอร์ที่ล็อกอิน GitHub แล้ว ไฟล์จะดาวน์โหลดลงเครื่อง" (branch `exports` เก็บเฉพาะไฟล์ล่าสุด).
   แก้ตามฟีดแบ็กเฉพาะจุด → preview จุดนั้น → เรนเดอร์ใหม่เป็น edit_v2.mp4, …

## ข้อห้าม

- อีโมจิ (ทุกที่ — ใช้ไอคอน Lucide), โลโก้จริง, รูปจากเว็บ, ตัวเลข/ข้อมูลที่ผู้พูดไม่ได้พูด (`progress` ปิด % ไว้เป็นค่าเริ่ม).
- กราฟิกที่ไม่มีความหมายกับประโยค, หลายชิ้นพร้อมกัน, ชิ้นเล็กกระจายมุมจอ, กล่องว่างรอของ, ทรานสิชันทุกประโยค.
- เกรดสีเป็นลุค, กลิตช์, เสียงการ์ตูน, เพลงที่มีลิขสิทธิ์.
