# Talking-Head Glass UI

สไตล์นี้มาจาก ref ของ @edita.visuals (ฝั่ง "Opus 5.5"): คนพูดอยู่บนจอเกือบตลอด, คลิปคมไม่เกรดสี,
ใต้คางมี **ซับสามชั้น** — คำนำตัวเอียงเล็กสีขาว → **คำสำคัญตัวใหญ่ หนา เอียง ไล่สีฟ้า (ขาว → ฟ้า → น้ำเงิน) ขอบขาวบาง** ที่ปาดเข้าจากซ้าย → คำตามท้ายเล็กชิดขวา.
ใต้ซับ (ระดับอก) มี **วิดเจ็ต UI แบบกระจก** เด้งขึ้นตามเนื้อหา: ป้าย pill กระจกมีติ๊ก/กากบาท + มือคลิก, การ์ด progress ฟ้า, ฟองแชตขาวมีอีโมจิ,
รูปโพลารอยด์, ป้ายขาวที่สีฟ้าปาดเต็ม, กรอบ viewfinder. จังหวะเปลี่ยนเรื่องใช้ **เบลอ→ชัด / whip / push-in** และมีฉากพิเศษไม่เกิน 1–2 ครั้งต่อคลิป:
**screen** (หน้าคนพูดหดเป็นไอคอนแอปบนพื้นฟ้า + ข้อความพิมพ์ทีละตัว) และ **cutaway** (ภาพประกอบเต็มจอ ขอบกระดาษฉีก + กระดาษปลิว).

งานนี้ทำด้วยโค้ด: HTML/CSS/WAAPI เรนเดอร์ทีละเฟรมใน Chromium (Playwright) แล้วรวมด้วย ffmpeg — ทุกเฟรมคำนวณจากเวลา จึงเรนเดอร์ซ้ำได้ตรงเป๊ะ.
คุณ (Claude) เป็นคนเขียน `timeline.js` ของแต่ละคลิป; เอนจิน วิดเจ็ต กล้อง เสียง และ pipeline มีให้แล้ว.
**ขั้นตอนใช้งานเหมือน skill talking-head ตัวอื่นทุกอย่าง** (fetch → word timing → frames → build/preview → render/audio/encode → ส่ง).

## สิ่งที่ต้องรู้ก่อนเริ่ม

- **คุณฟังเสียงไม่ได้** → ต้องได้บทพูดพร้อมเวลาจากผู้ใช้ (.srt จาก CapCut ดีที่สุด หรือบรรทัด `MM:SS ข้อความ`).
  ถ้าบทไม่ครบความยาวคลิป ให้ถามส่วนที่ขาด อย่าเดาเนื้อหา. ข้อความบนจอใช้ตามบทของผู้ใช้ (แก้ได้แค่คำผิดชัด ๆ และบอกผู้ใช้).
- **คุณดูวิดีโอได้แค่เป็นภาพนิ่ง** → ตรวจด้วย preview / crop / contact sheet เสมอ และบอกผู้ใช้ตรง ๆ ว่าความลื่นและเสียงต้องให้เขายืนยัน.
- **ผู้ใช้ส่วนใหญ่สั่งงานจากมือถือ** — เครื่องคลาวด์มี ffmpeg, Node + playwright, python3 แล้ว. ห้ามขอให้ผู้ใช้ติดตั้งหรือรันคำสั่งเอง.
  รัน `scripts/check_env.sh` ก่อนเสมอ (ต้องมีฟอนต์ Noto Color Emoji — ถ้าขาด ติดตั้งเองตามที่สคริปต์บอก).
- ไฟล์ที่ส่งในแชทต้อง ≤ ~30 MB; ไฟล์คุณภาพสูงส่งผ่าน GitHub (ขั้น 9).
- **ห้ามเกรดสีคลิป** · ฟอนต์ Kanit (ตัวเอียง) ชุดเดียวทั้งคลิป · สีตระกูลฟ้าจาก `brand.json` + ขาว; เขียว/แดงใช้เฉพาะความหมาย ใช่/ไม่ใช่.

## Workflow

ตั้ง `SK=<path ของ skill นี้>` และ `P=<โฟลเดอร์งาน>` (ชื่อสั้นไม่มีช่องว่าง, ใน scratchpad).

1. **ตรวจเครื่อง** — `bash $SK/scripts/check_env.sh`
2. **รับไฟล์** — `bash $SK/scripts/fetch_video.sh $P <ไฟล์แนบ | ลิงก์ Google Drive | หลายท่อน>` → `$P/input.*`
   (แนบได้ ~30 MB, ใหญ่กว่านั้นใช้ลิงก์ Drive แบบ "ทุกคนที่มีลิงก์" หรือแบ่งท่อน). แบรนด์: คัดลอก `$SK/assets/brand.default.json` เป็น `$P/brand.json` แล้วแก้ถ้าผู้ใช้มีสี.
   **รูปประกอบ** (โพลารอยด์, viewfinder, thumbnail การ์ด, cutaway) ใช้รูป/คลิปที่ผู้ใช้ส่งมา → `$P/img/` (วิดีโอ: `scripts/prep_broll.sh`).
   ถ้าไม่มี ใช้เฟรมจากคลิปเองได้ (crop ด้วย ffmpeg) หรือข้ามวิดเจ็ตที่ต้องใช้รูป — ห้ามดึงรูปจากเว็บ (ลิขสิทธิ์).
3. **จับเวลาบทพูด** — `bash $SK/scripts/word_timing.sh $P <video> <transcript>` → `chunks.json` / `chunks.md`
   (Whisper จับเวลาจริงทีละคำแล้วจับคู่กับบทผู้ใช้; ถ้าใช้ไม่ได้จะถอยไป `make_timeline.py` เอง). แถว `*` = เดาเวลา ให้ตรวจใน `words.json`.
   ถ้าคำสุดท้ายพูดชิดท้ายไฟล์ ใช้ `HOLD=0.6` ตอนขั้น frames.
4. **หาโซน** — `[HOLD=0.6] bash $SK/scripts/pipeline.sh $P <video> frames` แล้วเปิด `$P/grid.jpg` (เส้นกริดทุก 100 px)
   + contact sheet ทุก 2 วินาที: `ffmpeg -pattern_type glob -i "$P/src_frames/*.jpg" -vf "select='not(mod(n\,60))',scale=270:480,tile=7x3" -frames:v 1 $P/contact.jpg`.
   จดไว้: ยอดหัว, คาง, กลางหน้า. **ซับ** `top` = คาง + 40 (ปกติ 1000–1180). **วิดเจ็ต** = ใต้ซับถึง y 1620 (ระดับอก) หรือข้างหัว/เหนือหัวถ้ามีที่ว่าง.
   **screen** ต้องการ `face: [cx, cy, size]` = สี่เหลี่ยมจัตุรัสครอบหัวถึงคาง (พิกัดวิดีโอ).
5. **วางแผนแล้วให้ผู้ใช้เห็นก่อนเขียนโค้ด** — ตาราง `ช่วงเวลา · คำพูด · ซับ (คำนำ / คำใหญ่ / ท้าย) · วิดเจ็ต / กล้อง`.
   จังหวะจาก ref (23 วินาที): วิดเจ็ต ~8–10 ชิ้น, screen 1, cutaway 1, เบลอ/whip ~6 ครั้ง. ผู้ใช้สั่ง "ทำเลย" ก็ไปต่อได้.
6. **เขียน `$P/timeline.js`** — อ่าน `references/timeline-api.md` และ `references/widget-library.md` ก่อน;
   เปิด `examples/timeline_example.js` (ของจริง 24 วินาที ใช้ทุกวิดเจ็ต) — คัดลอกบล็อกแล้วเปลี่ยนเวลา/ข้อความ/ตำแหน่ง ดีกว่าเขียนใหม่.
7. **Build + preview + ตรวจเอง** — `bash $SK/scripts/pipeline.sh $P <video> build` แล้ว
   `PREVIEW="t1,t2,..." bash $SK/scripts/pipeline.sh $P <video> preview` อย่างน้อย 1 เฟรมต่อซับ/วิดเจ็ต (หลังขึ้น ~0.4 วิ) + กลางทุกทรานสิชัน.
   ซูมดูโซนซับ+วิดเจ็ต: `ffmpeg -pattern_type glob -i "$P/prev/p_*.jpg" -vf "crop=1080:760:0:1000,scale=540:-2,tile=3x4" -frames:v 1 $P/chest.jpg`.
   แก้ตาม QC ใน `references/standards.md`. เอนจินโยน error (render.js exit 2) ถ้าวิดเจ็ตซ้อนเวลากัน.
8. **เรนเดอร์ + เสียง + ไฟล์** — `pipeline.sh $P <video> render`, `... audio`, `... encode` (background ได้; 25 วิ ใช้ ~4–6 นาที).
   ระหว่างเรนเดอร์อย่าแก้ไฟล์ใน `scripts/` (bash อ่านสคริปต์ทีละส่วน — แก้กลางทางทำให้ขั้นถัดไปพัง).
9. **QC รอบสุดท้ายแล้วส่ง** — ดู `$P/qc_sheet.jpg`, ส่ง `$P/edit.mp4` + ตาราง "วินาที · สิ่งที่ใส่" และขอฟีดแบ็กแบบระบุวินาที.
   **ไฟล์คุณภาพสูง** — เมื่อ session มี GitHub repo: `pipeline.sh $P <video> hq` แล้วรันในโฟลเดอร์ repo
   `bash $SK/scripts/deliver_github.sh $P/edit_hq.mp4 <ชื่อคลิป>_hq.mp4` → ส่งลิงก์ `DOWNLOAD:` พร้อมบอกว่า
   "เปิดลิงก์ในเบราว์เซอร์ที่ล็อกอิน GitHub แล้ว ไฟล์จะดาวน์โหลดลงเครื่อง" (branch `exports` เก็บเฉพาะไฟล์ล่าสุด).
   แก้ตามฟีดแบ็กเฉพาะจุด → preview จุดนั้น → เรนเดอร์ใหม่เป็น edit_v2.mp4, …

## หลักที่ทำให้สไตล์นี้ออกมาดี

- **ซับครบทุกคำพูด แต่ละก้อนมีคำใหญ่ 1 จุด** (1–3 คำ) — คำนำ/คำตามท้ายขึ้นทีละคำตรงเวลาพูด, คำใหญ่ปาดเข้าตอนพูดคำนั้น (+ `keyHit`).
  ภาษาอังกฤษเป็นตัวพิมพ์ใหญ่อัตโนมัติ. ช่วงที่วิดเจ็ตเล่าแทนได้ ให้ซับเหลือแค่คำนำ (เหมือน ref ตอนป้าย "I'M FINALLY DONE").
- **วิดเจ็ตอยู่ใต้ซับระดับอก ทีละชิ้น** และต้องเล่าความหมายของประโยค + มี "เหตุการณ์ตรงคำ": ป้ายขึ้นทีละอันตามข้อที่พูด, มือกดตรงคำ,
  แถบเติมตอนพูดว่า "จ่ายจนหมด", สีฟ้าปาดเต็มตอนคำเน้น, อีโมจิแตกตอนอารมณ์พีค, เงินบินตอน "เสียเงิน".
- **ห้ามบังหน้า** — วิดเจ็ตและซับอยู่ใต้คาง หรือข้างหัวในที่ว่าง; ตรวจกับเฟรมที่ซูม/push มากที่สุด.
- **กล้องมีพลังแต่ไม่มั่ว** — `blurIn` ตอนขึ้นประโยค/เรื่องใหม่ (ทุก 3–6 วิ), `whip` ≤ 2 ครั้งต่อคลิป, `push` สำหรับคำเด็ด/ตัวเลขสำคัญ, `shake` สำหรับคำกระแทก.
- **ฉากพิเศษใช้น้อย** — `screen` สำหรับคำถาม/โพล/ลิสต์สั้น ("ใช่หรือไม่?", "เห็นด้วย"); `cutaway` สำหรับภาพเหตุการณ์ที่คนพูดเล่า (ต้องมีรูปจริงจากผู้ใช้หรือเฟรมจากคลิป).
- **อีโมจิได้** (Noto Color Emoji) แต่ต้องตรงความหมาย ≤ 3 ตัวต่อวิดเจ็ต.
- **ห้ามแต่งข้อเท็จจริง** — ไม่ใส่ตัวเลข ราคา % ชื่อ ที่ผู้พูดไม่ได้พูด (`progress` ปิด % ไว้เป็นค่าเริ่ม; เปิดได้เมื่อหมายถึง "ครบ 100%" หรือผู้พูดพูดตัวเลข); ไม่ใช้โลโก้จริง.
