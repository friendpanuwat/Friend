# Modern Carousel

carousel แนวเทมเพลตแบรนด์ยุคใหม่ ใช้ภาษาภาพเดียวกับ reference ที่ผู้ใช้เก็บไว้:
- พาดหัวใหญ่ที่มี **คำ accent หนึ่งจุด** และป้ายหมวดเล็ก (tag) ด้านบน
- **ตัวเลขยักษ์** (01, 99%, 5M+)
- การ์ด UI ลอย (กระจก / ทึบ / เส้นขอบ) และกราฟเส้นเรืองแสง
- มือถือจำลอง, toggle, notification
- เส้นประพร้อมไอคอนปลายทาง, เหรียญ 3D
- ลูกศรวงกลม, handle และเลขหน้าในทุกสไลด์

ทั้งชุดคุมด้วย **ธีมเดียว** (สีพื้น มืด / สว่าง / accent + texture + รูปทรงการ์ด).

**กฎหลักจากผู้ใช้: ถ้าผู้ใช้ไม่ได้ส่งรูปมา ทุกสไลด์ใช้กราฟิก + ตัวอักษร 100%**
- ไม่ดึงรูปจากเน็ต ไม่สร้างภาพคน
- แต่ละสไลด์ต้องมีกราฟิกอย่างน้อยหนึ่งชิ้นที่ช่วยเล่าความหมาย (ไม่ใช่ตัวอักษรล้วน)
- ถ้าผู้ใช้ส่งรูปมา ใช้ `photo()` เฉพาะรูปนั้น

งานทำด้วยโค้ดแบบเดียวกับ editorial-carousel คือ HTML/CSS/WAAPI ใน Chromium (Playwright). คุณ (Claude) เขียน `deck.js` (หนึ่งบล็อก `slide()` ต่อสไลด์); เอนจิน ธีม ชุดกราฟิก และ pipeline มีให้แล้ว.
- **PNG** = ภาพสุดท้ายหลังทุกอย่างเข้าที่
- **MP4** = สไลด์เดียวกันเล่นแอนิเมชัน (ตัวเลขนับขึ้น, วงกลมวาดเอง, toggle เปิด, กราฟวาดเส้น)

## สิ่งที่ต้องรู้ก่อนเริ่ม

- **ห้ามแต่งข้อเท็จจริง**: ข้อความมาจากผู้ใช้ (ข้อความ / บท / SRT / หัวข้อที่เขาให้รายละเอียด). ย่อ ตัด เรียงใหม่ได้
  แต่ **ห้ามสร้างตัวเลขสถิติ เปอร์เซ็นต์ ราคา ชื่อลูกค้า หรือผลลัพธ์ที่ผู้ใช้ไม่ได้ให้**. เทมเพลตแนวนี้ชอบใช้ตัวเลขยักษ์ —
  ถ้าไม่มีตัวเลขจริงให้ใช้ `num()` กับลำดับขั้น (01 02 03) หรือจำนวนที่อยู่ในข้อความ (เช่น "3 เหตุผล" → 3) แทน.
  ถ้าผู้ใช้ให้แค่หัวข้อแล้วขอให้คิดเนื้อหาเอง ให้ร่างข้อความเป็นตารางให้เขายืนยันก่อน และห้ามใส่สถิติที่ไม่มีแหล่ง.
- **คุณดูงานได้เป็นภาพนิ่ง**: ตรวจด้วย `preview.jpg` + เปิด PNG ทุกใบ; ความลื่นของ MP4 ให้ผู้ใช้ยืนยัน.
- **ผู้ใช้ส่วนใหญ่สั่งงานจากมือถือ** บน Claude Code เว็บ/แอป. ห้ามขอให้เขาติดตั้งหรือรันคำสั่ง. รัน `scripts/check_env.sh` ก่อนเสมอ.
- ฟอนต์ **Anuphan** (พาดหัว, ตัวเลข) + **IBM Plex Sans Thai** (เนื้อความ) — OFL ใช้เชิงพาณิชย์ได้. ไม่ใช้โลโก้แบรนด์จริงเป็นภาพ
  (ชื่อแพลตฟอร์มเป็นตัวอักษรได้).

## Workflow

ตั้ง `SK=<path ของ skill นี้>` และ `P=<โฟลเดอร์งาน>` (เช่นใน scratchpad, ชื่อสั้นไม่มีช่องว่าง).

1. **ตรวจเครื่อง**: `bash $SK/scripts/check_env.sh`
2. **รับเนื้อหา + เลือกธีม**
   - เนื้อหาคือข้อความ / บท / SRT ของผู้ใช้. รูปที่ผู้ใช้ส่งมาให้คัดลอกไป `$P/img/`.
   - ถ้าจะใช้เฟรมหน้าจากคลิป: `fetch_video.sh` + `pipeline.sh $P grab …` (เหมือน editorial-carousel).
   - คัดลอก `$SK/assets/brand.default.json` เป็น `$P/brand.json` แล้วตั้ง `theme`, `handle` (`@ชื่อ`), `logo` (1–2 ตัวอักษร).
   - **เลือกธีม** จาก `references/themes.md` ให้เข้ากับหัวข้อ/แบรนด์. ถ้าผู้ใช้ไม่ระบุ ให้เสนอ 1 ธีมพร้อมเหตุผลในตารางแผน
     (ถ้าเขาสั่งให้ทำเลย ใช้ธีมที่เสนอ). สีแบรนด์เองก็ได้: ใส่ `accent`, `accent_ink`, `accent_on_light` ใน brand.json.
   - ขนาดค่าเริ่ม 1080×1080; ถ้าผู้ใช้ขอ 4:5 ใช้ `SIZE=1080x1350` ตอน build (จัดตำแหน่งตามความสูงใหม่).
3. **วางแผนแล้วให้ผู้ใช้เห็นก่อนเขียนโค้ด**: ตาราง `สไลด์ · โทน (dark/light/accent) · พาดหัว (คำ accent ในวงเล็บ) · กราฟิก`.
   หลักดู "โครงเรื่องและจังหวะ" ด้านล่าง + `references/layouts.md`. ถ้าผู้ใช้สั่งให้ทำเลยก็ไปต่อ.
4. **เขียน `$P/deck.js`**: อ่าน `references/deck-api.md` และ `references/layouts.md` ก่อน. ต้นแบบที่จูนแล้ว:
   - `examples/deck_showcase.js`: ชุดกราฟิกครบ (เหรียญ, มือถือ, เช็กลิสต์, toggle, กราฟ, orbit, CTA)
   - `examples/deck_steps.js`: ปก + ความเชื่อ vs ความจริง + ขั้น 01–03 + quote + CTA

   คัดลอกสไลด์มาเปลี่ยนเนื้อหา ดีกว่าเขียนใหม่ — ต้นแบบใช้ได้กับทุกธีม.
5. **Build + PNG + ตรวจ**: `bash $SK/scripts/pipeline.sh $P all` → `$P/slides/NN.png`, `$P/preview.jpg`, `$P/carousel_png.zip`.
   - สคริปต์พิมพ์ `QC slide NN: …` เมื่อเจอปัญหาเหล่านี้ — แก้จนขึ้น `QC clean`:
     - ข้อความล้นขอบ หรือทับ handle / เลขหน้า / ลูกศร
     - ข้อความทับหรือชิดกราฟิกเกินไป (ต้องห่าง ≥ 16 px)
     - ไอคอน / ชิป / avatar / ปุ่ม ถูกขอบสไลด์ตัด
     - เนื้อหาไม่สมดุลบน-ล่าง (`unbalanced` บอกให้ขยับไปทางไหน กี่ px)
   - แล้ว **เปิด PNG ทุกใบ** ตรวจตาม QC ใน `references/standards.md`.
   - render ออก exit 2 ถ้ามี JavaScript error หรือหาไฟล์รูปไม่เจอ.
   - แก้เฉพาะบางสไลด์: `pipeline.sh $P build && pipeline.sh $P stills 3,5`.
   - ลองธีมอื่นทั้งชุด: `THEME=ember pipeline.sh $P all` (ไม่ต้องแก้ deck.js).
6. **MP4 (ถ้าผู้ใช้ขอแบบขยับได้)**: `[SFX=1] bash $SK/scripts/pipeline.sh $P motion` → `$P/slides/NN.mp4` + `carousel_mp4.zip`
   (~8 สไลด์ใช้เวลาไม่ถึง 1 นาที). ดูเฟรมช่วงเข้า + ท้ายของ 1–2 สไลด์ก่อนส่ง.
7. **ส่งงาน**: ส่ง PNG ทุกใบในแชท (เรียงลำดับ) + zip พร้อมตารางสรุปสไลด์ และขอฟีดแบ็กแบบระบุเลขสไลด์.
   - ไฟล์ใหญ่เกินแชท + session มี GitHub repo: `bash $SK/scripts/deliver_github.sh <zip> <ชื่อ>.zip` แล้วส่งลิงก์ `DOWNLOAD:`.
   - เสนอแคปชันโพสต์ได้ (ไม่บังคับ, ไม่ใส่ข้อมูลใหม่).

## โครงเรื่องและจังหวะ

- **5–10 สไลด์** (ค่าเริ่ม 7–8). หนึ่งสไลด์ = หนึ่งความคิด. พาดหัว ≤ 3 บรรทัด, เนื้อความ ≤ 2 บรรทัด.
- **ปก (สไลด์ 1)**: tag หมวด + พาดหัวใหญ่ 100–120 px ที่มีคำ accent / วงกลมล้อมคำ + กราฟิกเด่นหนึ่งชิ้น (เหรียญ, ไอคอน accent, เส้นประ, ornament).
  เนื้อหาสำคัญอยู่ใน x 135–945.
- **สไลด์กลาง** สลับรูปแบบได้หลายแบบ (ดู layouts.md):
  - ขั้นตอน (`num('01')` + พาดหัว + กราฟิก)
  - ความเชื่อ vs ความจริง
  - ตัวเลขเด่น (ใช้เฉพาะตัวเลขจากผู้ใช้)
  - การ์ด UI / มือถือ
  - เช็กลิสต์, กราฟ, orbit
- **ก่อนสุดท้าย**: สรุป / quote ใหญ่บนพื้น accent.
- **สุดท้าย**: CTA (`cta()` ปุ่ม pill) — เซฟ / แชร์ / ติดตาม / ทักแชต; ไม่มีลูกศรเลื่อน (อัตโนมัติ).
- **สลับโทน** dark / light / accent ไม่ให้ซ้ำติดกันเกิน 2 ใบ; accent ใช้ 1–2 ใบต่อชุด (สรุป, quote, CTA).
- **accent สีเดียวทั้งชุด**: ในพาดหัวใช้ได้ 1 จุดต่อสไลด์ (`[คำ]` หรือ `{คำ}` หรือ `((คำ))`). สีแดง (`--neg`) ใช้เฉพาะความหมายลบ (`~ขีดฆ่า~`, กากบาท).
- **ทุกสไลด์มีกราฟิก** และกราฟิกต้อง "เล่า" ความหมายของสไลด์ — ถามตัวเองว่าถ้าลบข้อความออก ภาพยังพอสื่อไหม.
- แอนิเมชันจบใน ~1.5 วิ แล้วค้าง (`dur` 3–4 วิ). PNG ถ่ายตอนท้าย → ของสำคัญต้องอยู่ครบในสถานะสุดท้าย.
