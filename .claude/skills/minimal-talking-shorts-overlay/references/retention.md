# ตัดต่อให้เข้ากับคนสมาธิสั้น (retention) — แบบ overlay

คนดูคลิปสั้นตัดสินใจภายใน 1–2 วินาทีแรก และปัดทิ้งเมื่อภาพนิ่งนานเกินไป. ทุกคลิปใช้กฎนี้ (ผู้ใช้สั่ง).
ไม่ตัดช่วงเงียบและไม่ตัดคลิป: ความเร็วมาจากการ์ด ซับ ซูม และเสียงที่เปลี่ยนตลอด.

## กฎ

1. **เปิดคลิปด้วยหน้าคนพูด + hook** (ผู้ใช้สั่ง)
   - hook คือซับตัวใหญ่ใต้คางที่บอกปัญหาของคลิป (คำจากคำพูดในคลิป) ต้องเห็นแล้วตั้งแต่เฟรม 0 ไม่จางเข้า
     (เริ่มก่อน 0 เล็กน้อย เช่น `kcap(-.2, t1, ...)`)
   - การ์ดใบแรกเด้งขึ้นหลังจากคนดูเห็นหน้าแล้ว ~1.5–2 วินาที
2. **ไม่เร็วเกินไป**: ไม่มีช่วงที่ภาพนิ่งสนิทเกิน ~2 วินาที แต่การ์ดก็**ไม่เด้งขึ้น-ลงถี่**
   - การ์ดละ 2–4.5 วินาที ถ้าข้างในยังขยับตามเสียง: ใช้ `beat()` ให้หลายจังหวะเลื่อนต่อกันในการ์ดเดียว
     (เช่น เหตุผล 3 ข้อในการ์ดเดียว, ลูกค้าน้อยลง → เงียบ → รีบลดราคา)
   - ระหว่างการ์ดเว้นได้ แต่ช่วงที่ไม่มีการ์ดต้องมีซับ/ซูมขยับ
3. **ซับเป็นวลี ~1–1.5 วินาที ครบทุกคำพูด** (รวมหลายท่อนจาก chunks.json): `kcap(t0, t1, 'วลี', {key, keyColor})`
   - ตัวใหญ่ (Anuphan Bold 100), เด้งเข้า, แถบสีเหลืองวิ่งทับตามเวลาที่พูด (คาราโอเกะ); วลียาวจะย่อตัวเองให้พอดี
   - คำสำคัญในวลี: `key` + `keyColor` (แดง = คำร้าย, `HILITE` = คำเน้น); ทั้งวลีเป็นคำสำคัญ: `{color}`
   - วางใต้คาง ไม่บังหน้า
4. **ซูมเฉพาะคำเน้นจริง ๆ** — `zoom()` แบบ talking-head-motion (1.0–1.10, ไม่เกิน 1.14).
5. **เสียงประกอบ / แถบความคืบหน้า: ไม่ใช้** (ผู้ใช้เลือก).

## ตรวจก่อนส่ง

- เฟรม 0 เห็น hook แล้ว
- contact sheet 2 เฟรมต่อวินาที: ไม่มีช่วงไหนที่ 4 เฟรมติดกันเหมือนกันทุกอย่าง; การ์ดไม่ซ้อนกัน; ไม่มีอะไรเลยเส้นแดง (x 900, y 240)
