# Minimal Talking Shorts — Overlay

ตัดต่อคลิปพูดหน้ากล้องแนวตั้ง (1080×1920) ให้ดูเหมือนจ้างคนตัดต่อมืออาชีพ: หน้าคนพูดชัดอยู่บนจอตลอดทั้งคลิป พร้อมซับเป็นวลีที่มีแถบสีวิ่งตามเสียง
และการ์ดกราฟิกมินิมอลชิ้นเล็กที่เด้งขึ้นเหนือหัวเพื่อ "เล่า" สิ่งที่ประโยคนั้นพูด. เป็นสกิลคู่กับ `minimal-talking-shorts` (ตัวนั้นสลับไปฉากพื้นขาวเต็มจอ).
งานทำด้วยโค้ด: HTML/CSS/WAAPI เรนเดอร์ทีละเฟรมใน Chromium แล้วรวมด้วย ffmpeg.
คุณ (Claude) เขียน 2 ไฟล์ต่อคลิป — `graphics.js` (การ์ดของคลิปนี้) และ `timeline.js` (เวลา ซับ ซูม การ์ด); ที่เหลือ skill มีให้.

## ต้องรู้ก่อนเริ่ม

- **คุณฟังเสียงไม่ได้** → ต้องได้บทพูดพร้อมเวลา (บรรทัด `MM:SS ข้อความ` หรือ .srt). ถ้าไม่ครบความยาวคลิป ให้ถามส่วนที่ขาด อย่าเดาเนื้อหา.
  เวลาระดับวินาทีทำงานได้ แต่ซับอาจคลาด ~0.5 วินาที — บอกผู้ใช้.
- **คุณเห็นวิดีโอเป็นภาพนิ่งเท่านั้น** → ตรวจด้วย contact sheet / preview เสมอ.
- **ลูกค้าส่วนใหญ่สั่งจากมือถือ** — งานรันบนเครื่องคลาวด์. ห้ามขอให้ลูกค้าติดตั้งหรือรันอะไรเอง และห้ามเพิ่มขั้นตอนให้ลูกค้า.
- **ไม่ตัดช่วงเงียบ ไม่ตัดคลิป ไม่ปรับสีวิดีโอ ไม่ใส่เสียงประกอบ** — ใช้ภาพและเสียงต้นฉบับ.
- กฎทั้งหมดที่ผู้ใช้ยืนยันแล้วอยู่ใน `references/core.md` — **อ่านทุกครั้งก่อนเริ่ม** ห้ามเปลี่ยนเองโดยไม่ถาม.
- **ทำรวดเดียวจนได้คลิป** — ลูกค้าส่งคลิป + บทพูดแล้วรอรับ `edit.mp4` เท่านั้น: **ไม่ส่งแผนให้อนุมัติ ไม่ส่งภาพตัวอย่างให้อนุมัติ ไม่หยุดถามระหว่างทาง**
  (ถามได้เฉพาะเมื่อทำต่อไม่ได้จริง ๆ เช่น บทพูดไม่ครบความยาวคลิป หรือโหลดคลิปไม่ได้). วางแผนและตรวจภาพตัวอย่างเอง แล้วทำต่อทันที.

## Workflow

ตั้ง `SK=<path ของ skill นี้>` และ `P=<โฟลเดอร์งาน>` (ชื่อสั้น ไม่มีช่องว่าง).

1. **ตรวจเครื่อง** — `bash $SK/scripts/check_env.sh` (ขาดอะไรให้ลองติดตั้งตามที่สคริปต์พิมพ์ ถ้ายังไม่ได้ให้บอกผู้ใช้ตรง ๆ)
2. **รับคลิป** — `bash $SK/scripts/fetch_video.sh $P <ลิงก์ Google Drive | ไฟล์แนบ | หลายท่อน>` → `$P/input.*`
   (ลิงก์ Drive ต้องแชร์แบบ "ทุกคนที่มีลิงก์"; ถ้าโหลดไม่ได้ให้บอกผู้ใช้ตามข้อความที่สคริปต์พิมพ์)
3. **บทพูด → ช่วงเวลา** — เขียนบทลง `$P/transcript.txt` แล้ว `python3 $SK/scripts/make_timeline.py $P/input.* $P/transcript.txt $P` → `$P/chunks.md`
4. **แยกเฟรม + ดูคลิป** — `bash $SK/scripts/pipeline.sh $P frames` แล้วเปิด `$P/face_sheet.jpg` (ภาพทุก 2 วินาที เส้นเหลืองทุก 200 px) จด:
   - แถบหัว (ผมบนสุด → คาง) เป็น y ของจอ 1920 — ถ้าคนขยับ/เปลี่ยนที่ถ่าย ให้จดแยกเป็นช่วงเวลา → `face(top, bottom, t0, t1)`
   - **ที่ว่างเหนือหัว** = y 240 ถึงยอดหัว − 40 (ตอนซูม) — ถ้าน้อยกว่า ~240 px ให้ใช้การ์ดเตี้ยลงหรือวางข้างลำตัว
   - ตัวหนังสือที่ติดมากับคลิป — ห้ามวางอะไรทับ
   - หัวชิดขอบบนไหม (ถ้าใช่ ซูมเบาลง ≤ 1.08)
5. **วางแผน (ทำเอง ไม่ต้องรอใคร)** — จดตาราง `ช่วงเวลา · คำพูด · การ์ด` (บอกเป็นภาพที่เห็น ไม่ใช่ชื่อฟังก์ชัน), ~1 ใบต่อ 3–4 วินาที
   + สิ่งที่ต้องรู้จากข้อ 4 + คำที่จะเติม/แก้/ตัดจากบทพูด แล้วทำข้อ 6 ต่อทันที.
6. **เขียน `$P/graphics.js` และ `$P/timeline.js`** — อ่านก่อน: `references/core.md`, `references/retention.md`, `references/zoom.md`
   และดูตัวอย่างระดับงานที่ `examples/clip01-customers/` (ทำตามกฎปัจจุบันครบ). การ์ดทุกใบต้อง**ออกแบบใหม่ให้คลิปนี้** จาก
   `assets/overlay_kit.js` + `assets/minimal_kit.js` — ห้ามคัดลอกการ์ดจากตัวอย่างหรือคลิปก่อนมาเปลี่ยนคำ. ซับต้องครบทุกคำพูด.
7. **Build + preview + ตรวจเอง** — `bash $SK/scripts/pipeline.sh $P build` (มี JS error หรือ `FACE:` error = หยุดและแก้ — รวมการ์ดที่ชนหัว เลยเส้นบน หรือเลยขอบขวา)
   แล้ว `PREVIEW="0,t1,t2,..." bash $SK/scripts/pipeline.sh $P preview` อย่างน้อย 1 ภาพต่อการ์ดและต่อซับที่ยาว → เปิด `$P/prev.jpg`:
   เฟรม 0 เป็นหน้าคนพูด + hook, ไม่มีอะไรเลยเส้นแดง (ขวา x 900 · บน y 240), ซับไม่แตะหน้า/คาง, การ์ดไม่มีชิ้นไหนหาย ทับกัน หรือเล็กจนอ่านไม่ออก.
8. **เรนเดอร์ + รวมไฟล์** — `bash $SK/scripts/pipeline.sh $P render` แล้ว `... encode` → `$P/edit.mp4` (≤ ~28 MB) + `$P/qc_sheet.jpg`
   (ใช้เวลาประมาณ 1 นาทีต่อวิดีโอ 7 วินาที — คลิป 1:40 ราว 15 นาที; รันแบบ background ได้)
9. **QC แล้วส่ง** — ดู `qc_sheet.jpg` (2 ภาพ/วินาที มีเส้นแดงที่ x 900 และ y 240) แล้วส่ง `edit.mp4` พร้อม:
   ตารางสรุปการ์ดแต่ละช่วง · คำที่แก้/เติม/ตัดจากบทพูด · ข้อจำกัด (เช่นเวลาในบทหยาบ) · ขอฟีดแบ็กแบบระบุวินาที.
   **ไฟล์คุณภาพสูง — ส่งทุกครั้งพร้อม `edit.mp4` ไม่ต้องรอให้ผู้ใช้ขอ:** `pipeline.sh $P hq` → `edit_hq.mp4` แล้ว `bash $SK/scripts/deliver_github.sh $P/edit_hq.mp4 <ชื่อ>.mp4`
   (ต้องรันจากในโฟลเดอร์ repo ของ session; ให้ลิงก์ `DOWNLOAD:` กับผู้ใช้). แก้ตามฟีดแบ็ก: แก้เฉพาะจุด → preview จุดนั้น → render ใหม่.

## timeline.js — สิ่งที่ใช้บ่อย

```js
face(580, 1010, 0, 42);                   // แถบหัว y ของจอ (ผม → คาง) ในช่วงเวลา — ซับ/การ์ดจะหลบเอง
zoom(3.35, 1.08, .12); zoom(4.0, 1.05, .35);  // ซูมแบบ talking-head-motion เฉพาะคำเน้น (zoom.md) — เรียงตามเวลา
kcap(-.2, .98, 'เวลาลูกค้าทักมาถาม', {key: 'ทักมา', keyColor: HILITE, size: 110});   // hook: เห็นตั้งแต่เฟรม 0
kcap(4.0, 4.98, 'ของเราแพงหรือเปล่า', {key: 'แพง', keyColor: RED});   // ซับเป็นวลี ~1–1.5 วินาที ครบทุกคำพูด
cardThink(2.02, 4.98, {...});             // การ์ดของคลิปนี้ (เขียนใน graphics.js) — ทีละใบ ไม่ซ้อนกัน
```

`graphics.js` — การ์ดละฟังก์ชัน:
- `const b = pop(t0, t1)` — การ์ดขาวเหนือหัว (ขนาดออกแบบ 800 × 240, ขยายเองถ้ามีที่ว่าง; `{w, h, x, y}` เปลี่ยนได้) คืนพื้นที่วาดเป็นพิกัดการ์ด
- `cv(b, svg)` — วาด SVG ในการ์ด · `beat(b, t0, t1, {first, last})` — หลายจังหวะในการ์ดเดียว · `txt(b, x, y, 'ข้อความ', {size, color, center})`
- จาก `minimal_kit.js`: `pic` (คนดำทึบ), `HAND`, `card`, `redQ`, `vanishingPerson`, `countUp`, `loop`, `rise`, `popIn`, สี `NIB` `G1` `G2` `G3` `RED` และ `OUT` (เส้นบาง)
- ดูการใช้จริงใน `examples/clip01-customers/graphics.js` (มี `mini()` สำหรับย่อภาพวาดขนาดจอใหญ่ลงในการ์ด)
