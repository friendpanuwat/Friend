# Core — หัวใจของ skill นี้ (ผู้ใช้ยืนยันแล้ว ห้ามเปลี่ยนเองโดยไม่ถาม)

## ขั้นตอนฝั่งลูกค้า
- **ไม่ตัดช่วงเงียบ** และไม่ให้ลูกค้าตัดเองก่อนส่ง — ใช้คลิปตามที่ส่งมา.
- ลูกค้าส่งคลิป + บทพูดพร้อมเวลา แล้วสั่ง — ที่เหลือ Claude ทำบนคลาวด์. ห้ามเพิ่มขั้นตอนให้ลูกค้า (เหตุผลที่เวอร์ชันลบพื้นหลังถูกยกเลิก).

## วิธีเล่าเรื่อง
1. **ประโยคไหนพูดถึงอะไร กราฟิกเล่าสิ่งนั้น** (แชท, ป้ายราคา, ปุ่ม, สวิตช์, รายการ, เส้นทาง) — Claude ออกแบบกราฟิกเองให้เข้ากับเนื้อหา
   ไม่ลอกจาก reference และไม่ใช้หน้าตาแอปจริง. ภาษาภาพ: สะอาด 1 ไอเดียต่อจังหวะ, ตัวหนาแบบ Apple, แสงเรืองเฉพาะสิ่งสำคัญ, เด้งแบบ spring (แนว swishy.ai).
2. **กราฟิกเป็น overlay ทับคลิป — หน้าคนพูดอยู่ตลอด** (ผู้ใช้สั่ง ไม่ใช้ฉากเต็มจอ). โซนวาง: **แถบบนเหนือหัว (ใช้ให้เต็มที่ — พื้นที่ว่างมาก)** · ข้างหัวฝั่งซ้าย · โซนใต้คาง.
   กราฟิกที่อยู่โซนใต้คางและบอกคำพูดอยู่แล้ว (รายการ, ปุ่ม, คำใหญ่) ใช้แทนซับของประโยคนั้นได้.
3. **คำเปลี่ยนเรื่อง = จังหวะตัด** ("แต่…", "เพราะฉะนั้น…") — คำใหญ่เด้ง/ยืดขึ้นใต้คาง + ตัดกระแทกกล้อง.
4. **รายการเหตุผล = บรรทัดไล่ทีละข้อ** พร้อมสัญลักษณ์นำหน้า; คำดี/คำร้ายแยกสีให้ชัด.
5. **ความสงสัย/ความคิด = กราฟิกเล็กข้างหัว** (เช่นเครื่องหมายคำถาม) — ไม่ทับหน้า.

## กล้อง
- ครอปเข้าหาหน้า (~1.2–1.3×) แล้ว **ดันเข้าช้า ๆ ตลอดประโยค**, **ตัดกระแทก** (~1.4×) ตอนขึ้นประโยคใหม่/คำเน้น — `push(t0, t1, from, to)`.
- สูตรซูมพื้นฐาน + การหายใจของกล้อง = talking-head-motion (`zoom.md`).

## ซับ
- ขึ้นตามเสียงพูด ใต้คาง **ห้ามบังหน้า** (`text-and-placement.md`); ประโยคที่กราฟิกโซนใต้คางบอกอยู่แล้ว ไม่ต้องมีซับซ้ำ.

## กฎถาวร
- ห้ามบังหน้า (ทุกกราฟิก ทุกซับ).
- ห้ามแต่งข้อเท็จจริง — ข้อความในฉากมาจากคำพูด; คำที่ต้องเติมให้สั้น ไม่มีตัวเลข/ราคา/ชื่อ และบอกผู้ใช้.
- ไม่ใช้โลโก้/หน้าตาแอปจริง.
- ไม่ปรับสีวิดีโอ (no color grading).
- ไม่ทำหน้าแอปโน้ต (ผู้ใช้ให้เอาออก).
- ไม่ใช้ฉากเต็มจอที่บังคลิป — ใช้ overlay.
- **หลบแถบขวา** (ปุ่มไลก์/ติดตาม/แชร์ของ TikTok/IG): ตัวหนังสือและกราฟิกอยู่ในช่วง x 60–900 (เว้นขวา 180 px), ซับจัดกลางที่ x 480.
