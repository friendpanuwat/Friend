ไฟล์นี้อธิบายว่าระบบสร้าง motion graphics ของ CutPack ทำงานอย่างไร ตั้งแต่ประโยคที่คนพูด จนเป็นภาพในคลิป (เขียน 2026-11-12 ตามที่ Friend ขอ: "ทำไฟล์เรื่องระบบเลโก้อธิบายอย่างละเอียดมาด้วย")
- คำสั่งที่ใช้รัน และรายละเอียดทีละรอบ อยู่ใน `engine/uni/README.md`
- หมวดทั้ง 21 หมวดแบบละเอียด อยู่ใน `CATEGORIES.md`
- ข้อตกลงกับ Friend อยู่ใน `DECISIONS.md` (ข้อ 3) และบทเรียนอยู่ใน `LESSONS.md`

## 1. ระบบเลโก้คืออะไร

**ที่มา:** Friend อยากได้ "ชิ้นส่วนที่ต่อกันได้หลายแบบ เหมือนตัวต่อเลโก้ 1,000 ชิ้น" (2026-11-07) และ "ชุดฐานต้องสามารถใช้ได้กับทุกสไตล์" เพราะในอนาคตอาจมีสไตล์เป็นร้อย ๆ แบบ แต่ละสไตล์ต่างกันที่หน้าตาทั้งหมด ไม่ใช่แค่สีกับฟอนต์

**แนวคิดหลัก: แยก "ความหมาย" ออกจาก "หน้าตา"**
ภาพ 1 ภาพในคลิปเกิดจาก 4 ส่วนที่แยกกัน

| ส่วน | คืออะไร | ใครเป็นคนเลือก |
|---|---|---|
| **หมวด** | ประโยคนี้ทำหน้าที่อะไร เช่น เปรียบเทียบ เตือน หรือเล่าเหตุและผล (21 หมวด) | AI |
| **ใบประกอบ** | ของและคำในภาพ เช่น ไอคอน "กาแฟ" ป้าย "ร้อน" (ช่องของแต่ละหมวด) | AI |
| **ร่าง** | หน้าตาของภาพ 1 แบบ ของหมวดนั้น เช่น ตาชั่ง หรือการ์ดพลิก (ตอนนี้ 150 ร่าง) | โปรแกรม |
| **สไตล์** | สี เส้น พื้น ฟอนต์ ท่าเคลื่อนไหว เสียง และการจัดจอ (8 สไตล์) | ลูกค้า |

เปรียบกับเลโก้:
- **ตัวต่อ** = ชิ้นส่วนกลางใน `kit.js` (การ์ด ไอคอนในกรอบ ป้าย ลูกศร ตาชั่ง สวิตช์ ฯลฯ)
- **แบบประกอบ** = ร่าง บอกว่าเอาตัวต่อไหนวางตรงไหน และขยับตอนไหน
- **ของที่ใส่ในแบบ** = ใบประกอบที่ AI เขียนจากประโยค
- **สีและผิวของตัวต่อ** = สไตล์

**ทำไมต้องแยกแบบนี้**
1. **AI ทำงานน้อย ราคาถูก** AI บอกแค่หมวดกับของ ไม่ต้องเขียนโค้ด และไม่ต้องรู้จักร่าง คำสั่งของ AI จึงไม่ยาวขึ้น แม้ร่างจะเพิ่มเป็นหลายร้อย
2. **เพิ่มสไตล์ได้โดยไม่แตะร่าง** สไตล์ใหม่ 1 ไฟล์ ได้ร่างทั้ง 150 ร่างในหน้าตาใหม่ทันที
3. **ลูกค้าเปลี่ยนสไตล์ได้โดยไม่ต้องวางแผนใหม่** จึงไม่เสียค่า AI ซ้ำ
4. **ผลเหมือนเดิมทุกครั้ง** ข้อมูลเดิมได้คลิปเดิมทุกครั้ง ตรวจและแก้ได้ง่าย
5. **ตรวจได้ด้วยโค้ด** ทุกร่างถูกตรวจเรื่องของทับกัน และสีกลืนกัน ในทุกสไตล์ ก่อนถึงมือ Friend

## 2. จากประโยคถึงภาพ (ลำดับการทำงาน)

```
ประโยคที่พูด
  │  AI (Sonnet 5.5): ประโยคนี้หมวดอะไร + ใบประกอบ        cat_ai.py
  ▼
SENTENCE("web.07", {cat: "B05", wrong: {...}, right: {...}})
  │  โปรแกรมเลือกร่างที่เข้ากับใบประกอบ                       scenes/cats.js  pickVariant()
  ▼
ร่าง B05 "strike" (ข้อผิดโดนขีดฆ่า ข้อถูกได้ ✓)
  │  ร่างวาดบนผืน 1000 × 700 ด้วยตัวต่อใน kit                  scenes/lego_*.js + kit.js
  ▼
ของบนผืน + เวลาของแต่ละจังหวะ
  │  สไตล์ทาสี จัดผืนลงจอ ใส่ท่าเคลื่อนไหวและเสียง            styles/<สไตล์>.js (+ overlay.js)
  ▼
หน้าเว็บ 1 หน้าต่อคลิป → เรนเดอร์ทีละเฟรม → MP4               build.py → core/pipeline.sh
```

**ตัวอย่าง**
ประโยค: "สิ่งที่ลูกค้าต้องการ อาจจะไม่ใช่ส่วนลด"
- AI: หมวด B05 ถูกกับผิด · `wrong` = ไอคอนป้ายราคา ป้าย "ส่วนลด" · `right` = ไอคอนคำถาม ป้าย "คำตอบ"
- โปรแกรม: B05 มี 7 ร่าง เลือกร่างที่ยังไม่ได้ใช้ในคลิปนี้
- ร่าง: วางของ 2 ชิ้น ขีดฆ่าฝั่งผิดตรงคำว่า "ไม่ใช่" แล้วติ๊กฝั่งถูกตรงคำสำคัญ
- สไตล์ card: การ์ดขาวเต็มจอ เส้นกรมท่าหนา สีเน้นเขียวมะนาว ของเด้งเข้ามาแบบสปริง
- สไตล์ glass: กระจกฝ้าบนภาพคนพูดที่เบลอ เส้นบางเรืองแสงฟ้า ของลอยขึ้นจากความเบลอ

ร่างเดียวกัน ใบประกอบเดียวกัน แต่หน้าตาต่างกันทั้งหมดตามสไตล์

## 3. คำศัพท์ของระบบ

| คำ | ในโค้ด | ความหมาย |
|---|---|---|
| หมวด | `CATEGORY` (`B01`–`B21`) | ประเภทของประโยค ตามหน้าที่ ไม่ใช่ตามเรื่อง |
| ใบประกอบ | slots | ช่องข้อมูลของหมวด ทุกร่างในหมวดเดียวกันใช้ช่องชุดเดียวกัน |
| ของ (THING) | `{icon, label, tone, shape}` | ไอคอน 1 ตัว + ป้ายคำ 0–12 ตัวอักษร + โทน (ปกติ เน้น จาง ลบ) + รูปทรง |
| ประโยค | `SENTENCE(id, {cat, say, ...ช่อง})` | 1 ประโยคของคลิป = หมวด + คำนำกับคำสำคัญ (`say`) + ใบประกอบ |
| ร่าง | `VARIANT(หมวด, id, {name, fits, build, small, ui})` | หน้าตา 1 แบบของหมวด |
| ร่างเล็ก | `small` / `SMALL()` | ร่างที่ออกแบบเองสำหรับวิดเจ็ต overlay เหนือหัว |
| ฉาก | `SCENE(id, meta, build)` | ภาพ 1 ภาพที่เล่นในคลิป (ประโยค 1 ประโยคสร้างฉาก `<ประโยค>` และ `<ประโยค>.<ร่าง>` ไว้ทดสอบ) |
| kit | `kit.js` → `K` | ตัวต่อและท่าเคลื่อนไหวที่ร่างเรียกใช้ได้ |
| สไตล์ | `STYLE(id, {...})` | หน้าตาทั้งหมด ตอบแบบฟอร์ม 7 ข้อ |

| ผืนเล็ก | 600 × 340 | ที่วาดของร่างเล็ก ในวิดเจ็ตเหนือหัว วาด 1:1 |
| จังหวะ | `T = {t0, t1, b[], hit, after}` | เวลาเริ่ม เวลาจบ จังหวะย่อย เวลาคำสำคัญ และช่วงหลังคำสำคัญ |

## 4. ใบประกอบ: สิ่งที่ AI เขียน

AI เขียนแค่ JSON สั้น ๆ ต่อประโยค ไม่เขียนโค้ด ไม่เลือกสี ฟอนต์ ท่า หรือร่าง

```json
{"line": 8, "rank": 1, "cat": "B05",
 "shows": "a price tag with a discount is crossed out, an answer bubble gets a tick",
 "slots": {"wrong": {"icon": "tag", "label": "ส่วนลด"}, "right": {"icon": "message-circle-question", "label": "คำตอบ"}},
 "lead": "อาจจะไม่ใช่", "key": "ส่วนลด"}
```

- `shows` = ภาพที่คนดูเห็น ต้องมีความหมายเดียวกับประโยค (ใส่เพื่อให้ AI คิดก่อนเลือก หลังเจอภาพไม่ตรงคำพูดราว 6 ใน 14 ฉาก)
- `rank` = ความสำคัญ 1–3 แต่ละสไตล์เก็บภาพตามจำนวนใน skill ของตัวเอง rank ดีก่อน (2026-11-12)
- คำทุกคำบนจอ (ป้าย คำนำ คำสำคัญ) ต้องคัดลอกจากประโยค ห้ามเรียบเรียงใหม่ ห้ามเพิ่มคำ
- ไอคอนเลือกจากชุด Lucide (ในคำสั่งราว 300 ชื่อที่ใช้บ่อย ตัวตรวจรับได้ทุกชื่อ) ไอคอนที่ดูแรงหรือไม่เหมาะถูกห้ามไว้
- ตัวตรวจ (`cat_ai.py check`) ไล่ทุกช่อง ถ้าผิดส่งกลับให้ AI แก้ 1 รอบ (Haiku 5.5) ภาพที่ยังไม่ผ่านถูกตัดทิ้ง คลิปยังเดินต่อได้
- ประโยคที่ควรมีภาพแต่ไม่เข้าหมวดไหน AI ตอบ `"cat": "none"` พร้อมเหตุผล เราใช้ข้อมูลนี้หาหมวดที่ยังขาด

ช่องของทั้ง 21 หมวด อยู่ใน `CATEGORIES.md`

## 5. ร่าง: แบบประกอบของภาพ

### ร่าง 1 ร่างมีอะไรบ้าง
```js
VARIANT('B05', 'strike', {
  name: 'ข้อผิดโดนขีดฆ่า ข้อถูกได้ ✓',
  fits: s => true,              // ใช้ได้กับใบประกอบแบบไหน (เช่น ร่างโพลต้องมี options 2 ตัว)
  build: (K, s, T) => { ... },  // วาดภาพเต็มจอ
  small: (K, s, T) => { ... },  // วาดร่างเล็กสำหรับ overlay
});
```
ร่างใหม่ทุกร่างใช้ `R3.both` คือออกแบบบนผืนเล็ก 600 × 340 ครั้งเดียว แล้วแบบเต็มจอใช้ภาพเดียวกันขยาย 1.6 เท่า กลางผืน 1000 × 700 ร่างเต็มจอกับร่างเล็กจึงเล่าเรื่องเดียวกันเสมอ

### ร่างวาดอะไรได้ และห้ามอะไร
- **ใช้ได้แค่ตัวต่อใน kit** ห้ามตั้งสี ฟอนต์ ความหนาเส้น หรือความเร็วเอง ทุกชิ้นได้ "ชื่อบทบาท" (เช่น `u-panel` `u-badge` และเส้นแบบ `ln sd fl ac`) แล้วสไตล์เป็นคนทาสี
- **ท่าเคลื่อนไหวเรียกด้วยชื่อ** เช่น `K.enter(el, t, 'pop')` สไตล์เป็นคนกำหนดว่า "pop" หน้าตาเป็นแบบไหน ชุดชื่อท่า: pop drop rise lead key chip leave punch shake move tilt snap swap draw stroke stagger fall float glow
- **ของ 1 ชิ้นมี 4 ชั้นซ้อนกัน** (`o` เข้าออก · `f` ลอยเบา ๆ · `m` เปลี่ยนสถานะ · `p` เด้งหรือสั่น) ท่าจึงไม่เขียนทับกัน
- **วางตำแหน่งด้วย `left/top` เท่านั้น** ห้ามใช้ `transform` เพราะท่าเคลื่อนไหวใช้ `transform` และจะเขียนทับ
- **ห้ามมีคำของประโยคใดประโยคหนึ่งฝังในร่าง** ของทุกชิ้นมาจากใบประกอบ (ดูหลักกลางใน `CATEGORIES.md`)

### ตัวต่อใน kit (บางส่วน)
- **ท่า:** `enter` `leave` `punch` `shake` `move` `fade` `draw` (วาดเส้น) `grow` `float`
- **พื้นผิว:** `panel` (การ์ด) `skel` (เส้นแทนข้อความ) `label` (คำ) `badge` (ไอคอนในกรอบ) `chip` (ป้ายเม็ดยา) `mark` (ติ๊ก กากบาท)
- **ของสำเร็จ:** `toggle` `slider` `checklist` `avatar` `scale` (ตาชั่ง) `halo` `sat` `ghost` และอื่น ๆ
- **ตัวช่วยของแต่ละรอบ:** `LG` (ของในกรอบ ลูกศร `lightUp` = ติดไฟแบบการ์ดทึบโผล่แล้วขยายทับ) · `R6` `R7` `R8` `R9` `R10` (เส้นที่วาดตัวเอง คำชิดซ้าย ของวิ่งตามเส้นทาง คลื่นทรงเดียวกับของ หน้าต่างตัดขอบ ฯลฯ)

### จังหวะของร่าง
เอนจินแบ่งเวลาของฉากเป็นจังหวะ `T.b[0..3]` ไล่ไปจนถึง `T.hit` = เวลาที่พูดคำสำคัญจริง (จากเสียง) แล้ว `T.after` = ช่วงค้าง
ทุกร่างต้องมี **กลไก 3–4 จังหวะ**: เข้า → ทำงาน → ผลลัพธ์ตรงคำสำคัญ → ค้างให้อ่าน (LESSONS 52, Friend: "Animation มันดูไม่มีอะไรเลย" กับร่างที่มีแค่ลอยเข้ามาแล้วติดสี)

### กฎที่ Friend ตั้งไว้สำหรับทุกร่าง (ย่อ ฉบับเต็มใน DECISIONS)
1. ของที่เชื่อมสองสิ่ง (เส้น ลูกศร จุด) อยู่บนแนวตรงระหว่างสองสิ่งพอดี
2. แสง วงกระเพื่อม และคำ ของสิ่งที่กำลังเคลื่อน ขึ้นหลังสิ่งนั้นมาถึงที่แล้ว
3. เครื่องหมายระหว่างสองสิ่ง (= →) อยู่กึ่งกลางช่องว่าง
4. คำใต้ไอคอนอยู่กึ่งกลาง และคำของของในแถวเดียวกันอยู่บรรทัดเดียวกัน
5. วงกระเพื่อมเป็นทรงเดียวกับของที่มันออกมา และออกจากด้านหลัง
6. ไอคอนที่ติดไฟต้องเห็นตลอด ไม่จางจนกลืนพื้น (ใช้ `LG.lightUp`)
7. ของที่ซ้อนแทนของเดิมอยู่ตำแหน่งเดียวกัน ขนาดเดียวกัน ไม่เหลือขอบของเดิม
8. สัญลักษณ์สีแดงไม่วางบนของสีแดง
9. ตาชั่ง: ฝั่งที่ชนะเป็นสีเน้น
10. สีทุกชิ้นต้องไม่กลืนกับพื้นข้างหลัง
11. ของโปร่งแสงที่ต่อกันเป็นเนื้อเดียว ไม่เห็นรอยซ้อน
12. ของที่แบ่งสองส่วนไม่มีเศษติดรอยแบ่ง
13. ร่างเดียวกันหน้าตาเหมือนกันทุกสไตล์ (ต่างแค่สีและผิว)
14. ของที่วางบนของอีกชิ้นต้องสีไม่กลืนกันในทุกสไตล์
15. เส้นวาดครั้งเดียว ไม่มีเส้นขอบซ้อนหลายชั้น

### รสนิยมที่ Friend บอกไว้ (ใช้ตอนคิดร่างใหม่)
- **ชอบ:** ของในชีวิตประจำวันที่เห็นแล้วนึกถึงความหมายทันที (ตู้เซฟ = ความลับ, เทียน = เวลา, จรวดถึงดาว = เป้าหมาย) และมีกลไกทำงานจนจบที่ผลลัพธ์ (หมุนรหัสแล้วประตูเปิด)
- **ไม่ชอบ:** แบบเดิมซ้ำ (ไอคอน 3 อันเรียงกัน) · เปรียบเปรยไกลจนงง (หอยเปิดเจอไข่มุก) · ภาพโล่ง
- **มินิมอลต้องไม่โล่ง:** ของหลักใหญ่เต็มกรอบ ไม่ใช่ของเล็กกลางที่ว่าง
- **สื่อหน้าที่ของหมวดตรง ๆ** อย่าครีเอทีฟเกินจนดูมั่ว (2026-11-11)
- **หลากหลาย:** ร่างในหมวดเดียวกันต้องมีโครงภาพต่างกัน (LESSONS 35)

## 6. โปรแกรมเลือกร่าง

`pickVariant()` ใน `scenes/cats.js` เลือกร่างให้แต่ละประโยค ตามลำดับนี้
1. เก็บเฉพาะร่างที่ `fits` ใบประกอบนี้ (เช่น ร่างที่ต้องมี 2 ตัวเลือก จะถูกข้ามเมื่อประโยคไม่มีตัวเลือก)
2. ถ้าสไตล์ขอร่างแบบหนึ่งก่อน (`prefer`) และมีร่างแบบนั้น ใช้แค่ร่างแบบนั้น
3. เอาร่างที่ใช้น้อยที่สุดในคลิปนี้
4. ไม่ใช้ร่างเดียวกับครั้งก่อนในหมวดเดียวกัน
5. ถ้ายังเหลือหลายร่าง เลือกจากตัวประโยคเอง (hash) ข้อมูลเดิมจึงได้ร่างเดิมทุกครั้ง

ก่อนวาด `calm()` เปลี่ยนโทนแดงที่ AI ใส่ให้ของ เป็นโทนปกติ ในหมวดที่ร่างมีสัญลักษณ์แดงของตัวเอง (B03 B04 B07) เพื่อไม่ให้สัญลักษณ์แดงซ้อนบนของแดง

ในอนาคตตัวเลือกร่างโหลดประวัติคลิปเก่าของลูกค้าได้ (`PICKS`) ลูกค้าคนเดิมจะไม่เจอร่างซ้ำบ่อย

## 7. สไตล์: แบบฟอร์ม 7 ข้อ

สไตล์ 1 สไตล์ = ไฟล์เดียว `engine/uni/styles/<ชื่อ>.js` ตอบ 7 ข้อ

| ข้อ | เรื่อง | ในโค้ด |
|---|---|---|
| 1 | จัดจอ: ผืนอยู่ตรงไหน คนพูดอยู่ไหน ตัดฉากแบบไหน | `frame()` · `speakerFrame()` |
| 2 | พื้นและกรอบ: การ์ด กระจก หน้าต่าง | `css` ของ `u-panel` และพื้น |
| 3 | วิธีวาดของ: เส้นหนาหรือบาง ถมสีหรือโปร่ง เรืองแสงไหม | ตัวแปร `--lw --sd --fl --ac ...` |
| 4 | ชุดสี: พื้น หมึก สีเน้น 1 สี และแดงเฉพาะความหมายลบ | ตัวแปร `--ink --ac --neg --tr ...` |
| 5 | ตัวอักษร: ฟอนต์ ขนาด และคำขึ้นยังไง | `text()` |
| 6 | ท่าเคลื่อนไหว: แต่ละชื่อท่าหน้าตาแบบไหน | `motion: {pop, rise, punch, ...}` |
| 7 | เสียง: ท่าไหนมีเสียงอะไร ดังเท่าไร | `sound: {cut, pop, hit, ...}` |

**สไตล์ที่มีตอนนี้ (8 สไตล์)**

| สไตล์ | หน้าตา | มาจาก |
|---|---|---|
| `card` | ตัดเข้าการ์ดเต็มจอ พื้นสลับดำเรืองแสง ครีม ขาว เส้นหนา เด้งแบบสปริง | skill talking-head-editorial |
| `glass` | กระจกฝ้าบนภาพคนพูดที่เบลอ เส้นบางเรืองแสงฟ้า ตัวอักษรพลิก 3D | skill talking-head-motion |
| `split` | แบ่งจอ หน้าต่างพาสเทลด้านบน คนพูดหดลงกรอบด้านล่าง นิ่งนุ่ม | คลิปตัวอย่างที่ 3 ของ Friend (ไม่มี skill ใช้กฎกลางของ skill) |
| `gold` | ตามคลิป reference ของ Friend (กฎใน `style-rules/gold.md`) | คลิป reference |
| `card-overlay` `glass-overlay` `split-overlay` `gold-overlay` | หน้าตาเดียวกับแบบเต็มจอ แต่คนพูดอยู่บนจอตลอด ภาพเป็นวิดเจ็ตเหนือหัว | skill overlay ของแต่ละแบบ |

**overlay ไม่นับเป็นสไตล์ใหม่** `OVERLAY(id, สไตล์เต็มจอ, def)` ใน `overlay.js` ยืมสี เส้น ท่า และเสียง จากสไตล์เต็มจอ แล้วเปลี่ยนแค่การจัดจอ (วิดเจ็ตเหนือหัว) กับซับใต้คาง

**ทุกสไตล์ยกเว้น gold ทำตาม skill ส่วนตัวของ Friend** (2026-11-12) ทั้งการซูม จำนวนภาพ ซับ และฟอนต์ (รายละเอียดใน HANDOFF หัวข้อ "ทำทุกสไตล์ให้เหมือน skill")

**เพิ่มสไตล์ใหม่:** เขียนไฟล์สไตล์ 1 ไฟล์ ตอบครบ 7 ข้อ แล้วรันตัวตรวจทั้งชุด ร่างทั้ง 150 ร่างจะออกมาในสไตล์ใหม่โดยไม่ต้องแก้ร่าง ถ้าสไตล์ต้องการตัวต่อที่ kit ยังไม่มี ให้เพิ่มใน kit (ทุกสไตล์ได้ใช้ด้วย) ไม่ใช่เขียนในร่าง

## 8. ร่างเล็กสำหรับ overlay

Friend ดูคลิป overlay ตัวอย่างของตัวเองแล้วไม่ชอบภาพเต็มจอที่ถูกย่อ (2026-11-07) ทุกร่างจึงมี **ร่างเล็ก** ที่ออกแบบเองสำหรับวิดเจ็ตเหนือหัว
- ผืน 600 × 340 วาด 1:1 ไม่ย่อจากภาพใหญ่
- ไม่มีประโยคในวิดเจ็ต คำทั้งหมดอยู่ที่ซับใต้คาง
- ของใหญ่ 1–3 ชิ้น (ไอคอนราว 100 px ขึ้นไป) ป้ายไม่เกิน 1–2 คำ
- มีเหตุการณ์ 1 อย่างตรงคำสำคัญ
- วิดเจ็ตต้องไม่บังหน้า แม้ตอนกล้องซูมสุด (ตำแหน่งหน้ามาจากตัวหาหน้า `faces.json`)
- `test_picker.js` ฟ้องถ้าร่างไหนไม่มีร่างเล็ก

## 9. คลิปจริง: จากเสียงถึงคลิป

| ขั้น | ทำอะไร | ไฟล์ | โมเดล |

ในคลิปจริง เอนจินทำเพิ่ม 3 อย่าง (`core.js`)

- **รอยต่อของซับ** ตัดทันที ซับเก่าหายก่อนซับใหม่ขึ้น ไม่มีเฟรมที่สองซับซ้อนกัน

## 12. วิธีเพิ่มของเข้าระบบ

**เพิ่มร่างใหม่** (ลำดับเต็มและคำสั่งใน `engine/uni/README.md` หัวข้อ "เพิ่มร่างใหม่")
1. อ่าน LESSONS ก่อน
2. เลือกหมวด และใช้แค่ช่องของหมวดนั้น
3. ทำภาพนิ่งครบทุกสไตล์ให้ Friend เลือกก่อน (ไฟล์ใน `sketches/` ยังไม่เข้าระบบ)
4. Friend ผ่านแล้ว เขียนการเคลื่อนไหว 3–4 จังหวะด้วย `R3.both` ใน `scenes/`
5. เพิ่มประโยคตัวอย่าง 1 ประโยคต่อร่าง แล้วรัน `test_picker.js`
6. รันตัวตรวจทับกันและสีกลืนครบทุกสไตล์ ดูทีละเฟรม
7. ทำคลิปให้ Friend ดู
8. จดคำตัดสินของ Friend ลง DECISIONS ทันที

**เพิ่มหมวดใหม่**
1. เขียนหมวดใน `scenes/cats.js` (`CATEGORY`)
2. เขียนคำอธิบายหมวดและช่องในคำสั่งของ AI (`cat_ai.py`: ข้อความใน `SYSTEM`, `SLOTS`, `problems()`)
3. เขียนหมวดใน `CATEGORIES.md` ให้ตรงกัน
4. ทำร่างอย่างน้อย 4 ร่าง ตามขั้นตอนเพิ่มร่าง

**เพิ่มสไตล์ใหม่**
1. เขียน `styles/<ชื่อ>.js` ตอบแบบฟอร์ม 7 ข้อ
2. ถ้ามีแบบ overlay เขียน `styles/<ชื่อ>-overlay.js` (สีการ์ด ซับใต้คาง)
3. เพิ่มกฎของสไตล์ใน `tools/clip_plan.py` (`RULES`: จำนวนภาพ ความยาวฉาก วิธีถอยซูม)
4. รันตัวตรวจทุกร่างในสไตล์ใหม่ และรันคลิปจริงด้วย `clip_all_styles.sh` (LESSONS 53)
