# Talking-Head Motion (มาตรฐาน v9)

สร้างคลิปพูดหน้ากล้องแนวตั้งที่ดูเหมือนตัดต่อโดย motion designer: ทุกวลีขึ้นจอตามเสียงพูดด้วยตัวอักษรพลิก 3D,
คำสำคัญเรืองแสงสี accent, ตัดสลับไปฉากกราฟิกเต็มจอที่ "เล่า" ประโยคนั้น แล้วกลับมาที่หน้าคนพูด.

งานนี้ทำด้วยโค้ด: HTML/CSS/WAAPI เรนเดอร์ทีละเฟรมใน Chromium (Playwright) แล้วรวมด้วย ffmpeg — ทุกเฟรมคำนวณจากเวลา
จึงเรนเดอร์ซ้ำได้ตรงเป๊ะ. คุณ (Claude) เป็นคนเขียน `timeline.js` ของแต่ละคลิป; เอนจิน, ฉาก kit, เสียง และ pipeline มีให้แล้ว.

## สิ่งที่ต้องรู้ก่อนเริ่ม

- **คุณฟังเสียงไม่ได้** และมักติดตั้งตัวถอดเสียงไม่ได้ → ต้องได้บทพูดพร้อมเวลาจากผู้ใช้ (.srt หรือบรรทัด `MM:SS ข้อความ`).
  ถ้าบทไม่ครบความยาวคลิป ให้ถามส่วนที่ขาด อย่าเดาเนื้อหา.
- **คุณดูวิดีโอได้แค่เป็นภาพนิ่ง** → ตรวจงานด้วย contact sheet / preview เสมอ และบอกผู้ใช้ตรง ๆ ว่าความลื่นของ motion และความดังเสียงต้องให้เขาดู/ฟังยืนยัน.
- **ผู้ใช้ส่วนใหญ่สั่งงานจากมือถือผ่าน Claude Code บนเว็บ/แอป** — งานรันบนเครื่องคลาวด์ที่มี ffmpeg, Node + playwright (Chromium), python3 อยู่แล้ว.
  ห้ามขอให้ผู้ใช้ติดตั้งโปรแกรมหรือรันคำสั่งเอง; ถ้า skill มาเป็น .zip/.skill ที่แนบในแชท ให้แตกไฟล์เองแล้วใช้โฟลเดอร์นั้นเป็น `SK`.
  รัน `scripts/check_env.sh` ก่อนเสมอ; ถ้าขาดอะไร ลองติดตั้งเองด้วยคำสั่งที่สคริปต์พิมพ์ ถ้ายังไม่ได้ ให้บอกผู้ใช้ตรง ๆ ว่าเครื่องคลาวด์นี้ขาดอะไร.
- ไฟล์ที่ส่งให้ผู้ใช้ต้องดาวน์โหลดบนมือถือได้: ≤ ~30 MB (pipeline เข้ารหัส 2-pass ให้แล้ว).
- **ทำรวดเดียวจนได้คลิป** — ผู้ใช้ส่งคลิป + บทพูดแล้วรอรับ `edit.mp4` เท่านั้น: **ไม่ส่งแผนให้อนุมัติ ไม่ส่งภาพตัวอย่างให้อนุมัติ ไม่หยุดถามระหว่างทาง**
  (ถามได้เฉพาะเมื่อทำต่อไม่ได้จริง ๆ เช่น บทพูดไม่ครบความยาวคลิป หรือโหลดคลิปไม่ได้). วางแผนและตรวจภาพตัวอย่างเอง แล้วทำต่อทันที.

## Workflow

ตั้ง `SK=<path ของ skill นี้>` และ `P=<โฟลเดอร์งาน>` (ชื่อสั้น ไม่มีช่องว่าง).

1. **ตรวจเครื่อง** — `bash $SK/scripts/check_env.sh`
2. **รับไฟล์** — `bash $SK/scripts/fetch_video.sh $P <ไฟล์แนบ | ลิงก์ Google Drive | หลายท่อนเรียงลำดับ>` → `$P/input.*`
   (แนบในแชทได้ไม่เกิน ~30 MB; คลิปใหญ่กว่านั้นให้ผู้ใช้ส่งลิงก์ Drive แบบ "ทุกคนที่มีลิงก์" หรือแบ่งเป็นหลายท่อน — สคริปต์ต่อให้เอง).
   ถ้าดาวน์โหลดไม่ได้ ให้บอกผู้ใช้ตามข้อความที่สคริปต์พิมพ์ (ตั้งแชร์ลิงก์ / environment ต้องเป็น Network access = Full
   ซึ่งตั้งได้ในแอปมือถือ: เลือก environment → Create new environment → Full แล้วเปิด session ใหม่).
   คลิปแนวตั้ง ตัดโลโก้ CapCut ท้ายคลิปออกแล้วถ้ามี; 60fps / HEVC / .mov ใช้ได้ (pipeline แปลงเป็น 30fps ให้). ใช้ `$P/input.*` เป็น <video> ในทุกขั้นถัดไป.
   นอกจากนี้ต้องมีบทพูดพร้อมเวลา และแบรนด์ (ถ้าผู้ใช้มีสี/ฟอนต์ของตัวเอง
   ให้คัดลอก `$SK/assets/brand.default.json` เป็น `$P/brand.json` แล้วแก้ — ดู `references/standards.md` หัวข้อ Brand).
3. **จับเวลาบทพูด** — `bash $SK/scripts/word_timing.sh $P <video> <transcript>` → `chunks.json` / `chunks.md`
   (Whisper จับเวลาจริงทีละคำแล้วจับคู่กับบทของผู้ใช้ — แม่นกว่าเวลาวินาทีเต็มมาก; ถ้าติดตั้ง/โหลดโมเดลไม่ได้ สคริปต์ถอยไปใช้
   `make_timeline.py` ให้เอง). แถวที่มี `*` คือเดาเวลาจากแถวข้าง ๆ — เปิด `words.json` ดูคำแถวนั้นแล้วแก้ใน chunks.json เองถ้าจำเป็น.
   (เวลาเริ่มแต่ละวลีถูกดูดเข้ากับจุดหยุดหายใจจริงในเสียง).
4. **ดูหน้าคนพูด** — `bash $SK/scripts/pipeline.sh $P <video> frames` แล้วทำ contact sheet ทุก 2 วินาทีจาก `$P/src_frames`
   เพื่อหาตำแหน่งใบหน้า/มือ และโซนว่างสำหรับตัวอักษร.
5. **วางแผน (ทำเอง ไม่ต้องรอใคร)** — ตาราง `ช่วงเวลา · คำพูด · การจัดการ (A-roll text / ฉากเต็มจอ / จอดำ / ไอคอน / ป้ายชื่อ)`.
   เลือกคำสำคัญ 1–2 คำต่อประโยค, ฉากเต็มจอ 6–10 ฉากต่อ ~50 วินาที เฉพาะประโยคที่ภาพช่วยเล่า, ประโยคแรง 2 จุด + ตอนจบเป็น statement.
   ช่องฉากบอกเป็นภาพที่เห็นซึ่งคิดจากประโยคนั้นของคลิปนี้ (ไม่ใช่ชื่อฉากจากตัวอย่าง).
   แล้วทำข้อ 6 ต่อทันที.
6. **เขียน `$P/timeline.js`** — อ่าน `references/timeline-api.md` (ฟังก์ชันทั้งหมด) และ `references/scene-library.md`
   (ภาษาภาพ + ตัวอย่างวิธีคิด) ก่อน; เปิด `examples/timeline_example.js` (ของจริง 52 วินาที) เพื่อดูระดับงานและวิธีใช้ฟังก์ชัน —
   **ออกแบบฉากใหม่ให้คลิปนี้ทุกครั้ง** ห้ามคัดลอกฉากจากตัวอย่างหรือคลิปก่อนมาเปลี่ยนคำ (ดู "Motion graphics ต้องทำใหม่ให้คลิปนั้น" ด้านล่าง).
7. **Build + preview + ตรวจเอง** — `bash $SK/scripts/pipeline.sh $P <video> build` แล้ว
   `PREVIEW="t1,t2,..." bash $SK/scripts/pipeline.sh $P <video> preview` อย่างน้อย 1 เฟรมต่อก้อนข้อความและต่อฉาก
   (เลือกเวลาหลังคำสำคัญขึ้น ~0.5 วินาที). เปิด `$P/prev.jpg` ดูตาม QC ใน `references/standards.md` แก้จนผ่าน.
   render.js ออกด้วย exit code 2 ถ้ามี JavaScript error — แก้ก่อนไปต่อ.
8. **เรนเดอร์ + เสียง + ไฟล์** — `pipeline.sh $P <video> render`, `... audio`, `... encode` (หรือ `all` ถ้ายังไม่ได้แยกเฟรม).
   ~50 วินาทีใช้เวลาเรนเดอร์ราว 5–8 นาทีบน 4 คอร์ — รันแบบ background ได้.
9. **QC รอบสุดท้ายแล้วส่ง** — ดู `$P/qc_sheet.jpg`, ส่ง `$P/edit.mp4` (≤ ~30 MB สำหรับดูในแชท) พร้อมตารางสรุปสิ่งที่ใส่ในแต่ละช่วง และขอฟีดแบ็กแบบระบุวินาที.
   **ไฟล์คุณภาพสูงสำหรับโพสต์จริง** — ส่งทุกครั้งเมื่อ session มี GitHub repo (ไม่ต้องรอให้ผู้ใช้ขอ):
   `bash $SK/scripts/pipeline.sh $P <video> hq` (ได้ `edit_hq.mp4` ≈8–12 Mbps, ≤95 MB) แล้ว
   รันจากในโฟลเดอร์ repo: `bash $SK/scripts/deliver_github.sh $P/edit_hq.mp4 <ชื่อคลิป>_hq.mp4` → ส่งลิงก์ `DOWNLOAD:` ให้ผู้ใช้
   พร้อมบอกว่า "เปิดลิงก์ในเบราว์เซอร์ที่ล็อกอิน GitHub แล้ว ไฟล์จะดาวน์โหลดลงเครื่อง". branch `exports` เก็บเฉพาะไฟล์ล่าสุด
   (ไฟล์ก่อนหน้าถูกแทนที่) — ถ้าผู้ใช้ต้องการเก็บหลายไฟล์ ให้บอกให้ดาวน์โหลดก่อนส่งงานชิ้นถัดไป.
   ไม่มี repo ใน session → แจ้งว่าได้แค่ไฟล์ในแชท (คุณภาพต่ำกว่า) และแนะนำให้เปิด session ใหม่โดยเลือก repo.
   ตั้งชื่อเวอร์ชันถัดไป edit_v2.mp4, … เมื่อแก้ตามฟีดแบ็ก ให้แก้เฉพาะจุด แล้ว preview จุดนั้นก่อนเรนเดอร์ทั้งคลิป.

## หลักที่ทำให้งานออกมา "โปร" (และเหตุผล)

- **ตัวอักษรต้องตรงจังหวะพูด** — คนดูอ่านตามเสียง; ช้า/เร็วไปแค่ 0.3 วินาทีก็รู้สึกหลุด. ใช้เวลาจาก chunks.json เสมอ.
- **คำสำคัญน้อย ๆ แต่ชัด** — สี accent + glow มีพลังเพราะใช้ไม่บ่อย. ถ้าทุกคำสำคัญ จะไม่มีคำไหนสำคัญ.
- **Motion graphics ต้องทำใหม่ให้คลิปนั้น** (ผู้ใช้สั่ง) — ฉากทุกฉากคิดจากเนื้อหาของคลิปนี้ทีละประโยค: พูดถึงอะไร,
  เห็นอะไรแล้วเข้าใจทันที, อะไรเกิดตรงคำสำคัญ — แล้วประกอบจากชิ้นใน kit. **ห้ามเอาฉากจากตัวอย่างหรือคลิปก่อนมาเปลี่ยนคำพูด**.
  **สไตล์ไม่เปลี่ยน** — ตัวอักษรพลิก 3D, สี, กระจกฝ้า, ฟอนต์ และการเคลื่อนไหวคงเดิม; ที่ต่างกันแต่ละคลิปคือ "วาดอะไร จัดวางยังไง และอะไรเกิดตรงคำ".
- **ไม่ปรับสีวิดีโอ** (ผู้ใช้สั่ง) — คลิปต้นฉบับตามที่ถ่าย ไม่มี filter สี, ไล่สี, vignette หรือเกรนฟิล์ม; ฉากเต็มจอใช้คลิปเดียวกันที่เบลอเป็นพื้น (ไม่มีพื้นกรมท่า/ออโรร่า).
- **ฉากเต็มจอต้องเล่าความหมายของประโยค** ไม่ใช่ของตกแต่ง — ถามตัวเองว่า "ถ้าปิดเสียง ฉากนี้ยังสื่อไหม".
- **ห้ามแต่งข้อเท็จจริง** — ไม่ใส่ตัวเลข ชื่อ หรือข้อมูลที่ผู้พูดไม่ได้พูด (ยกเว้นบทบาทที่เป็นข้อเท็จจริงสาธารณะที่ผู้พูดอ้างถึง เช่น ตำแหน่งของคนที่เขาพูดถึง);
  ใช้ชื่อแบรนด์เป็นตัวอักษร ไม่ใช้โลโก้จริง.
- **ไม่บังหน้า** — ตัวอักษรอยู่โซนอก (y≈1225–1660), ไอคอนอยู่เหนือหัว, เว้นล่าง 300 px และขวา 140 px ให้ปุ่มของแพลตฟอร์ม.
- **จังหวะช้า นุ่ม ไม่รีบ** (ผู้ใช้สั่ง — เวอร์ชันที่ขยับเร็ว/เด้งแรงถูกติว่า "รีบ แข็ง แปลก") — กราฟิกเข้า 0.7–0.9 วินาที (`SOFT`), ออก 0.4 วินาที;
  การเคลื่อนไหวหลักชิ้นละ **1 อย่าง** ตรงคำสำคัญ ยาว 0.6–1.0 วินาที (`CALM`) แล้ว**ค้างนิ่งให้อ่านทัน** ≥ 0.5 วินาที. ห้ามวนซ้ำเร็ว ๆ
  (สลับ/ส่าย/กระพริบเกิน 2 ครั้ง หรือรอบละ < 0.8 วินาที) — ช่วงรอใช้ลอยขึ้นลงช้า ๆ แทน; ห้าม duration < 0.4 วินาที ยกเว้นเส้นขีดฆ่า (0.4–0.5).
  ฟังก์ชันในเอนจิน (`rise`, `fadeOut`, `draw`) ตั้งค่าเริ่มต้นตามนี้แล้ว — **อย่าใส่ duration สั้นกว่าค่าเริ่ม**, และอย่าลอกตัวเลขเวลาจากไฟล์ตัวอย่างที่สั้นกว่านี้.
- **ซูมน้อย ช้า** (ผู้ใช้สั่ง — ซูมทุกก้อนซับถูกติว่าถี่เกิน) — ซูมเข้า 4–5 ครั้งต่อคลิป (ห่างกัน ≥ 4 วินาที) เฉพาะประโยคแรง:
  ค่อย ๆ ดันเข้า 1.04–1.06 ใน 1–1.5 วินาที แล้วกลับ 1.0 ใน ~1 วินาทีตอนขึ้นเรื่องใหม่; ไม่ซูมกระแทกตามคำเน้น (`keyHit` อย่างเดียวพอ).
  build เตือน `WARNING pace` เมื่อเกินกฎ — แก้ timeline จนไม่มีคำเตือน.
- **ฉากเต็มจอยาว ≥ 1.5 วินาที** — ฉากที่สั้นกว่านั้นทำให้ทุกอย่างต้องขยับเร็ว; ประโยคสั้นให้ใช้ซับบนหน้าแทน หรือรวมกับประโยคข้าง ๆ เป็นฉากเดียว.
- **นิ่งดีกว่าจุกจิก** — ไม่ใช้กลิตช์ RGB, ซูมพุ่ง, อีโมจิ, หรือเสียงการ์ตูน. ผู้ใช้ที่ทดสอบสไตล์นี้ปฏิเสธเวอร์ชันที่เอฟเฟกต์เยอะทุกครั้ง.

## ไฟล์ใน skill

| ไฟล์ | ใช้เมื่อ |
|---|---|
| `references/timeline-api.md` | ก่อนเขียน timeline.js — ฟังก์ชัน พิกัด เวลา และกับดักที่พบบ่อย |
| `references/scene-library.md` | เลือก/ดัดแปลงฉากเต็มจอ 10 แบบ |
| `references/standards.md` | สี ฟอนต์ ขนาด motion เสียง QC checklist และการตั้งค่าแบรนด์ |
| `examples/timeline_example.js` | ตัวอย่างระดับงานเต็มคลิป (ไทย 52 วินาที) — ดูเป็นไอเดีย ห้ามคัดลอกฉาก |
| `scripts/fetch_video.sh` | ดึงคลิปจากไฟล์แนบ / ลิงก์ Drive / หลายท่อน → input |
