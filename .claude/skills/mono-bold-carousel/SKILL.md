# Mono-Bold Carousel

carousel ขาว-ดำ ตัวหนา ที่ผู้ใช้จูนมาแล้วจนพอใจ (ต้นแบบ: โพสต์ "ลูกค้าใหม่แพงกว่าลูกค้าเก่า 5 เท่า" — `examples/deck_bw.js`).
เอนจินเดียวกับ modern-carousel (HTML/CSS/WAAPI ใน Chromium ผ่าน Playwright) แต่ **ล็อกสไตล์ไว้แล้ว**: คุณ (Claude) เขียนแค่ `deck.js`.

## กฎสไตล์ที่ผู้ใช้กำหนด (ห้ามฝ่า)

1. **ขาว-ดำล้วน** — ไม่มีสีอื่น. สไลด์สลับพื้นดำ / พื้นขาว; โทน `accent` = ขาวล้วน (ใช้ใบเดียว ตรงสรุป).
   ยกเว้น **สีความหมาย** เมื่อผู้ใช้ขอเอง: `var(--pos)` เขียว (กำไร/ยอดขายขึ้น/บวก) และ `var(--neg)` แดง (ติดลบ/ลดลง/เตือน)
   — ใช้กับตัวเลข เส้นกราฟ ไอคอน และคำเดียวในพาดหัวผ่าน `tint()` เท่านั้น ไม่ใช้เป็นสีพื้นหรือสีตกแต่ง (ตัวอย่าง: `examples/deck_cashflow.js`).
2. **ตัวหนาทั้งชุด** — พาดหัว/ตัวเลข Anuphan 700, เนื้อความ 500, รายการ/ป้าย 600 (ธีม `bw` ตั้งให้แล้ว).
3. **ห้ามกรอบรอบตัวหนังสือ** (`{คำ}`) และ **ห้ามขีดฆ่า** (`~คำ~`). ห้าม `((วงกลม))` และ `[สี accent]` ด้วย.
4. **ห้ามตัวหนังสือสีเทาอ่อน** โดยเฉพาะบนพื้นขาว — พาดหัวสีเต็มเสมอ (ขาวบนดำ / ดำบนขาว).
5. **เน้นคำด้วย `__เส้นใต้__` เท่านั้น** หนึ่งจุดต่อพาดหัว.

`build_deck.py` ตรวจข้อ 3/5 ให้อัตโนมัติ (ขึ้น `STYLE:` แล้วหยุด). ถ้าผู้ใช้ขอสีแบรนด์ / ไฮไลต์สี → นั่นคืองานของ modern-carousel.

## สิ่งที่ต้องรู้ก่อนเริ่ม

- **ห้ามแต่งข้อเท็จจริง**: ข้อความมาจากผู้ใช้. ย่อ ตัด เรียง แบ่งบรรทัดใหม่ได้ แต่ห้ามสร้างตัวเลข สถิติ ราคา ชื่อ หรือผลลัพธ์ที่เขาไม่ได้ให้.
  ป้ายหมวดสั้น ๆ (ปัญหา, สาเหตุ, สรุป) และปุ่ม CTA ("เซฟโพสต์นี้") เพิ่มได้ — บอกผู้ใช้ตอนส่งงานว่าเพิ่มอะไร.
- ผู้ใช้มักส่งสคริปต์มาเป็นบล็อก `[สไลด์ N — บทบาท]` ครบแล้ว → **ทำเลย** ไม่ต้องถามแผนก่อน. ถ้าให้แค่หัวข้อ ให้ร่างข้อความเป็นตารางให้ยืนยันก่อน.
- คุณดูงานได้เป็นภาพนิ่ง: ตรวจ `preview.jpg` + เปิด PNG ทุกใบ (ครอปดูจุดที่สงสัยด้วย ffmpeg `crop`).
- ผู้ใช้สั่งจากมือถือ — ห้ามขอให้ติดตั้ง/รันคำสั่ง. รัน `scripts/check_env.sh` ก่อนเสมอ.
- ฟอนต์ Anuphan + IBM Plex Sans Thai (OFL ใช้เชิงพาณิชย์ได้). ไม่ใช้โลโก้แบรนด์จริงเป็นภาพ.

## Workflow

ตั้ง `SK=<path ของ skill นี้>` และ `P=<โฟลเดอร์งานใน scratchpad>` (ชื่อสั้นไม่มีช่องว่าง).

1. `bash $SK/scripts/check_env.sh`
2. คัดลอก `$SK/assets/brand.default.json` เป็น `$P/brand.json` (theme `bw`; ใส่ `handle` ถ้าผู้ใช้ให้).
3. **เขียน `$P/deck.js`**: อ่าน `references/layouts.md` + `references/deck-api.md`; เริ่มจากคัดลอก `examples/deck_bw.js`
   แล้วเลือกเลย์เอาต์ B1–B8 ที่ตรงกับบทบาทของแต่ละสไลด์ (hook / setup / สาเหตุ / ตัวเลข / วิธีทำ / rehook / สรุป / CTA).
   ใช้กริดเดิม: tag y140 · พาดหัว y205 (`lh: 1.36`) · เนื้อหา y≈440–900.
4. **Build + PNG + ตรวจ**: `bash $SK/scripts/pipeline.sh $P all` → `$P/slides/NN.png`, `preview.jpg`, `carousel_png.zip`.
   แก้จนไม่มี `STYLE:` และขึ้น `QC clean`, แล้วเปิด PNG ทุกใบตาม QC ใน `references/standards.md`.
   จุดที่พลาดบ่อย: พาดหัวบรรทัดยาวเกิน 920 px (Anuphan Bold กว้าง), ข้อความในการ์ดตัดบรรทัดผิดที่ (ใส่ `\n` เอง / `<br>` ในรายการ),
   การ์ดล่างชนลูกศรมุมขวาล่าง.
5. **MP4** (ถ้าผู้ใช้ขอ): `[SFX=1] bash $SK/scripts/pipeline.sh $P motion` → `slides/NN.mp4` + `carousel_mp4.zip`.
6. **ส่งงาน**: ถ้า session มี git repo ให้คัดลอก `deck.js`, `brand.json`, `slides/`, `preview.jpg`, zip ไป `carousels/<ชื่อ>/` แล้ว commit + push;
   ส่ง PNG ทุกใบ (เรียงลำดับ) + zip ในแชท พร้อมสรุปสั้น ๆ และขอฟีดแบ็กแบบระบุเลขสไลด์.
   ไฟล์ใหญ่เกินแชท: `bash $SK/scripts/deliver_github.sh <zip> <ชื่อ>.zip`.

## โครงเรื่องและจังหวะ

- 6–10 สไลด์ (ปกติ 8). หนึ่งสไลด์ = หนึ่งความคิด. พาดหัว ≤ 3 บรรทัด (ปก) / ≤ 2 บรรทัด (สไลด์ใน).
- ทุกสไลด์มีป้ายหมวด (tag) + พาดหัว + กราฟิกที่ "เล่า" ความหมาย (การ์ดเปรียบเทียบ, แถบสัดส่วน, ขั้นตอน, ไอคอน, เส้นแนวโน้ม).
- โทน: `dark · light · dark · light · dark · light · accent · dark`. สไลด์สุดท้าย = CTA (`cta()` + รายการ เซฟ/คอมเมนต์/แชร์), ไม่มีลูกศร (อัตโนมัติ).
- แอนิเมชันจบใน ~1.5 วิ แล้วค้าง; PNG ถ่ายตอนท้ายสไลด์.
