## เจ้าของโปรเจกต์ และวิธีคุยด้วย

- เจ้าของทำ Jarua คนเดียว **ไม่ใช่โปรแกรมเมอร์** และ **ใช้มือถืออย่างเดียว ไม่มีคอมพิวเตอร์** — ไม่อ่านโค้ด ไม่รันคำสั่งเอง
- ตอบเป็น **ภาษาไทย** อ่านง่าย อ่านครั้งเดียวเข้าใจ · ศัพท์ธุรกิจภาษาอังกฤษให้มีคำแปลไทยในวงเล็บ
- **ทำตามที่สั่งตรงตัว** ไม่เพิ่มของที่ไม่ได้ขอ ไม่ปรับโครงสร้างเอง · ถ้าจะทำต่างจากที่สั่ง **ถามก่อน**
- **ยืนยันลำดับงานกับเจ้าของก่อนเริ่มเขียน**
- เจ้าของเป็นคนตัดสินใจเรื่องโครงสร้างและทิศทาง — เสนอทางเลือกพร้อมเหตุผลและคำแนะนำ แล้วให้เจ้าของเลือก
- เจ้าของจะแย้งถ้าเหตุผลกำกวมหรือวนไปวนมา — ให้เหตุผลตรงและซื่อสัตย์ ถ้าเจ้าของถามว่า "ดีที่สุดแล้วจริงไหม" ให้ตรวจอย่างเป็นระบบ ไม่ใช่ตอบรับทันที
- ถามทีละน้อย ถ้ามีหลายเรื่องให้สรุปว่า "ตกลงแล้ว / ยังต้องตัดสินใจ" แยกให้ชัด เจ้าของงงง่ายเมื่อเรื่องพันกัน
- ทุก Pull Request อธิบายเป็นภาษาไทยง่ายๆ: เปลี่ยนอะไร ผู้ใช้จะเห็นอะไรต่างไป กระทบส่วนไหน ทดสอบอะไรแล้ว
- **ห้ามบอกว่า "บันทึกแล้ว" หรือ "เสร็จแล้ว" จนกว่าจะตรวจซ้ำจริง** (เคยเกิดการบอกว่าบันทึกแล้วแต่ไม่ได้บันทึก จนข้อมูลหาย)

## ข้อห้าม (ถ้าจำเป็นต้องทำ ให้ถามเจ้าของก่อนทุกครั้ง)

- **ห้ามแตะ PL2** (เครื่องสร้างแผนธุรกิจ) ทั้งโค้ดและตาราง เช่น `plan-engine-run`, หน้า `/plan`, `plan_engine_usage`, หน้า business plan, plan-intake, PlanShell, PlanUI, PlanCharts
- **ตัวคำนวณ `src/lib/financialCalculationModule.ts` (ในโค้ดเว็บ) เป็นของ PL2** — Business Lab import มาเรียกใช้ได้ แต่ห้ามแก้ ย้าย หรือเปลี่ยนชื่อ · สำเนาใน repo นี้ `jarua/docs/business-lab/reference/pl2-calc-v4.ts` ก็ห้ามแก้ (รายละเอียดใน HANDOFF ข้อ 9.1)
- การอ้างถึงเครื่องมือ PL1 ในโค้ด Lab ให้ใช้รหัส (เช่น `bmc1`) ไม่เขียนชื่อเครื่องมือตายตัว เพราะชื่อยังเปลี่ยนได้ระหว่างอัปเกรด v6
- **ห้ามเปลี่ยนทิศทาง PL1** (เครื่องมือ AI 83 ตัว) · ห้ามเปลี่ยนโมเดลใน edge function `gemini-run` (ล็อก `google/gemini-3.6-flash`)
- **ห้ามแก้ฐานข้อมูลจริง** (สร้าง/แก้ตาราง, migration, แก้ข้อมูล) โดยไม่ถาม — การแก้ prompt หรือข้อความหน้า tool ในฐานข้อมูลมีผลกับเว็บที่ publish อยู่ทันที
- **ห้าม push เข้าสาขาหลักตรงๆ** — ทำในสาขาแยกและเปิด Pull Request ให้เจ้าของกดรวมเสมอ
- ตอนนำงานขึ้นเว็บ (ผ่าน Lovable) **ห้ามแก้ไฟล์เดียวกับที่ Lovable กำลังแก้** ถ้าไม่แน่ใจให้ถามเจ้าของว่าช่วงนี้ใช้ Lovable อยู่ไหม
- Business Lab **ห้ามใช้ AI หรือ API ตอนรัน**

## ภาษาบนหน้าจอและในเอกสาร

- คำบนหน้าจอ: ภาษาบ้าน ไม่มีศัพท์วิชาการ · ใช้ "คุณ" ไม่ใช้ "ท่าน" · ไม่มีคำว่า "AI" หรือ "prompt" ในข้อความถึงผู้ใช้ของ Business Lab
- ใช้คำชุดเดียวกับที่เจ้าของเลือกไว้ใน PL1 v6 (เช่น "ทางเลือก" "แนวทางแก้ไข" "เหมาะสำหรับ ผู้ที่…") ห้ามคิดคำ "ภาษาง่าย" ขึ้นเอง (รายการใน HANDOFF ข้อ 9.1)
- สะกดตามราชบัณฑิตยสถาน
- เอกสารทำงาน: **ไม่ใส่วันที่หรือป้าย "(เพิ่มใหม่ — วันที่...)"** ทุกข้อเขียนให้อ่านเป็น "สิ่งที่จริงตอนนี้"
