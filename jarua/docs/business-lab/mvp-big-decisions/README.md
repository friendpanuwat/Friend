# MVP ตัวที่ 3 "เช็กก่อนตัดสินใจเรื่องใหญ่" (Business Lab)

- ดูบนมือถือ (artifact ส่วนตัวของเจ้าของ): ลิงก์อยู่ใน `../HANDOFF.md` ข้อ 7.5
- สถานะ ความเห็นเจ้าของ และสิ่งที่ยังต้องตัดสินใจ: `../HANDOFF.md` ข้อ 7.5

## ทำอะไร

เทียบ "ไม่ทำ" กับ "ทำ" ของเรื่องใหญ่ 5 เรื่อง ด้วยตัวเลขร้านของผู้ใช้เอง: จ้างคนเพิ่ม / ย้ายร้าน / ขายผ่านแอปหรือช่องทางใหม่ / ซื้ออุปกรณ์ / เปิดสาขาที่ 2 (เจ้าของตัดเรื่องกู้เงินออกแล้ว)

ผลที่ได้: กำไรต่อเดือนหลังตัดสินใจ · เงื่อนไขที่ทำให้คุ้ม (เช่น ต้องขายเพิ่มวันละกี่แก้ว) · คืนทุนกี่เดือน · เงินสด 12 เดือน (ทำ กับ ไม่ทำ) · ถ้าไม่เป็นอย่างที่คาด · กำไรเปลี่ยนเพราะอะไร → เช็กความพร้อม → จุดที่ควรเช็ก + เครื่องมือ PL1 → แผนธุรกิจ PL2

| `src/decide.js` | แปลงการตัดสินใจเป็นตัวเลขร้านชุดใหม่ แล้วเรียกตัวคำนวณ PL2 (`calculateV4`) · เงินก้อน คืนทุน เงื่อนไขที่ทำให้คุ้ม ถ้าไม่เป็นอย่างที่คาด ใบเสร็จของการตัดสินใจ · ไม่มีสูตรกำไรของตัวเอง |

| `tests/unit.js` | ค่าที่คิดด้วยมือของร้านกาแฟตัวอย่าง · ตรงกับตัวคำนวณ · ใบเสร็จรวมได้เท่ากำไรที่เปลี่ยน · เงื่อนไขถึงจุดคุ้มจริง · คืนทุนตรงกับเงินสะสม · ทุกรูปแบบ × ทุกเรื่อง |

## ใช้ร่วมกับตัวที่ 1 (อ่านอย่างเดียว)

`build.sh` ดึง `../mvp-check-numbers/src/data.js`, `engine.js` และ `style.css` มาใช้ตรงๆ เพื่อให้ข้อมูลร้านชุดกลาง (ช่องกรอก 8 รูปแบบรายได้) สูตร และหน้าตาเป็นชุดเดียวกัน ตามข้อ 5 ใน HANDOFF · ตัวที่ 3 ไม่แก้ไฟล์ของตัวที่ 1 · ถ้าแก้ไฟล์เหล่านั้น ให้รันทดสอบของทั้ง 2 ตัว

## วิธีแก้แล้วส่งให้เจ้าของดู

1. แก้ไฟล์ใน `src/`
2. `./build.sh`
3. `node tests/unit.js && node tests/fuzz.js`
4. `tests/fetch-fonts.sh` (ครั้งแรกครั้งเดียว) แล้ว `node tests/flows.js` · ภาพหน้าจออยู่ใน `.out/shots/`
5. อ่าน artifact เดิมก่อน (Artifact tool `action: "read"` กับลิงก์ใน HANDOFF ข้อ 7.5) แล้ว publish `big-decisions.html` ด้วย `url` เดิม
