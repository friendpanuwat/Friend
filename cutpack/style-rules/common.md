# สกิลกลางของ CutPack: ทำคลิป 1 คลิปตั้งแต่ต้นจนจบ (ทุกสไตล์)

**อ่านไฟล์นี้คู่กับไฟล์ของสไตล์เสมอ** (`neon.md` · `lime.md` · `window.md` …) ไฟล์นี้บอกขั้นตอนที่เหมือนกันทุกสไตล์ ไฟล์ของสไตล์บอกหน้าตาและกฎของสไตล์นั้น
อ่าน 2 ไฟล์นี้แล้วต้องทำคลิปได้โดยไม่ต้องเปิดโค้ด (Friend 2026-11-18: "ดราฟแรกที่ผ่านแล้วอ่ะ ก็ต้องทำไฟล์สกิลโดยละเอียดให้สไตล์นั้นๆด้วย" · LESSONS 64)

หลักของระบบ (Friend 2026-11-17: "เขียน skill ให้ละเอียดนะ AI จะได้คิดน้อยๆที่สุดและผลลัพธ์มันจะได้ออกมาดีสม่ำเสมอกันทุกคลิป")
- **AI ทำ 2 งานเท่านั้น**: ตัดคำพูดเป็นบรรทัดซับ (Haiku 5.5) · เลือกบรรทัดที่มีภาพ หมวด ของในภาพ คำเด่น บรรทัดที่ซูม (Sonnet 5.5 effort low)
- **โค้ดทำที่เหลือทั้งหมด**: หน้าตาภาพ จอ สี เวลา ซับ กล้อง เสียง โดยสุ่มจากเลขของรอบ
- **ทุกคำตอบของ AI ผ่านตัวตรวจของโค้ด** ถ้าผิดกฎ ส่งกลับให้ AI แก้เฉพาะภาพนั้น

## 2. ขั้นตอน 8 ขั้น (คำสั่งจริง)

### ขั้น 1 · เฟรมและเสียง
```
bash core/pipeline.sh $W/base $W/clip.mp4 frames
```
ได้ `$W/base/src_frames/s00001.jpg …` (30 เฟรมต่อวินาที 1080 × 1920 ครอปเต็มจอ) และ `$W/base/voice.wav` (เสียงพูดที่ทำความสะอาดแล้ว)

### ขั้น 2 · ตำแหน่งหน้า
```
python3 plan/faces.py $W/base/src_frames $W/faces.json
```
ได้ `faces.json` = กรอบหน้าทุก 0.5 วินาที (`track`) · ทุกสไตล์ใช้ไฟล์นี้กันภาพและคำไม่ให้ทับหน้า และเลื่อนของลงใต้คาง

### ขั้น 3 · คำพร้อมเวลา (Typhoon บนเครื่องเรา)
```
python3 plan/asr.py $W/clip.mp4 $W/typhoon_words.json --threads 4
python3 plan/align.py $W/typhoon_words.json $W/script.txt $W/words.json     # เฉพาะเมื่อมีบท: เอาคำที่ถูกจากบท เวลาจาก Typhoon
```
ไม่มีบท: ใช้ `$W/typhoon_words.json` แทน `$W/words.json` ในขั้นถัดไป (รูปแบบเดียวกัน `{"words":[{"w","t0","t1"}]}`)

### ขั้น 4 · งาน AI ที่ 1: ตัดซับ (Haiku 5.5 `claude-haiku-5-5`)
มีคีย์:
```
python3 plan/captions.py $W/words.json $W/captions.json
```
ไม่มีคีย์ (ทำแบบเดียวกับที่สคริปต์ส่ง):
1. `python3 plan/captions.py $W/words.json $W/captions.json --dry > $W/cap_dry.txt` → ได้คำขอเป็น JSON (`model` `system` `messages`)
2. ส่ง `system` และ `messages` ตามนั้นให้ Haiku 5.5 · เก็บเฉพาะ JSON ที่ตอบไว้ที่ `$W/cap_answer.json` รูปแบบ `{"lines":[{"chunks":[{"phrase_ends":[1,3]}, …]}, …]}`
3. `python3 plan/captions.py $W/words.json $W/captions.json --answer $W/cap_answer.json`

ได้ `captions.json` = บรรทัดซับ (`captions`: `t0` `t1` `text`) + ก้อนคำพร้อมเวลา · คำตอบที่ไม่ตรงกับคำพูด สคริปต์ตัดตามกฎแทนเอง (`source` บอกว่า `ai` / `ai+rules` / `rules`)

### ขั้น 5 · งาน AI ที่ 2: วางภาพ (Sonnet 5.5 `claude-sonnet-5-5` effort low · รอบแก้ Haiku 5.5)
```
cd uni
python3 cat_ai.py ask $W/captions.json <ความยาวคลิปเป็นวินาที> $W/ask
```
ได้ `$W/ask/system.txt` (คำสั่งรุ่น 5) · `$W/ask/user.txt` (บรรทัดซับมีเลขบรรทัด) · `$W/ask/lines.json`
1. ส่ง `system.txt` เป็น system และ `user.txt` เป็นข้อความผู้ใช้ ให้ Sonnet 5.5 effort low · เก็บ JSON ที่ตอบไว้ที่ `$W/answer.json`
   รูปแบบ: `{"pictures":[{"line":4,"rank":1,"shows":"…","cat":"B04","slots":{…},"key":"…"}, …],"zoom":[4,12,9,1,15,7]}`
2. ตรวจ: `python3 cat_ai.py check $W/ask $W/answer.json $W/cats web`
   ได้ `$W/cats/report.json` (ภาพไหนผ่าน ไม่ผ่านเพราะอะไร) · `sentences.js` · `camera.json` (บรรทัดที่ซูม) · `scenes.txt`
3. ถ้ามีภาพไม่ผ่าน: `python3 cat_ai.py fix $W/ask $W/cats` → ได้ `$W/cats/fix_system.txt` + `fix_user.txt` → ส่งให้ Haiku 5.5 → เก็บที่ `$W/fix_answer.json`
   → ตรวจอีกรอบ: `python3 cat_ai.py check $W/ask $W/answer.json $W/cats web $W/fix_answer.json` (ยังไม่ผ่าน = ภาพนั้นไม่ใช้ บรรทัดนั้นมีแต่ซับ)

ตัวตรวจของโค้ด: หมวดมีจริง · ช่องตรงหมวด · ไอคอนอยู่ในคลัง · คำไทยทุกคำคัดจากบรรทัดนั้นจริง ไม่เกิน 12 ตัวอักษร · ตัวเลขต้องพูดจริง · บรรทัดเดียวไม่มี 2 ภาพ

AI **ไม่ต้อง** เลือกสี หน้าตาภาพ จอ เวลา หรือแต่งคำเพิ่ม (คำสั่งเขียนไว้ว่า "Code does everything else")

### ขั้น 6 · แผนของคลิป (สุ่มรอบใหม่ทุกครั้ง)
```
cd uni
python3 tools/clip_plan.py $W $W/faces.json <สไตล์> --history <ประวัติลูกค้า.json>
```
- พิมพ์เลขสุ่มของรอบ (`seed`) · ได้ `$W/plan_<สไตล์>.js` (หน้า ซับ ซูม เลขสุ่ม) และ `$W/then_<สไตล์>.txt` (ภาพทีละบรรทัด `<ฉาก>.<ชุด>.<แบบ>,t0,t1,ลำดับ,เวลาคำเด่น`)
- เพิ่มรอบนี้ลงประวัติลูกค้าเอง
- อยากได้คลิปเดิมซ้ำทุกจุด: ใส่ `--seed <เลขเดิม>` แทนการสุ่มใหม่ (Friend: "ต่อให้ user อัพคลิปเดิมลงไปแล้วกดรันอีกรอบนึงผมก็ไม่อยากให้มันออกมาเหมือนกัน" → ปกติไม่ใส่ seed)

### ขั้น 7 · เรนเดอร์
```
cd uni
NODE_PATH=$(npm root -g) bash tools/clip_all_styles.sh $W <สไตล์>
```
ได้ `$W/st_<สไตล์>/edit.mp4` · พิมพ์บรรทัดเดียว: จำนวนเฟรม · ความดัง (ต้องราว −14 LUFS) · ขนาดไฟล์ · เวลาที่ใช้ (คลิป 42 วินาทีใช้ราว 2.5 นาทีบน 2 คอร์)

### ขั้น 8 · ตรวจก่อนส่ง (ห้ามข้าม)
```
cd uni
NODE_PATH=$(npm root -g) node tools/picture_sizes.js $W/st_<สไตล์>
```
ทีละภาพ: เวลา · จอ · ขนาดภาพเป็น % ของจอ · `OUTSIDE` (หลุดโซนปุ่ม) · `LOW` (สีกลืน) · บรรทัดสุดท้ายคือค่าเฉลี่ย
- `OUTSIDE` ต้องเป็น 0 เสมอ
- `LOW` ที่ยอมได้: วงตกแต่งที่ตั้งใจจาง (บอก Friend ทุกครั้งว่าเหลืออะไร)
- ดูภาพทั้งคลิปด้วยตา: ตัดเฟรมทุก 2–3 วินาที (`ffmpeg -ss <วินาที> -i edit.mp4 -frames:v 1 …`) วางเป็นแผ่นเดียว
- เทียบกับรูปของ Friend ข้างกัน · ตัวเลขที่บอก Friend ต้องมาจากคำสั่งที่รันจริง (LESSONS 62)

## 4. ภาพ motion graphic (ทุกสไตล์ใช้ระบบเดียวกัน)

- ภาพทั้งหมดมาจาก glow-line: **965 แบบ ใน 21 หมวด** (`engine/uni/glow/index.json` · ฉากใน `engine/uni/scenes/glow.js`)
- **ชุดแม่แบบเป็นหลักทุกสไตล์** (Friend 2026-11-18: "ใช้ template ชุดฐานเป็นหลักเลยนะครับ ไม่ว่าจะสไตล์ไหนก็ตาม") หมวดที่มีชุดแม่แบบ (B01T–B12T) ใช้ชุดแม่แบบอย่างเดียว · หมวด B13–B21 ใช้ชุดหมวดไปก่อน
- โค้ดเลือกหน้าตาภาพ (`engine/uni/tools/pick.js`) ตามลำดับ:
  1. ชุดแม่แบบถ้าหมวดนั้นมี
  2. แบบเดียวกันไม่ซ้ำในคลิปเดียว
  3. ไม่ใช้แบบจาก 10 รอบล่าสุดของลูกค้าคนนั้น (หมดแล้วใช้แบบที่ห่างนานที่สุด)
  4. แบบที่สัดส่วนกว้าง/สูง 0.7–2.4 ก่อน (ภาพแบนเกินหรือสูงเกินออกมาเล็ก)
  5. ที่เหลือสุ่มจากเลขของรอบ
- สไตล์วาดภาพลงกล่องของจอนั้น (`glow/bridge.js` `glowDraw`) · ภาพขยายเต็มกล่องเสมอ · สีและวัสดุตามสไตล์ (`GLOWLOOK.<สไตล์>` แสงและความหนาเส้น · `GLASSY.<สไตล์>` สีชิ้นติดไฟ ไอคอน คน)
- สัดส่วนของทุกแบบวัดไว้แล้ว (`glow/shapes.json`) สไตล์ใช้เลือกจอที่ภาพออกมาใหญ่
- **ของใหม่ในโค้ดกลางเปิดเป็นรายสไตล์** (LESSONS 63 · Friend: "อยากให้มีผลเฉพาะสไตล์นี้ครับ ถ้าสไตล์อื่นไม่มีปัญหาก็ไม่ต้องแก้") เช่น `motionFit` `washLit` เปิดเฉพาะหน้าต่างแอป · แก้โค้ดกลางที่กระทบสไตล์ที่เสร็จแล้ว ต้องถาม Friend ก่อน
- เพิ่มแบบใหม่ใน skill glow-line แล้วรัน: `node glow/index.js` แล้ว `NODE_PATH=$(npm root -g) node glow/shapes.js`

## 5. ซับ (ทุกสไตล์)
- ซับครบทุกคำ ขึ้นทีละก้อนตามเสียง (ก้อนจาก Haiku ขั้น 4)
- ในก้อนหนึ่ง วลีสุดท้าย = **คำเด่น** (ตัวใหญ่ ขึ้นตอนพูดคำนั้น) · วลีก่อนหน้า = **คำนำ** (ตัวเล็ก ขึ้นก่อน)
- ช่วงที่มีภาพ: ซับอยู่ตรงตำแหน่งคำของจอนั้น · ช่วงที่ไม่มีภาพ: อยู่บนคนพูดตามจอพูดของสไตล์ (`speakerFrame`) · ก้อนที่คร่อมขอบจอถูกตัดที่ขอบ
- หน้าตาซับแต่ละสไตล์อยู่ในไฟล์ของสไตล์ (ฟอนต์ ขนาด สี ท่าขยับ)

## 6. กล้อง (ทุกสไตล์)
- ซูมช้าไป 1.05 เท่าใน 1.4 วินาที **4–5 ครั้งต่อคลิป** บนบรรทัดที่ AI ให้ซูม (`zoom`) เฉพาะช่วงที่เห็นหน้าคน ห่างกันอย่างน้อย 4 วินาที กลับ 1.0 ใน 1 วินาทีเมื่อจบบรรทัด (Friend: "ซูมช้า 4–5 ครั้ง")
- บรรทัดของ AI โดนภาพทับหมด → โค้ดหาบรรทัดที่เห็นหน้าเอง

## 7. เสียง (ทุกสไตล์)
- เข้าจอกราฟิก: เสียงวูบ (`whoosh` −20 dB) · คำเด่นขึ้น: เสียงปัดเบา (`softswish` −21 dB) · ห่างกันอย่างน้อย 2.5 วินาที
- เสียงรวม −14 LUFS เพดาน −1.5 dBTP (`core/pipeline.sh audio`)
