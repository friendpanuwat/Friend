# กฎของสไตล์ editorial และ editorial-overlay: ข้อไหนล็อก ข้อไหนให้ AI เลือก ข้อไหนให้ Friend ตัดสิน

ไล่จาก skill `talking-head-editorial` และ `talking-head-editorial-overlay` ครบทุกไฟล์ ได้แก่ SKILL.md, references และเอนจิน งานนี้ **อ่านอย่างเดียว ไม่ได้แก้ skill**

**กลุ่ม**
- **ก ล็อกในโค้ดหรือเทมเพลต** ✓ = เอนจินของ skill ทำอยู่แล้ว · ⚙ = ต้องสร้างใหม่
- **ข ให้ AI เลือก** ภายในกรอบที่โค้ดกำหนด
- **ค รสนิยมของ Friend** ต้องตัดสินว่าเป็นกฎของสินค้า หรือเป็นตัวเลือกให้ลูกค้า (หัวข้อ 1)
- **ง ใช้เฉพาะตอน Claude Code ตัดคลิปให้ Friend** ไม่ใช้ในระบบ (หัวข้อ 2.4)
- **แทนแล้ว** มีข้อตกลงใน `../DECISIONS.md` ใช้แทน

## 1. สิ่งที่ Friend ต้องตัดสิน (กลุ่ม ค)

### 1.1 ต้องเลือกจริง 5 ข้อ

**1) ฟอนต์ในคลิป**
- skill: ใช้ Mitr กับ Sriracha เท่านั้น
- เอกสารส่งต่องาน: ใช้ Prompt ทั้งบนเว็บและตอนเรนเดอร์
- ทางเลือก:
  - (ก) Prompt ทุกที่
  - (ข) ในคลิปใช้ Mitr กับ Sriracha ส่วนหน้าเว็บใช้ Prompt
  - (ค) ให้ลูกค้าเลือก แต่ต้องเพิ่มตัวเลือกในขั้นที่ 3 ซึ่งล็อกไว้แล้ว
- **แนะนำ (ข)** เพราะฟอนต์เป็นส่วนหนึ่งของหน้าตาสไตล์ที่ Friend อนุมัติแล้ว และตรงกับข้อตกลงที่ให้แต่ละสไตล์ล็อกตายตัว สไตล์อื่นในอนาคตใช้ Prompt ได้

**2) สีธีม**
- skill: accent สีเดียวทั้งคลิป (ค่าเริ่มเป็นเขียวมะนาว) ส่วนที่เหลือเป็นขาว กรมท่า ครีม และดำ
- เอกสารส่งต่องาน: ขั้นที่ 3 ให้เลือก preset หรือ "สีของฉัน" ที่มีสีเน้นได้ 1–2 สี
- **แนะนำ**
  - preset แต่ละชุดกำหนดสีครบทุกช่อง คือ accent, สีเข้ม และสีสว่าง
  - "สีของฉัน" ให้เลือก accent 1 สีจากรายการที่ตรวจแล้วว่าอ่านออกทั้งบนพื้นดำและบนหน้าคน
  - สองสไตล์นี้ไม่ใช้ accent สีที่สอง เพราะหัวใจของสไตล์คือสีเดียว
  - สีแดงยังสงวนไว้สำหรับความหมายลบเท่านั้น

**3) ข้อห้ามด้านดีไซน์ (ไล่สีม่วง ปุ่มทรงแคปซูล เอฟเฟกต์กระจก) ใช้กับกราฟิกในคลิปด้วยไหม**
- ข้อห้ามนี้อยู่ในหัวข้อดีไซน์ของเอกสารส่งต่องาน ซึ่งเขียนไว้สำหรับแอปและแลนดิ้งเพจ
- แต่ skill มีของพวกนี้อยู่ในคลิป:
  - editorial: พื้นการ์ดดำแบบ Glow ใช้แสงฟ้ากับม่วง (`#7A5CFF`) และกล่องไอคอนกระจกฝ้า
  - overlay: ชิปทรงแคปซูล
- ทางเลือก:
  - (ก) ใช้ข้อห้ามกับคลิปด้วย เปลี่ยน Glow เป็นแสงสีกรมท่าหรือสีธีม เปลี่ยนกระจกเป็นกล่องเรียบ และเปลี่ยนแคปซูลเป็นสี่เหลี่ยมมุมมน
  - (ข) ใช้ตามเดิมของ skill
- **แนะนำ (ก)** เพราะ Friend เคยติว่าหน้าตาแบบนี้ "ดูเป็น AI ทั่วไป" ผมจะทำภาพตัวอย่างเทียบสองแบบให้ดูก่อนตัดสิน

**4) รูปหรือ B-roll ของลูกค้า**
- skill รองรับ: editorial วางรูปหรือคลิปเต็มการ์ดได้ ส่วน overlay วางรูปเล็กในวิดเจ็ตได้
- แต่ลำดับ 7 ขั้นที่ล็อกไว้ไม่มีขั้นอัปโหลดรูป
- **แนะนำ:** รุ่นแรกใช้ motion graphics อย่างเดียว ถ้าจะเพิ่มต้องเปลี่ยนลำดับ 7 ขั้น ซึ่งต้องถาม Friend ก่อนอยู่แล้ว

**5) อีโมจิ**
- skill overlay ห้ามใช้อีโมจิ ก่อนหน้านี้เราคุยกันว่าอาจใช้ Fluent Emoji
- **แนะนำ:** ไม่ใช้ในสองสไตล์นี้ตามที่ skill กำหนด แล้วค่อยพิจารณาสำหรับสไตล์อื่น

### 1.2 แนะนำให้เป็นกฎของสินค้าตามเดิม (ตอบครั้งเดียวทั้งกลุ่ม)

| กฎใน skill | เหตุผลที่แนะนำให้คงไว้ |
|---|---|
| ไม่เกรดสี ไม่ใส่ vignette ไม่ใส่ grain (ระบบยังลด noise และเพิ่มความคมเบา ๆ เหมือนเดิม) | คลิปของลูกค้าออกมาเหมือนที่ถ่าย และเรนเดอร์ได้เร็วขึ้น |
| overlay: ไม่เบลอ ไม่หรี่คลิป | หน้าคนพูดต้องชัดตลอด ซึ่งเป็นหัวใจของสไตล์ |
| เสียงประกอบแบบเบา: ไม่มีเสียงป๊อป ทุก 0.9 วินาทีมีเสียงได้เสียงเดียว ระดับ −17 dB | Friend จูนไว้แล้ว การเพิ่มปุ่มปิดเสียงประกอบต้องแก้ขั้นที่ 3 |
| ไม่ใช้กลิตช์ และไม่ใช้เสียงการ์ตูน (boing, womp, sparkle) | ช่วยให้คลิปดูไม่จุกจิกและดูมืออาชีพ |
| ไม่ใส่บาร์โค้ด | Friend ไม่เอา |
| ไม่ใส่เพลง ให้ลูกค้าเลือกในแอปตอนโพสต์ | เลี่ยงปัญหาลิขสิทธิ์ |
| ตัดคำลงท้าย เช่น "เนี่ย" "อ่ะ" "นะเว้ย" ออกจากซับได้ | AI เสนอตอนจัดกลุ่มซับ และลูกค้าเห็นแล้วแก้คืนได้ในขั้นที่ 4 |
| สีแดงใช้เฉพาะความหมายลบ เช่น กราฟร่วง หรือกากบาท | สีจะได้มีความหมายเหมือนกันทุกคลิป |

| รูปหรือ B-roll ของผู้ใช้ รวมถึงการวางภาพพื้นดำบนการ์ดดำ | ค | หัวข้อ 1.1 ข้อ 4 |

### 2.3 เฉพาะ editorial-overlay

| กฎใน skill | กลุ่ม | ในระบบทำอย่างไร |

### 2.4 ใช้เฉพาะตอน Claude Code ตัดคลิปให้ Friend (กลุ่ม ง)

กฎเหล่านี้ไม่ใช้ในระบบ:
- ขอบทพูดพร้อมเวลาจากผู้ใช้ (ระบบใช้การถอดเสียงร่วมกับขั้นที่ 4 แทน)
- รับคลิปทางแชทหรือ Google Drive โดยไฟล์ต้องไม่เกิน 30 MB
- ตรวจเครื่องด้วย `check_env.sh`
- ห้ามขอให้ผู้ใช้ติดตั้งโปรแกรมเอง
- ทำรวดเดียวโดยไม่หยุดถาม
- วางแผนเป็นตาราง
- ตรวจงานด้วยตาจากภาพตัวอย่าง ภาพกริด และ contact sheet (ระบบใช้โค้ดตรวจแทน)
- บอกผู้ใช้ว่าตรวจจากภาพนิ่ง
- ส่งไฟล์คุณภาพสูงผ่าน GitHub
- ส่งตารางสรุป และขอฟีดแบ็กแบบระบุวินาที
- ห้ามแก้สคริปต์ระหว่างเรนเดอร์

## 3. งานที่ต้องสร้างเพิ่ม (รวบรวมจากรายการ ⚙)

1. **ตัวหาหน้า** ใช้กำหนดตำแหน่งซับและโซนวิดเจ็ต และใช้ตรวจว่าไม่มีอะไรบังหน้า
2. **โค้ดตรวจงาน** ตรวจเรื่องต่อไปนี้:
   - ซับครบทุกคำ และแต่ละก้อนมีโครงสร้างถูกต้อง
   - ความแน่นและจังหวะของการ์ดหรือวิดเจ็ต
   - ไม่ล้ำเขตห้าม
   - ข้อความไม่ล้นกรอบ และสระไม่ชน
   - ตัวเลขบนจอต้องมีอยู่ในบท
   - ไม่มีท่าเคลื่อนไหวนอกชุดของสไตล์ และไม่มีการสุ่ม
3. **ตัวสร้างอัตโนมัติ** ทำการซูม เสียงวูบที่คำใหญ่ และการค้างภาพท้าย รวมถึงคำนวณเวลาเข้าของวิดเจ็ตและของในวิดเจ็ตจากเวลาคำ
4. **คลังชิ้นส่วน** แปลงการ์ด C1–C11 กับ F1 และวิดเจ็ต W1–W14 เป็นชิ้นส่วนที่มีช่องให้เติม พร้อมหน้าแกลเลอรีให้ Friend เลือก
5. **ตัวตรวจความต่างสี** ของทุกชุดสีธีม

## 4. ขั้นต่อไป

เมื่อ Friend ตอบหัวข้อ 1 แล้ว งานถัดไปคือข้อ 4 ในหัวข้อ 3 คือดึงชิ้นส่วนเข้าคลังพร้อมหน้าแกลเลอรี สำหรับหัวข้อ 1.1 ข้อ 3 ผมจะทำภาพตัวอย่างเทียบแบบเดิมกับแบบไม่มีม่วง กระจก และแคปซูลไว้ในแกลเลอรีด้วย
