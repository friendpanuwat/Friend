# รูปแบบแผนฉาก (scene plan) ของ CutPack

AI เขียนแค่แผนนี้เป็น JSON และไม่เขียนโค้ด แผนผ่าน `validate.py` ก่อน แล้ว `plan2timeline.py` แปลงเป็น timeline ให้เอนจินเรนเดอร์ ทุกค่าในแผนถูกส่งเข้าเอนจินเป็นข้อมูล จึงไม่มีข้อความในแผนกลายเป็นโค้ดได้ ตัวอย่างจริงอยู่ที่ `examples/test18_editorial.json` และ `examples/test18_overlay.json` ซึ่งเรนเดอร์ได้ภาพตรงกับคลิปทดสอบ 18 วินาทีที่ Friend ผ่านแล้วทุกพิกเซล

```json
{
  "version": 1,
  "style": "editorial | overlay",
  "clip": {"file": "...", "duration": 18.165, "customer": "id ของลูกค้า"},
  "script": "ซับทั้งคลิปที่ผู้ใช้ยืนยันแล้ว (ใช้ตรวจว่าตัวเลขบนจอมีอยู่ในบท)",
  "layout": {"subtitleTop": 1300, "widgetPos": {"short": {"x": 240, "y": 150}, "narrow": {"x": 36, "y": 400}}},
  "camera": [{"push": 0.3}, {"pull": 2.4, "cut": true}],
  "subtitles": [{"t0": 0.0, "t1": 2.4, "text": "ทำไมคลิป ของคุณ / ยอดวิว ไม่ขึ้น", "key": "...", "keyAt": 1.2}],
  "scenes": [
    {"t0": 2.4, "t1": 4.8, "kind": "card", "part": "B02.v1", "bg": "glow", "hit": 3.9, "slots": {"dir": "down", "icon": "eye"}},
    {"t0": 0.5, "t1": 2.3, "kind": "widget", "part": "B06.v1", "size": "short", "hit": 1.3, "slots": {"wkey": "ไม่ขึ้น"}}
  ]
}
```

| ช่อง | ความหมาย |
|---|---|
| `style` | `editorial` ใช้การ์ดเต็มจอ (`kind: card`) ส่วน `overlay` ใช้วิดเจ็ต (`kind: widget`) |
| `layout` | สร้างโดย `faces.py` จากคลิปนั้น บอกความสูงของซับและตำแหน่งวิดเจ็ตทั้งสองขนาด ถ้าไม่มี ใช้ค่าจากคลิปตัวอย่าง |
| `camera` | `push` คือซูมเข้าช้า ๆ (เลือกใส่ `z` ได้ ไม่เกิน 1.08) ห่างกันอย่างน้อย 4 วินาที ส่วน `pull` คือถอยกลับ ถ้า `cut: true` จะถอยทันทีใต้จังหวะตัดเข้าการ์ด |
| `subtitles` | ซับเป็นช่วง ๆ โดย `/` คั่นท่อน และคำท้ายท่อนเป็นคำใหญ่ ในสไตล์ editorial ซับต้องอยู่นอกช่วงการ์ด |
| `scenes[].part` | ชิ้นจากคลัง เช่น `B02.v1` ดูรายการทั้งหมดใน `catalog.json` ซึ่งสร้างจากโค้ดด้วย `node catalog.js` |
| `scenes[].hit` | เวลาคำสำคัญของฉากนั้น เหตุการณ์ของชิ้นจะเกิดตรงเวลานี้ |
| `scenes[].slots` | ค่าที่เติมลงช่องของชิ้น ต้องตรงกับ `slots` ใน `catalog.json` วิดเจ็ตใช้ `wlead` และ `wkey` เป็นข้อความบนการ์ด (ไม่เกิน 3 คำ) |
| `scenes[].bg` / `size` | การ์ดใช้ `bg` เป็น `glow`, `white` หรือ `cream` ตามที่ชิ้นนั้นอนุญาต ส่วนวิดเจ็ตใช้ `size` เป็น `short` (เหนือหัว) หรือ `narrow` (ข้างหัว) |

## ขั้นตอนตรวจแผนก่อนเรนเดอร์ (3.2)

```
faces.py  →  validate.py  →  (ไม่ผ่าน) ส่ง issues กลับให้ AI แก้ 1 ครั้ง  →  validate.py  →  (ยังไม่ผ่าน) fallback.py  →  plan2timeline.py  →  เรนเดอร์
```

| ไฟล์ | หน้าที่ |
|---|---|
| `faces.py <src_frames> <faces.json>` | หาหน้าคนพูดด้วย YuNet ทุก 0.5 วินาที แล้วรวมเป็นกรอบเดียว ขยายกรอบเผื่อซูมสูงสุด (1.08 × กล้องหายใจ 1.014) เป็น `keepOut` แล้วคำนวณ `layout`: ความสูงซับ (ไม่สูงกว่า 1300 และไม่เกิน 1380) ตำแหน่งวิดเจ็ตเตี้ย (เหนือหัว ถ้าหัวชิดขอบบนจะลงไปอยู่ระดับอกระหว่างคางกับซับ บอกไว้ใน `shortPlace`) กับวิดเจ็ตแคบข้างหัว และบอกว่าคลิปนี้มีที่ให้วิดเจ็ตแต่ละขนาดไหม (`shortFits`, `narrowFits`) ถ้าหาหน้าไม่เจอเลยจะใช้กรอบกลางจอที่ยังเหลือที่ให้วิดเจ็ตทั้งสองขนาด |
| `validate.py <plan.json> [--faces] [--history] [--render]` | ตรวจแผนตาม DECISIONS ข้อ 4 และ 5 ตัวเลขทุกตัวของกฎอยู่ใน `RULES` ที่หัวไฟล์ พร้อมที่มา ผลเป็นรายการปัญหา แต่ละข้อมีรหัส (`code`) และบอกว่าเป็นของฉาก ซับ หรือการซูมลำดับที่เท่าไร |
| `render_check.py` | ส่วนที่ต้องเปิดฉากจริงในเอนจิน (`validate.py --render` เรียกให้): วัดหมึกของตัวอักษรทีละตัว รวมสระและวรรณยุกต์ ทุก 0.2 วินาที แล้วจับข้อความล้นจอ ถูกกรอบตัด ตัวอักษรทับกัน และข้อความในแถบปุ่มขวาของแอป ปัญหาต้องเห็น 2 จังหวะติดกันจึงนับ |
| `fallback.py <plan.json> <out.json>` | ทำให้แผนเรนเดอร์ได้เสมอ: ฉากที่ไม่ผ่านเปลี่ยนเป็นการ์ดตัวอักษร B14 จากคำบนฉากนั้นเอง ถ้าไม่มีคำหรือ B14 ยังไม่ผ่านจะตัดฉากทิ้ง ซูมที่ผิดถูกตัด ซับที่ผิดถูกตัดเวลาหรือตัดทิ้ง ทุกการเปลี่ยนถูกจดไว้ใน `fallbackLog` |
| `tests/library_sweep.py` | ใช้ `render_check` กับทุกชิ้นในคลังด้วยตัวอย่างในแกลเลอรี (การ์ด 314 ฉาก วิดเจ็ต 120 ฉาก) คลังที่ดีต้องไม่มีข้อผิดพลาด |

**ข้อผิดพลาด 2 ระดับ**
- **ข้อผิดพลาดด้านคุณภาพ** (`QUALITY` ใน `validate.py`): ความแน่นไม่ถึงเกณฑ์ ช่วงหน้าคนพูดยาวเกิน ใช้ชิ้นซ้ำ ซ้ำกับคลิปก่อนของลูกค้า และท่อนซับยาวหรือเร็วเกิน ให้ AI แก้ 1 ครั้ง ถ้ายังไม่ผ่าน คลิปก็ยังเรนเดอร์ต่อ
- **ข้อผิดพลาดที่ห้ามเรนเดอร์**: ทุกข้ออื่น เช่น ช่องผิด ไอคอนไม่มี ตัวเลขที่ไม่ได้พูด วิดเจ็ตบังหน้า ข้อความล้นหรือทับกัน และซูมถี่เกิน ต้องผ่าน `fallback.py` ก่อนเรนเดอร์

**ประวัติลูกค้า (`--history`)** เป็นไฟล์ `{"clips": [{"parts": ["B02.v1", ...]}, ...]}` เรียงจากเก่าไปใหม่ คะแนนความซ้ำคิดจาก 10 คลิปล่าสุด โดยคลิปที่ใหม่กว่ามีน้ำหนักมากกว่า ถ้าชิ้นในคลิปนี้ซ้ำกับคลิปล่าสุดเกินครึ่งจะเป็นข้อผิดพลาด

## ให้ AI วางแผน (แผน D, ขั้น 3.3)

```
ข้อมูลคลิป (input.json)  →  prompt.py สร้างคำขอ  →  Sonnet 5.5 effort low ตอบ {camera, scenes}  →  assemble.py เป็นแผนเต็ม  →  ตรวจตามข้างบน
```

| ไฟล์ | หน้าที่ |
|---|---|
| `prompt/system.md` | คำสั่งให้ AI: เลือกชิ้นตามหน้าที่ของประโยค เวลาของฉากและคำสำคัญ ช่องที่ต้องเติม ความแน่น ความหลากหลาย และกล้อง เขียนเป็นภาษาอังกฤษเพราะใช้ token น้อยกว่าและ AI ทำตามได้แม่นกว่า ส่วนบทพูดและคำบนจอยังเป็นภาษาไทย |
| `prompt/categories.json` | 15 หมวดกับประโยคที่แต่ละหมวดใช้ (คัดมาจากหน้ารายการ 15 หมวดที่ Friend เก็บครบ) |
| `prompt.py` | สร้างคำขอ ส่วนคงที่ (คำสั่ง + คลังของสไตล์นั้น + ไอคอนทั้งหมด + ตัวอย่างคลิป 18 วินาที) ใช้ร่วมกันทุกคลิปและเก็บแคชไว้ ส่วนที่เปลี่ยนตามคลิปคือความยาว ขนาดวิดเจ็ตที่ใส่ได้ ชิ้นที่ลูกค้าใช้ไปแล้ว และบทพูดพร้อมเวลาของทุกคำ คำอธิบายช่องของแต่ละหมวดดึงจากคอมเมนต์ในโค้ดชิ้นส่วน จึงไม่ต้องแก้สองที่ คำตอบถูกบังคับให้ตรงโครง JSON (`answer_schema`) |
| `assemble.py` | รวมคำตอบของ AI กับข้อมูลคลิปเป็นแผนเต็ม โค้ดเป็นคนใส่ซับเอง: overlay ใส่ซับครบ ส่วน editorial ใส่เฉพาะท่อนที่พูดตอนเห็นหน้า ท่อนที่อยู่ใต้การ์ดถูกเอาออกเพราะการ์ดเล่าประโยคนั้นแล้ว |
| `plan_d.py` | ตัวรันทั้งขั้น: ถาม AI → ตรวจ → ถ้ามีข้อผิดพลาด ส่งรายการปัญหากลับไปแก้ 1 รอบในบทสนทนาเดิม → ถ้ายังติด ใช้ `fallback.py` แล้วสร้างซับใหม่รอบการ์ดที่เหลือ → ถ้าไม่ได้คำตอบเลย (API ล่ม หรือถูกปฏิเสธ) ทำแผนที่มีแต่ซับ ลูกค้าจึงได้คลิปเสมอ บันทึกจำนวน token ของทุกครั้งที่เรียกไว้ใน `run.json` ตามรูปแบบของ `cost_model.py` |

**ข้อมูลคลิป (`input.json`)** มาจากขั้นถอดเสียงและขั้นจัดกลุ่มซับ ตัวอย่างอยู่ที่ `examples/test18_input.json`
```json
{"clip": {"file": "...", "duration": 18.165, "customer": "..."},
 "words": [{"w": "ทำไมคลิป", "t0": 0.0, "t1": 0.5}],
 "captions": [{"t0": 0.0, "t1": 2.4, "text": "ทำไมคลิป ของคุณ / ยอดวิว ไม่ขึ้น"}],
 "layout": "layout จาก faces.py", "history": {"clips": [{"parts": ["B02.v1"]}]}}
```
คำในซับเรียงตรงกับ `words` ถ้าไม่ตรงกัน ระบบจะเกลี่ยเวลาของคำในบรรทัดนั้นให้เท่า ๆ กัน

**คำตอบของ AI** เช่น `examples/test18_editorial.answer.json`: `camera` เป็นรายการ `{"move": "push"|"pull", "t", "z"?, "cut"?}` และ `scenes` เป็นรายการ `{t0, t1, part, bg|size, hit, say, slots}` ซึ่ง `say` คือคำในบทที่ฉากนั้นเล่า ไว้ให้คนตรวจงานอ่าน

**ทดสอบแล้วโดยไม่เรียก API จริง (ยังไม่มีคีย์)**
- คำตอบตัวอย่างของคลิป 18 วินาที เมื่อประกอบแล้วได้ซับ ฉาก และกล้องตรงกับแผนที่ Friend ผ่านแล้วทุกค่า
- ทดสอบด้วยตัว API จำลอง: คำตอบที่ดีผ่านเลย, คำตอบที่พัง 8 จุดเข้ารอบแก้แล้วผ่าน, คำตอบที่พังและไม่ได้แก้ผ่านด้วยตัวสำรอง, และกรณี API ไม่รับโครง JSON ระบบจะถามใหม่ 1 ครั้งโดยขอ JSON เปล่า
- `plan_d.py <input> <style> <out> --dry` เขียนคำขอที่จะส่งจริงออกมาดูได้

**ยังต้องทดสอบเมื่อมีคีย์:** API รับโครง JSON ของคำตอบไหม (ช่อง `slots` มีบางชื่อที่รับได้หลายชนิด), จำนวน token จริง (นับด้วย API) และคุณภาพของแผนกับคลิปจริง

**ค่าใช้จ่ายโดยประมาณต่อคลิป (ยังไม่ได้วัดจริง):** ส่วนคงที่ยาวราว 3.4 หมื่นตัวอักษร คาดว่าราว 1.2 หมื่น token อ่านจากแคชคิด 0.2 ดอลลาร์ต่อล้าน token ส่วนของคลิปราว 1,000 token และคำตอบรวมความคิดราว 4,000 token รวมราว 0.045 ดอลลาร์ หรือประมาณ 1.6 บาทต่อคลิป ถ้าต้องแก้อีกรอบจะเพิ่มอีกเกือบเท่าตัว

## ชุดทดสอบ (ขั้น 3.4)

`python3 -m unittest discover -s cutpack/engine/plan/tests -v` (รันจากโฟลเดอร์บนสุดของ repo ใช้ราว 15 วินาที ต้องมี Chromium และ ffmpeg) ถ้าใส่ `CUTPACK_SLOW=1` จะไล่ทุกชิ้นในคลังด้วย ใช้เพิ่มอีกราว 2 นาที

| กลุ่ม | ตรวจอะไร |
|---|---|
| แผนที่ดี | แผน 18 วินาทีทั้งสองสไตล์ผ่านทั้งการตรวจและการวัดบนภาพจริง, ตัวประกอบแผนสร้างแผนเดิมได้ตรงทุกค่า, ข้อความในแผนไม่มีทางกลายเป็นโค้ด |
| แผนที่จงใจทำพัง | 43 แบบ ครอบคลุมกฎทุกข้อ (โครง เวลา ช่อง ตัวเลข ความแน่น ความซ้ำ ซับ ตำแหน่ง กล้อง ประวัติลูกค้า) ทุกแบบต้องถูกจับด้วยรหัสที่ถูกต้องและชี้ถูกฉาก รวมถึงกรณีที่เอนจินเป็นคนปฏิเสธ และการวัดข้อความทับ ถูกตัด ล้นจอ และเข้าแถบปุ่ม |
| ตัวสำรอง | แผนพังทั้ง 43 แบบต้องกลับมาเรนเดอร์ได้ และมีกรณีที่ใช้เอนจินจริงในรอบซ่อม |
| ตัวเลขและตัวอักษร | อ่านตัวเลขไทยได้ (สามสิบห้า ยี่สิบเอ็ด หนึ่งล้านสองแสน ๑,๒๐๐) และนับตัวอักษรแบบเดียวกับเอนจิน |
| prompt | ส่วนที่แคชไว้ต้องเหมือนกันทุกคลิป (ไม่อย่างนั้นแคชไม่ทำงาน), คลังในคำขอมีครบทุกชิ้นและไอคอน, คำตอบตัวอย่างตรงโครง JSON, ข้อความรอบแก้บอกครบทุกปัญหา |
| ตัวหาหน้า | หาหน้าในคลิป 18 วินาทีแล้วได้ตำแหน่งเดียวกับที่ Friend ผ่านแล้ว และถ้าหาหน้าไม่เจอยังเหลือที่ให้วิดเจ็ต |
| คลังทั้งหมด (ช้า) | `tests/library_sweep.py` การ์ด 314 ฉาก วิดเจ็ต 120 ฉาก ต้องไม่มีข้อผิดพลาด |

**ก่อนบันทึกงานที่แก้เอนจิน ชิ้นส่วน หรือตัวตรวจ ให้รันชุดทดสอบนี้ทุกครั้ง** ถ้าแก้ชิ้นส่วนหรือขนาดตัวอักษร ให้รันแบบช้าด้วย

## ฉากที่ AI เขียนเอง (Friend ตกลง 2026-11-04: เปิดใช้ตั้งแต่วันแรก ไม่จำกัดจำนวน)

เมื่อไม่มีชิ้นในคลังที่เล่าประโยคได้ดี AI วางแผนจะใส่ `"part": "custom"` พร้อม `need` (ฉากควรแสดงอะไร และคลังขาดชิ้นแบบไหน) จากนั้นมีคำขอรอบที่สองเขียนโค้ดของฉากเหล่านั้น

| ไฟล์ | หน้าที่ |
|---|---|
| `prompt/kit.md` | คู่มือให้ AI เขียนฉาก: พื้นที่วางของการ์ดและวิดเจ็ต เครื่องมือที่ใช้ได้ ท่าเคลื่อนไหวที่ล็อก เสียง สี กฎเนื้อหา และตัวอย่าง 2 ชิ้น |
| `prompt.py` `code_request()` | คำขอรอบที่สอง (Sonnet 5.5 effort low) ส่วนคู่มือกับรายชื่อไอคอนเก็บแคชไว้ ส่วนของคลิปคือรายการฉาก custom พร้อมเวลา คำพูด และสิ่งที่ต้องแสดง |
| `custom_check.py` | **ด่านที่ 1:** ตรวจโค้ดก่อนเข้าเอนจิน ใช้ได้เฉพาะชื่อในชุดเครื่องมือ ห้ามแตะหน้าเว็บ กล้อง ฉากอื่น หรืออินเทอร์เน็ต ห้ามสร้างท่าเคลื่อนไหวเอง ห้ามสุ่ม ห้าม while และ new ข้อความใส่ได้แค่ CSS กับรูปทรง SVG ห้ามประกอบแท็ก ห้ามรหัส escape และวงเล็บต้องสมดุล โค้ดหนีออกจากฟังก์ชันตัวเองไม่ได้ |
| `motion.js` `customPart()` / `customWidget()` | ห่อฉากแบบเดียวกับชิ้นในคลัง (กรอบ ข้อความ lead/key ท่าเข้าออก) **ด่านที่ 2:** หลังโค้ดทำงานแล้ว ล้างทุกอย่างที่โหลดหรือรันอะไรได้ทิ้ง (iframe, img, event handler, url( ฯลฯ) |
| `render.js`, `render_check.js` | **ด่านที่ 3:** เบราว์เซอร์ที่ใช้เรนเดอร์ปิดอินเทอร์เน็ต |

**ตรวจเหมือนชิ้นในคลัง:** เวลา จังหวะคำสำคัญ ข้อความล้นหรือทับกัน แถบปุ่มของแอป และตัวเลขที่ฉากวาดเองต้องมีในบทพูดด้วย (ตัวเลขเดี่ยว 1–9 ใช้เป็นเลขลำดับได้) ฉาก custom ไม่ถูกนับเรื่องใช้ชิ้นซ้ำหรือประวัติลูกค้า เพราะทุกฉากเป็นของใหม่

**รอบแก้:** ปัญหาของแผนส่งกลับไปที่คำขอวางแผน (แล้วเขียนโค้ดฉาก custom ใหม่) ส่วนปัญหาของโค้ดส่งกลับไปที่คำขอเขียนโค้ด ถ้ายังไม่ผ่าน ฉากนั้นกลายเป็นการ์ดตัวอักษร B14 จากคำ lead/key ของฉาก

**ให้คลังโตขึ้น:** `report.json` เก็บ `library_missing` คือสิ่งที่ AI บอกว่าคลังขาด แม้ฉากจะถูกเปลี่ยนเป็นการ์ดตัวอักษร ฉากที่ถูกขอบ่อยควรทำเป็นชิ้นในคลัง ซึ่งถูกกว่าและตรวจได้ครบกว่า

**ทดสอบแล้ว (ยังไม่ได้เรียก API จริง):** โค้ดอันตราย 15 แบบถูกด่านที่ 1 ปฏิเสธ, โค้ดที่หลุดด่านที่ 1 ถูกด่านที่ 2 ล้างจนไม่เหลือ iframe, event handler หรือ url(, ฉากการ์ดและวิดเจ็ตที่เขียนตามคู่มือผ่านการตรวจบนภาพจริง และตัวรันผ่านทั้ง 3 เส้นทาง (โค้ดดี / โค้ดผิดแล้วแก้ได้ / โค้ดผิดแล้วกลายเป็นการ์ดตัวอักษร)
