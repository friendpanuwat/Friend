# รูปแบบแผนฉาก (scene plan) ของ CutPack

AI เขียนแค่แผนนี้เป็น JSON และไม่เขียนโค้ด แผนผ่าน `validate.py` ก่อน แล้ว `plan2timeline.py` แปลงเป็น timeline ให้เอนจินเรนเดอร์ ทุกค่าในแผนถูกส่งเข้าเอนจินเป็นข้อมูล จึงไม่มีข้อความในแผนกลายเป็นโค้ดได้ ตัวอย่างจริงอยู่ที่ `examples/test18_editorial.json` และ `examples/test18_overlay.json` ซึ่งเรนเดอร์ได้ภาพตรงกับคลิปทดสอบ 18 วินาทีที่ Friend ผ่านแล้วทุกพิกเซล

```json
{
  "version": 1,
  "style": "editorial | overlay",
  "clip": {"file": "...", "duration": 18.165, "customer": "id ของลูกค้า"},
  "script": "ซับทั้งคลิปที่ผู้ใช้ยืนยันแล้ว (ใช้ตรวจว่าตัวเลขบนจอมีอยู่ในบท)",
  "layout": {"subtitleTop": 1300, "widgetPos": {"short": {"x": 240, "y": 150}, "narrow": {"x": 36, "y": 400}}},
  "camera": [{"push": 0.3}, {"pull": 2.4, "cut": true}],
  "subtitles": [{"t0": 0.0, "t1": 2.4, "text": "ทำไมคลิป ของคุณ / ยอดวิว ไม่ขึ้น", "key": "...", "keyAt": 1.2}],
  "scenes": [
    {"t0": 2.4, "t1": 4.8, "kind": "card", "part": "B02.v1", "bg": "glow", "hit": 3.9, "slots": {"dir": "down", "icon": "eye"}},
    {"t0": 0.5, "t1": 2.3, "kind": "widget", "part": "B06.v1", "size": "short", "hit": 1.3, "slots": {"wkey": "ไม่ขึ้น"}}
  ]
}
```

| ช่อง | ความหมาย |
|---|---|
| `style` | `editorial` ใช้การ์ดเต็มจอ (`kind: card`) ส่วน `overlay` ใช้วิดเจ็ต (`kind: widget`) |
| `layout` | สร้างโดย `faces.py` จากคลิปนั้น บอกความสูงของซับและตำแหน่งวิดเจ็ตทั้งสองขนาด ถ้าไม่มี ใช้ค่าจากคลิปตัวอย่าง |
| `camera` | `push` คือซูมเข้าช้า ๆ (เลือกใส่ `z` ได้ ไม่เกิน 1.08) ห่างกันอย่างน้อย 4 วินาที ส่วน `pull` คือถอยกลับ ถ้า `cut: true` จะถอยทันทีใต้จังหวะตัดเข้าการ์ด |
| `subtitles` | ซับเป็นช่วง ๆ โดย `/` คั่นท่อน และคำท้ายท่อนเป็นคำใหญ่ ในสไตล์ editorial ซับต้องอยู่นอกช่วงการ์ด |
| `scenes[].part` | ชิ้นจากคลัง เช่น `B02.v1` ดูรายการทั้งหมดใน `catalog.json` ซึ่งสร้างจากโค้ดด้วย `node catalog.js` |
| `scenes[].hit` | เวลาคำสำคัญของฉากนั้น เหตุการณ์ของชิ้นจะเกิดตรงเวลานี้ |
| `scenes[].slots` | ค่าที่เติมลงช่องของชิ้น ต้องตรงกับ `slots` ใน `catalog.json` วิดเจ็ตใช้ `wlead` และ `wkey` เป็นข้อความบนการ์ด (ไม่เกิน 3 คำ) |
| `scenes[].bg` / `size` | การ์ดใช้ `bg` เป็น `glow`, `white` หรือ `cream` ตามที่ชิ้นนั้นอนุญาต ส่วนวิดเจ็ตใช้ `size` เป็น `short` (เหนือหัว) หรือ `narrow` (ข้างหัว) |

## ขั้นตอนตรวจแผนก่อนเรนเดอร์ (3.2)

```
faces.py  →  validate.py  →  (ไม่ผ่าน) ส่ง issues กลับให้ AI แก้ 1 ครั้ง  →  validate.py  →  (ยังไม่ผ่าน) fallback.py  →  plan2timeline.py  →  เรนเดอร์
```

| ไฟล์ | หน้าที่ |
|---|---|
| `faces.py <src_frames> <faces.json>` | หาหน้าคนพูดด้วย YuNet ทุก 0.5 วินาที แล้วรวมเป็นกรอบเดียว ขยายกรอบเผื่อซูมสูงสุด (1.08 × กล้องหายใจ 1.014) เป็น `keepOut` แล้วคำนวณ `layout`: ความสูงซับ (ไม่สูงกว่า 1300 และไม่เกิน 1380) ตำแหน่งวิดเจ็ตเตี้ยเหนือหัวกับวิดเจ็ตแคบข้างหัว และบอกว่าคลิปนี้มีที่ให้วิดเจ็ตแต่ละขนาดไหม (`shortFits`, `narrowFits`) ถ้าหาหน้าไม่เจอเลยจะใช้กรอบกลางจอที่ยังเหลือที่ให้วิดเจ็ตทั้งสองขนาด |
| `validate.py <plan.json> [--faces] [--history] [--render]` | ตรวจแผนตาม DECISIONS ข้อ 4 และ 5 ตัวเลขทุกตัวของกฎอยู่ใน `RULES` ที่หัวไฟล์ พร้อมที่มา ผลเป็นรายการปัญหา แต่ละข้อมีรหัส (`code`) และบอกว่าเป็นของฉาก ซับ หรือการซูมลำดับที่เท่าไร |
| `render_check.py` | ส่วนที่ต้องเปิดฉากจริงในเอนจิน (`validate.py --render` เรียกให้): วัดหมึกของตัวอักษรทีละตัว รวมสระและวรรณยุกต์ ทุก 0.2 วินาที แล้วจับข้อความล้นจอ ถูกกรอบตัด ตัวอักษรทับกัน และข้อความในแถบปุ่มขวาของแอป ปัญหาต้องเห็น 2 จังหวะติดกันจึงนับ |
| `fallback.py <plan.json> <out.json>` | ทำให้แผนเรนเดอร์ได้เสมอ: ฉากที่ไม่ผ่านเปลี่ยนเป็นการ์ดตัวอักษร B14 จากคำบนฉากนั้นเอง ถ้าไม่มีคำหรือ B14 ยังไม่ผ่านจะตัดฉากทิ้ง ซูมที่ผิดถูกตัด ซับที่ผิดถูกตัดเวลาหรือตัดทิ้ง ทุกการเปลี่ยนถูกจดไว้ใน `fallbackLog` |
| `tests/library_sweep.py` | ใช้ `render_check` กับทุกชิ้นในคลังด้วยตัวอย่างในแกลเลอรี (การ์ด 314 ฉาก วิดเจ็ต 120 ฉาก) คลังที่ดีต้องไม่มีข้อผิดพลาด |

**ข้อผิดพลาด 2 ระดับ**
- **ข้อผิดพลาดด้านคุณภาพ** (`QUALITY` ใน `validate.py`): ความแน่นไม่ถึงเกณฑ์ ช่วงหน้าคนพูดยาวเกิน ใช้ชิ้นซ้ำ ซ้ำกับคลิปก่อนของลูกค้า และท่อนซับยาวหรือเร็วเกิน ให้ AI แก้ 1 ครั้ง ถ้ายังไม่ผ่าน คลิปก็ยังเรนเดอร์ต่อ
- **ข้อผิดพลาดที่ห้ามเรนเดอร์**: ทุกข้ออื่น เช่น ช่องผิด ไอคอนไม่มี ตัวเลขที่ไม่ได้พูด วิดเจ็ตบังหน้า ข้อความล้นหรือทับกัน และซูมถี่เกิน ต้องผ่าน `fallback.py` ก่อนเรนเดอร์

**ประวัติลูกค้า (`--history`)** เป็นไฟล์ `{"clips": [{"parts": ["B02.v1", ...]}, ...]}` เรียงจากเก่าไปใหม่ คะแนนความซ้ำคิดจาก 10 คลิปล่าสุด โดยคลิปที่ใหม่กว่ามีน้ำหนักมากกว่า ถ้าชิ้นในคลิปนี้ซ้ำกับคลิปล่าสุดเกินครึ่งจะเป็นข้อผิดพลาด
