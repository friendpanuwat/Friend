# ทดสอบคลิปจริงรอบ 1: ต้นทุนต่อคลิปเมื่อเรียก API จริง (2026-11-05)

คลิปดิบของ Friend 4 คลิปจาก Google Drive (แนวตั้ง 576×1024, 60–90 วินาที) ทำทั้ง 2 สไตล์ ด้วยโมเดลที่ตกลงไว้ (Haiku 5.5 จัดซับ, Sonnet 5.5 effort low วางแผนฉาก)
**จ่ายจริงรวม 1.00 ดอลลาร์ (ราว 34 บาท)** จากเพดาน 4 ดอลลาร์ที่ Friend ตั้งไว้

## วิธีรัน

1. ถอดเสียงทุกคลิปก่อนด้วย Typhoon บนเครื่อง (`plan/asr.py`, ฟรี ราว 20 วินาทีต่อคลิป)
2. `tools/plan_all.sh` รัน `run_clip.py --words … --stop-after plan` ทีละคลิปต่อกัน (ซับ + แผนทั้ง 2 สไตล์) ห่างกันไม่เกิน 4 นาที แคชคำสั่งชุดใหญ่จึงไม่หมดอายุ และหยุดเองเมื่อยอดจ่ายจริง (`tools/spent.py` นับค่าจัดซับครั้งเดียวต่อคลิป) ถึงเพดาน
3. `tools/render_all.py` เรนเดอร์จาก `plan.json` ที่บันทึกไว้ด้วยขั้น render ของเอนจินเอง (ไม่เรียก API)

คีย์ในเครื่องนี้อยู่ในตัวแปร `KEY` สคริปต์ใช้ `ANTHROPIC_API_KEY="${ANTHROPIC_API_KEY:-$KEY}"`
ไฟล์ในแต่ละโฟลเดอร์คลิป: `words.json` (ถอดเสียง) `captions.json` `faces.json` `input.json` และ `<สไตล์>/plan.json report.json run.json` ส่วน `runs.jsonl` คือบันทึกต้นทุน (สรุปด้วย `cost_model.py report`) และ `plan_log.txt` คือผลที่สคริปต์พิมพ์ออกมา

## ปัญหาที่เจอเมื่อใช้ API จริง (ชุดทดสอบด้วย API จำลองจับไม่ได้)

1. **โครงคำตอบ (schema) ของแผนฉากถูก API ปฏิเสธทุกครั้ง:** มีช่องที่ไม่บังคับ 78–80 ช่อง แต่ API รับได้ไม่เกิน 24 ระบบจึงถามใหม่แบบไม่มีโครงทุกครั้ง (คำขอที่ถูกปฏิเสธไม่เสียเงิน) AI จึงตอบได้โดยไม่มีอะไรบังคับรูปแบบ และน่าจะเป็นเหตุให้ผิดเกณฑ์จนต้องแก้บ่อย
2. **Haiku จัดซับไม่ครบ 2 ใน 4 คลิป** (หยุดที่คำ 22 จาก 299 และคำ 146 จาก 239) ระบบจึงจัดซับตามกฎแทน
3. **คลิป 115846 สไตล์ overlay ได้ 0 ฉาก:** คำตอบรอบแรกยาว 24 token (แผนว่าง) รอบแก้ได้แผนจริงแต่มีข้อผิดพลาดร้ายแรงมากกว่า ตัวเลือก "เก็บแผนที่ดีกว่า" นับเฉพาะข้อผิดพลาดร้ายแรง แผนว่างมีศูนย์ข้อ จึงถูกเก็บไว้ คลิปนี้ออกมามีแต่ซับ
4. AI เลือกหมวดแยกกันในแต่ละสไตล์ คลิป 115213 จึงได้ biz ในสไตล์หนึ่ง และ none ในอีกสไตล์ ส่วน**ชิ้นของหมวดแทบไม่ถูกใช้** (รวม 4 ฉากจาก 148 และ overlay ไม่ใช้เลย)
5. ถอดเสียงผิดบ้าง เช่น "ยูไซเนส", "Conprentblenport" (comprehensible input) ลูกค้าแก้ได้ในขั้นตรวจซับ
