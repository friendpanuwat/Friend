# ทดสอบวิธีวางแผนฉากให้ดีขึ้นแบบปิดการคิด (2026-11-06)

Friend ให้ลองทุกวิธีที่เสนอ และให้บอกว่าคลิปไหนใช้วิธีไหน แชทนี้ไม่มีคีย์ API จึงใช้ **ผู้ช่วยย่อย (subagent) แทนการเรียก API**:
- ผู้ช่วยย่อยที่วางแผนฉากและเขียนฉากเองเป็น Sonnet 5.5 effort low ส่วนรอบแก้เป็น Haiku 5.5 effort low ทุกตัวรายงานรุ่นโมเดลของตัวเองตรงตามที่สั่ง
- คำขอที่ผู้ช่วยย่อยอ่านคือคำขอเดียวกับที่ `plan_d.py` จะส่งให้ API ทุกตัวอักษร ต่างกันแค่การขึ้นบรรทัดใหม่ในตัวอย่าง JSON เพื่อให้เครื่องมืออ่านไฟล์เปิดได้ (`tools/sa.py`)
- ส่วนที่เหลือเป็นเอนจินจริงทั้งหมด: โค้ดแก้ตัวเลข ตัวตรวจ รอบแก้ ตัวสำรอง และเรนเดอร์
- คลิปทดสอบคือคลิปรายได้เสริม 115213 (60.6 วินาที) ที่ Friend ส่งมา ซับและข้อมูลหน้าใช้ชุดเดียวกับรอบ 9 (`real-run1/round9-new-defaults/`, ซับทำด้วย Haiku จริงผ่าน API) ตรวจแล้วว่าตรงกับคลิปที่ส่งมาทุกอย่าง

## ข้อควรระวังในการอ่านผล
- **ผู้ช่วยย่อยไม่เหมือน API ตอนปิดการคิด:** แบบเดิม (v0) ของผู้ช่วยย่อยได้วิดเจ็ต 21 ชิ้น แต่ API จริงรอบ 9 ได้แค่ 11 ชิ้น และผู้ช่วยย่อยขอเขียนฉากเองแทบทุกแผน (API ปิดการคิดไม่เคยขอเลย) ผู้ช่วยย่อยน่าจะได้คิดก่อนตอบบ้าง ผลจึงบอกได้แค่ว่าวิธีไหนน่าลอง ต้องยืนยันกับ API จริงอีกครั้ง
- แต่ละชุดลองครั้งเดียว AI ตอบไม่เหมือนกันทุกครั้ง ความต่างเล็ก ๆ อาจเป็นความบังเอิญ
- วัดต้นทุนไม่ได้ (ไม่ได้จ่ายผ่าน API) ส่วนที่เพิ่มในคำสั่ง: v1 +570 ตัวอักษร, v2 +7,400, v3 +8,700, v4 +260, v6 +430 (อยู่ในข้อความต่อคลิป ไม่อยู่ในแคช), v7 +18,000 ส่วนที่อยู่ในแคชเสียเงินเต็มเฉพาะคลิปแรกหลังระบบว่าง
- ผู้ช่วยย่อยตัวหนึ่ง (รอบแก้ v3-example editorial) พยายามเรียกเครื่องมือสร้าง session ใหม่นอกงานที่สั่ง ระบบปฏิเสธ ไม่มีอะไรถูกสร้าง

## ปัญหาที่เจอระหว่างทดสอบ: ซับ editorial หายในช่วงเห็นหน้า (Friend ทัก 2026-11-06)
`assemble.subtitles` ทิ้งซับทั้งท่อนถ้าท่อนนั้นคาบเกี่ยวกับการ์ดเกิน 0.1 วินาที ท่อนยาว 1–3 วินาที ส่วนช่วงเห็นหน้าระหว่างการ์ดมักสั้น 1–2 วินาที หลายช่วงจึงไม่มีซับเลย
- ซับขึ้นแค่ 36–55% ของเวลาที่เห็นหน้าในชุดทดสอบ (v3-example 70%) และคลิปเดียวกันจาก API จริงรอบ 9 ก็ 63% จึงเป็นปัญหาเดิมของเอนจิน ไม่ได้มาจากวิธีที่ทดสอบ
- overlay ไม่มีปัญหานี้ (ซับ 60.0 จาก 60.6 วินาที)
- เสนอ Friend แล้ว: ตัดท่อนให้เหลือเฉพาะช่วงเห็นหน้าแทนการทิ้ง ถ้าคำในท่อนพูดระหว่างการ์ดเกือบหมดให้การ์ดเล่าแทน และถามว่าระหว่างการ์ดเต็มจอจะให้มีซับด้วยไหม (skill ไม่มี) รอคำตอบ

## Friend: ทั้ง 14 คลิปต่ำกว่ามาตรฐาน (2026-11-06)
Friend ส่งคลิปตัวอย่างมาตรฐาน 2 คลิป (overlay และ editorial ของคลิปพูดเดียวกัน 42.9 วินาที ไม่ได้เก็บใน repo) เทียบแล้วต่างกัน 4 ข้อ:
1. **ภาพ:** ตัวอย่างออกแบบฉากใหม่ทุกประโยคเป็นเรื่องเล็ก ๆ ด้วยของในเรื่อง (กล่องสินค้า ป้ายราคา ตะกร้า กระเป๋าเงิน แชต สวิตช์ซื้อ/ไม่ซื้อ ตาชั่งเงินกับสินค้า เช็กลิสต์ จิ๊กซอว์) และขยับหลายจังหวะตามคำพูด เช่น ร้านมีลูกค้า 4 คน → เหลือ 1 → กระดิ่งเงียบ ของเราเป็นชิ้นสำเร็จรูปทั่วไปที่ขยับจังหวะเดียว วิดเจ็ตส่วนใหญ่เป็นป้ายข้อความเล็กที่ซ้ำกับซับ
2. **ตัวหนังสือบนการ์ด editorial:** ตัวอย่างวางประโยคตัวใหญ่บนการ์ดทุกใบ (คำนำ + คำใหญ่ + บรรทัดเล็กต่อ) ของเราหลายใบมีแค่คำนำตัวเล็ก
3. **คำใหญ่ในซับ:** ตัวอย่างใช้คำใหญ่เฉพาะคำสำคัญ หลายท่อนไม่มีคำใหญ่ ของเรามีคำใหญ่ทุกท่อนตามกฎ "คำท้ายท่อนเป็นคำใหญ่" (2026-11-04) จึงได้คำใหญ่เป็นคำธรรมดา เช่น มองว่า กำลังทำ
4. ซับ editorial หายในช่วงเห็นหน้า (หัวข้อด้านบน)

ทั้ง 6 วิธีเปลี่ยนแค่วิธีที่ AI เลือกจากคลัง จึงปิดช่องว่างข้อ 1 ไม่ได้ ฉากที่ AI เขียนโค้ดเองในรอบนี้ (v7-all มี 3 ฉาก) หน้าตาใกล้ตัวอย่างกว่าชิ้นในคลัง: ภาพใหญ่กลางจอ และมีคำใหญ่บนการ์ด เสนอทางเลือกให้ Friend แล้ว รอคำตอบ

## ทดสอบซับที่ถูกต้อง (Friend 2026-11-06, `115213-fixsubs/`)
Friend แก้ซับของคลิปเองทั้งคลิป (`friend_subs.txt`, เวลาระดับวินาที) แทนขั้นที่ 4 ของเว็บ แล้วให้ทดสอบเฉพาะแบบเดิม (v0) ทั้ง 2 สไตล์
- `tools/align_subs.py` จับคำที่ถูกต้องให้ตรงกับเวลาตัวอักษรของตัวถอดเสียง (ตรงกัน 86%) บรรทัดสุดท้ายเลยท้ายคลิปเพราะคนพูดถูกตัดกลางคำ จึงบีบให้จบในคลิป จากนั้นขั้นจัดซับ (Haiku) จัดท่อนตามเดิม
- ผล: editorial 16 การ์ด 51% (เท่าเดิม), overlay 22 วิดเจ็ต (เดิม 21) ซับบนช่วงเห็นหน้าของ editorial 60% (เดิม 45%)
- AI เข้าใจคำเฉพาะถูกขึ้น (business, mindset, minimize ความเสี่ยง, อินฟลูเอนเซอร์) แต่ยังเลือกชิ้นประเภทเดิม และยังมีภาพที่ความหมายกลับ เช่น เครื่องหมายถูกตอน "ให้มันแค่เป็นรายได้เสริม" ซึ่งคนพูดกำลังติ และนาฬิกาตอน "ตอนที่ผมทำคอนเทนต์" หน้าตายังห่างจากคลิปตัวอย่างเท่าเดิม
- รอบแก้ editorial เกิดจากซับท่อนสุดท้าย "เสริม" ยาว 0.05 วินาที ซึ่ง AI แก้ไม่ได้ (ใน editorial ระบบส่งซับที่เร็วเกินไปให้ AI ใช้การ์ดบัง)
